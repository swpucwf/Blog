# Element-Wise 与 Reduction

## 1. 逐元素算子是带宽题

`c[i] = a[i] + b[i]` 每个输出只依赖同下标的两个输入，没有跨线程协作，是典型的带宽受限算子：计算只有一次加法，数据要读写 12 字节。

实测基线（`N = 16 777 216`，FP32，block 256，三个独立进程取中位数）约 **0.336 ms**，按逻辑字节换算有效带宽约 **599 GB/s**。这个数字接近同机 `copy_` 的实测参考值，说明基线本身已经跑在带宽附近——后续优化空间主要来自「怎样少搬或不搬」，而不是「怎样多算」。

## 2. 三个可调的设计选择

| 变量 | 做法 | 影响 |
|---|---|---|
| 地址映射 | 相邻线程读相邻元素 | 决定请求能否合并 |
| Grid 规模 | 总线程数与每线程元素数 | 决定并行度与循环次数 |
| 向量化 | `float4` / 128-bit 访存 | 减少指令数，受对齐约束 |

每轮只动一个变量，才能把收益归因清楚。同时改三项，即使变快了也说不清是谁的贡献。

## 3. 实测：负结果比正结果更有信息量

| 实现 | 中位耗时 | 逻辑带宽 | 说明 |
|---|---|---|---|
| `hip-v0` 基线 | 0.3363 ms | 598.6 GB/s | 一线程一元素，grid 65536 |
| `hip-v1-contiguous` | 0.3696 ms | 544.7 GB/s | grid 降到 2048，每线程多元素 |
| `hip-v1-strided` | 2.5672 ms | 78.4 GB/s | 跨步地址，合并访存被破坏 |
| `hip-v2` | 0.3435 ms | 586.1 GB/s | `float4`，grid 256 |
| `hip-v3` | 0.3452 ms | 583.2 GB/s | `float4` 变体 |
| `triton-t0` | 0.3362 ms | 598.8 GB/s | tile 256 |
| `triton-t1` | 0.3385 ms | 594.8 GB/s | tile 1024 |

三个结论值得记住：

1. **跨步访存是明确负例**：同样的数学运算，耗时是基线的 7.6 倍。地址布局对带宽敏感算子有决定性影响。
2. **`float4` 没有带来额外收益**：v2/v3 与 v0 差距在波动范围内。基线已接近带宽上限时，减少指令数并不能突破瓶颈。
3. **grid 变小反而变慢**：每线程处理更多元素会引入循环与地址计算，并行度下降的代价盖过了循环开销的节省。

HIP 与 Triton 在本次配置下带宽落在同一区间（598.6 与 598.8 GB/s），进程范围重叠。这说明当算子被带宽限死时，框架选择对结果影响很小——瓶颈不在代码生成质量。

## 4. Reduction：从「人人写全局」到两阶段

求和的关键变化是：多个输入要归并成一个输出，线程之间必须交接结果。四种做法对应四档性能：

| 实现 | 中位耗时 | 问题 |
|---|---|---|
| 逐元素全局 atomic | 34.65 ms | 每次都争用同一地址，串行化 |
| 每 block 一次 atomic | 4.35 ms | 争用减少，但仍按 block 数排队 |
| 两级归约（partials） | 477.7 µs | 先写 partial，再由 final kernel 合并 |
| block 内 LDS 归约 | 79.0 µs | 块内树状合并，块间写 partial |
| Triton p256 | 49.4 µs | program 内归约，配置更省 |

这条曲线说明一个通用规律：**归约的成本主要来自「写冲突」和「启动次数」**。atomic 把冲突暴露到全局，两级归约用中间数组换掉冲突，LDS 把合并压进块内，Triton 则把一次归约压进一个 program。

### 4.1 树状归约的线程分工

在 `N = 2^24`、block 256 的受控实验里，三种块内合并方式的中位数分别是：

- 折半树（相邻线程两两合并）：398.7 µs；
- 间隔映射（interleaved）：438.0 µs；
- 紧凑映射（compacted）：441.6 µs。

预期中「让活跃线程更集中」的写法没有变快，反而慢约 10%。trace 显示编译产物已把取模条件优化成位运算，而紧凑映射额外引入了乘法与地址计算。这个负结果的价值在于提醒：**源码里看起来更聪明的写法，未必对应更少的指令或更少的等待**。

### 4.2 配置不是越大越好

同一章还测了 LDS 归约的 grid 规模：`g256` 约 79.0 µs、`g1024` 约 83.2 µs、`g65536` 约 490.7 µs。block 数量增加到远超并行能力后，调度开销与部分写放大反而成为主导。Triton 侧同样有最优点：`p256` 约 49.4 µs，`p1024` 约 58.6 µs。

## 5. 方法论的沉淀

这两个算子给出的可复用经验：

- **先判断瓶颈类型**。带宽受限的算子优化访存模式，计算受限的算子优化指令与并行度，方向错了再努力也无效。
- **保留负结果**。跨步访存、grid 变小、紧凑映射三次失败，比任何一次成功都更能说明变量的真实作用。
- **一轮只改一个变量**。同时改地址映射、线程数与向量化，就无法区分收益来源。
- **逻辑带宽不等于物理流量**。按算法语义算出的带宽只用于横向比较，不能当作显存实际流量的证据。
