# 编程模型与 wavefront 执行

## 1. 一份规则，多份执行

把两排数对应相加：第一对 1 与 10 得 11，第二对 2 与 20 得 22。算第二对不需要等第一对的答案，这类互不依赖的工作天然可以拆开。

程序从 CPU 上开始：准备输入、把数据放到 GPU 能访问的位置、请 GPU 完成这批加法、取回结果校验。写给 GPU 的计算规则放在一个函数里，叫**核函数（Kernel）**；CPU 提交这次计算的动作叫**启动（Launch）**；一次启动可以让许多线程(Thread)执行这个函数。

```mermaid
flowchart LR
    A[CPU 准备输入] --> B[数据搬到 GPU]
    B --> C[启动 kernel]
    C --> D[GPU 多线程执行]
    D --> E[拷回结果并校验]
```

启动只负责提交工作。CPU 要使用结果，还得确认 GPU 已经算完——这一步就是主机端同步。

## 2. 三层组织：Block、Wavefront、Thread

HIP 把一组线程称为**线程块（Block）**；启动时指定「每块多少线程」和「一共多少块」；同一次启动的全部线程块合起来叫**网格（Grid）**。

Block 有两个作用：硬件可以把不同块安排到可用资源上，不必等所有线程同时可执行；同一块内的线程可以在需要时交换数据、一起等待某个步骤完成。

块内还有一层：一个 Block 的线程会被组成若干个「共同执行一条指令、各自用自己的数据」的小组，叫**波前（Wavefront，简称 wave）**。以 2 个 Block、每块 64 线程、wave32 为例：

| 类比 | GPU 中的名字 | 本例关系 |
|---|---|---|
| 营 | Grid：本次启动的全部线程块 | 含 2 个 Block |
| 连 | Block：一组可协作的线程 | 每块 64 线程，即 2 个 wavefront |
| 排 | Wavefront：共同执行指令的小组 | 每组 32 线程 |
| 单兵 | Thread：kernel 的一次执行 | 处理分配给自己的数据 |

两层的职责不同：**Block 规定哪些线程归在一起、能否协作；wavefront 决定块内线程怎样共同执行指令**。一个 Block 里的多个 wavefront 不必同时开始或结束，不同 Block 的线程也不会拼成同一个 wavefront。

线程在 wave 里的位置叫**通道（Lane）**。wave 大小不是固定的：`gfx1201` 同时支持 wave32 与 wave64，具体取决于 kernel 采用哪一种。

## 3. 线程怎么找到自己的数据

内核里唯一要解决的事，是每个线程算出自己负责的下标：

```cpp
int idx = blockIdx.x * blockDim.x + threadIdx.x;
if (idx < n) c[idx] = a[idx] + b[idx];
```

- `threadIdx.x`：块内编号，范围 `0 ~ blockDim.x-1`；
- `blockIdx.x`：第几块；
- `blockDim.x`：每块线程数；
- `gridDim.x`：块数，配合使用可算出全局编号。

`if (idx < n)` 处理的是**尾线程**：`n` 不能被线程数整除时，最后一块里会多出几个线程，它们算出的下标越界，必须跳过。少了这个判断，轻则结果错误，重则访问越界崩溃。

以 `n = 10`、每块 4 线程为例：需要 3 块（`(10+4-1)/4`），第 2 块的线程 2、3 算出下标 10、11，被边界判断挡掉。手算几遍这类小例子，看任何 kernel 都能立刻定位到地址映射。

## 4. 提交量不等于同时执行量

两个容易混淆的点：

**线程不是显卡上专属的一颗小处理器**。提交很多线程工作，GPU 用有限硬件资源安排执行；提交了多少份工作，和某一时刻有多少份正在执行，是两回事。

**GPU 不会因为看到「加法」就自动分好数组**。本例安排「一对数一个线程」，只是因为各对数据独立；也可以让一个线程处理多个元素，分工方式由程序决定。

## 5. 从编程模型到硬件执行

软件侧看到的是 grid → block → wavefront → lane，硬件侧对应的是 GPU → WGP → CU → SIMD。一个 wavefront 的指令最终由 SIMD 单元调度执行，lane 对应执行通道。这层对应关系解释了后续所有优化的方向：

- 相邻 lane 访问相邻地址，访存请求才容易合并；
- 同一 wave 内的线程走同一路径时效率最高，分支发散会让部分 lane 空转；
- 一个 CU 能同时驻留多少 wave，取决于寄存器与共享内存的占用。
