# 端到端搜索：OneSug 与 OneSearch

## 1. 搜索和推荐不是一回事

推荐是「猜你想看」，搜索是「答你所问」。三个差别决定了架构不能照搬 OneRec：

- **相关性是第一优先级**。推荐可以给喜欢运动鞋的人推运动服；搜索「红色连衣裙」返回蓝色款就是事故。必须先满足相关性，再谈个性化；
- **开放词表 → 封闭词表**。用户输入任意文本，商品库却是有限的；
- **商品信息噪声大**。标题堆满「2024新款韩版修身显瘦包邮」，真正核心的属性被营销词淹没。

电商搜索链路的前半段是查询补全，后半段是商品检索。OneSug 与 OneSearch 各管一段，共享同一套生成式哲学，但设计取舍不同。

## 2. OneSug：查询补全

### 2.1 把多阶段链路拍平成生成

传统做法是 Trie 粗召回 \(10^8\to10^4\)、预排序到 \(10^2\)、精排到 16 个候选。问题是前序阶段的瓶颈决定后序上限，各阶段目标还互相打架。

OneSug 直接定义条件生成：

$$
P(\mathrm{Query}\mid \mathrm{Prefix}, \mathrm{UserContext})
$$

四个挑战写得很实在：前缀只有 1～2 个字（「苹」是水果还是手机）、个性化与流行度要平衡、六级反馈怎么建模、100ms 内要出结果。

### 2.2 三个模块

**前缀-查询语义对齐**。用 BGE 抽前缀语义，但通用模型不懂电商。于是从日志里挖 prefix-query / query-query 共现对，做对比学习：

$$
\mathcal{L}_{align} = -\log\frac{\exp(\mathrm{sim}(e_{q_i},e_{q_j})/\tau)}{\sum_{q_k\in\mathcal{B}}\exp(\mathrm{sim}(e_{q_i},e_{q_k})/\tau)}
$$

对齐后，查询检索的语义相关性从 0.67 提升到 0.81。

**PRE（前缀表示增强）**。短前缀信息不够，就从历史日志检索共现查询，把它们的平均嵌入按权重融合：

$$
e_p^* = (1-w)e_p + w\bar{e}_q^c,\quad w=0.5
$$

MRR 提升 2.3%，但 \(w>0.7\) 会引入噪声导致下降——这是个需要调的甜点。为高效检索，查询也用 RQ-VAE 编成 4 层、每层 512 码本的离散码，从 \(O(Nd)\) 的向量检索变成码本查找。

**输入构造**。增强后的前缀 + 语义相关查询序列 + 最近 10 条历史查询 + 用户画像。两个细节：超过 10 条历史会引入噪声（MRR 降 1.2%）；**不引入商品交互特征**，因为补全发生在输入阶段，还没有商品曝光。

**解码与排序**。Beam Search 束宽 32，配长度归一化避免模型偏爱短查询：

$$
\mathrm{Score}(q) = \frac{1}{|q|^\alpha}\sum_t \log P(q_t\mid q_{<t}),\quad \alpha\in[0.6,0.8]
$$

### 2.3 RWR：把六级反馈变成偏好

NTP 训练只学了「查询会不会出现」，没学「哪个查询更有价值」。于是把搜索链路的反馈分成六级：

| 层级 | 反馈 | 基础权重 |
|---|---|---|
| 1 | 下单 | 2.0 |
| 2 | 点击商品 | 1.5 |
| 3 | 点击查询 | 1.0 |
| 4 | 展示未点击 | 0.5 |
| 5 | 在召回池未展示 | 0.2 |
| 6 | 随机负样本 | 0.0 |

奖励为 \(r(x_u,q)=\lambda e^{pi}\)，\(pi\) 是该层级的归一化出现频率——高频交互拿更高奖励。再从六级中构造 9 类偏好对（Order > Show、Item Click > Not Show、Click > Rand 等），用奖励差定义样本难度：

$$
rw_\Delta = \frac{1}{r(x_u,q_w)-r(x_u,q_l)}
$$

差值越小说明这对样本越难区分，训练时权重越大。损失在 DPO 上加了两项改进：奖励加权 + 目标奖励边界 \(\delta\)（强制正负差至少为 \(\delta\)），并保留 SFT 项维持生成质量。

## 3. OneSearch：商品检索

### 3.1 商品怎么表示

**KHQE（关键词增强的分层量化编码）**：

第一步，商品表示。文本、OCR、类目、价格、统计特征过蒸馏 BGE 得到 768 维向量，再用多类对齐任务补协同信号：

- \(q2q\)、\(i2i\) 对比学习（ItemCF/Swing 挖共现对）；
- \(q2i\) 对比，保证查询与商品同空间；
- 分层反馈对齐 \(rank\)：曝光 < 点击 < 下单，用 Margin 区分；
- 难样本相关性校正 \(rel\)：边界样本用 LLM 打相关性分，让 BGE 拟合。

第二步，关键词增强。NER 从日志里挖出 18 类属性词表，用 Aho-Corasick 在标题里 \(O(n)\) 匹配（图片走 Qwen-VL 识别），再做 50-50 融合：

$$
e_i^o = \frac{1}{2}\left(e_i + \frac{1}{n}\sum_j e_{k_j}\right)
$$

这一步专门对治标题噪声——营销词被稀释，核心属性被放大。

第三步，RQ-Kmeans 三层 + OPQ 两层：

| 层 | 码本 | 语义 |
|---|---|---|
| L1 | 4096 | 大类（服装/数码） |
| L2 | 1024 | 子类（女装/男装） |
| L3 | 512 | 细类（连衣裙/牛仔裤） |
| OPQ1/2 | 256×2 | 独特属性（品牌、价格段） |

合计约 6000 个唯一 token、每个商品 5 个 token。

两个经验很关键：

- **只在 L3 加平衡约束**。早期层强制平衡会让层次聚类崩溃——不同细粒度的商品被硬塞进同一簇；
- **不要全用 OPQ**。试过 `4*2/256`、`4*4/256`，性能大幅下降——破坏了「粗到细」的生成结构。

### 3.2 Mu-Seq：三个视角注入用户

**用户 ID 由行为构造**。不用随机哈希，而是把短期与长期点击商品的 SID 加权求和：

$$
\mathrm{SID}_{short} = \left\lceil\sum_i \lambda_i\mathrm{SID}_{s_i}\right\rceil,\quad
\lambda_i = \frac{\exp(\sqrt{i})}{\sum_j\exp(\sqrt{j})}
$$

\(\sqrt{i}\) 的指数归一化让近因权重更高，但不像线性衰减那么激进。长短各 5 个 token 拼成 10 维 UserID。好处是兴趣相似的用户 ID 相近，冷启动用户还能用「查询 → Top 点击商品」兜底。

**短期序列显式注入**：查询用原文（2～3 个词，可直接 tokenize），商品用 SID（标题太长），历史查询 ≤10、点击商品 ≤20。

**滑动窗口增强**：完整序列 `[i1..i5]` 不再只产一个样本，而是 `[]→i1`、`[i1]→i2`……五个样本。既学到兴趣演化，又天然覆盖冷启动。

**长期序列压缩**：点击/下单/搜索三类行为，各按 L1/L2/L3 三层聚合，得到 3×3=9 个向量，再用 128 个可学习查询做 Q-Former 交叉注意力，压成长度固定的 128 token。按层级聚合的好处是能分别学到「大类偏好」与「细类偏好」。

### 3.3 生成与推理

用 BART 做 Encoder-Decoder。编码器吃异构序列（UserID、Query 文本与 SID、历史序列、Q-Former 输出），解码器逐 token 生成 5 层 SID：

```text
[BOS] → L1 → L2 → L3 → OPQ1 → OPQ2
```

推理时 Beam Search 有两种：**约束搜索**强制 token 来自有效 SID 池，保证结果对应真实商品；**非约束搜索**更快，但可能生成幻觉 SID。

### 3.4 PARS：先相关性，再个性化

NTP 只学了「哪些商品与查询共现」，没学「用户更偏好哪个」。PARS 分两块。

**三阶段 SFT**：

1. **语义内容对齐**：文本→SID、SID→文本、文本→类目，建立双向映射；
2. **共现关系同步**：查询↔商品文本、查询 SID↔商品 SID，学协同信号；
3. **用户个性化建模**：输入完整用户上下文，训练格式与推理完全一致。

**自适应奖励**。固定权重不够——新商品曝光 1 次被点 1 次，CTR 100%，不代表它比曝光 1000 次点击 500 次的热门更好。于是用对数平滑：

$$
Cnt_T = \log(Cnt_{pos}+10)+\log(Cnt_{clk}+10)+\log(Cnt_{order}+10)
$$

$$
Ctr = \frac{\log(Cnt_{clk}+10)}{Cnt_T},\qquad Cvr = \frac{\log(Cnt_{order}+10)}{\log(Cnt_{clk}+10)}
$$

最终 \(r(q,i) = 2\lambda\cdot\frac{Ctr\cdot Cvr}{Ctr+Cvr}\)，即 CTR 与 CVR 的调和平均。

奖励模型是 SIM 三塔（CTR/CVR/CTCVR），但关键一项是**离线相关性分数 \(S_{Rel}\) 权重放大 10 倍**：

$$
RScore = \lambda_1 CTR + \lambda_2 CVR + \lambda_3 CTCVR + 10\lambda_4 S_{Rel}
$$

这就是搜索与推荐最本质的差别在损失函数上的体现——相关性不是加分项，而是硬门槛。

**混合排序**：用 SFT 模型生成 512 个候选，奖励模型重排，挑「排名发生变化」的样本做 List-wise DPO，并保留 NLL 项维持生成能力。上线后再用真实交互（Level 1-3 为正、4-6 为负）做小时级持续学习，突破奖励模型继承自 MCA 的上限。

## 4. 三者的分工

| 维度 | OneRec | OneSug | OneSearch |
|---|---|---|---|
| 输入 | 用户行为序列 | 前缀 + 用户上下文 | 查询 + 用户上下文 |
| 输出 | 语义 ID 序列 | 查询文本 | 商品 SID 序列 |
| 词表 | 封闭 | 开放（文本） | 开放输入 + 封闭商品 |
| 核心约束 | 兴趣匹配 | 前缀相关 + 个性化 | 相关性优先 + 个性化 |
| 对齐手段 | ECPO / GBPO | RWR + DPO | 三阶段 SFT + List-wise DPO |

## 5. 落地判断

- **相关性与个性化要分层加权**：搜索里 \(S_{Rel}\) 的权重必须显著高于其他项，否则一定会出现相关性漂移；
- **关键词增强是低成本高收益**：50-50 融合几乎不改架构，却能显著缓解标题噪声；
- **平衡约束别乱加**：只在最细层加，早期层强制均衡会破坏层次；
- **奖励要防稀疏偏差**：对数平滑是必须的，否则新品与长尾会被系统性高估；
- **上线后继续学**：奖励模型的天花板来自旧系统，只有真实反馈能突破。
