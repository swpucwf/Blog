# 物品 Tokenizer 与语义 ID

## 1. 问题：物品怎么变成 token

LLM 的 token 是词或子词，天然承载语义；推荐系统的物品却是 `item_10086` 这样的原子 ID，对模型毫无意义。把它直接塞进词表，会遇到三个硬墙：

- **词表爆炸**：数十亿视频、数亿商品，Softmax 要在十亿级词表上做归一化，工程上不可行；
- **存储与泛化**：十亿个 256 维嵌入约 1TB，挤占模型容量；且原子 ID 彼此正交，新物品必须从零积累交互；
- **协同信号隐式依赖**：只能靠「看过 A 也看 B」的统计关联学相似性，数据稀疏时直接失效。

所以 Tokenizer 要回答的是：怎么把物品映射到一个**可控大小的离散词表**上，同时保留语义与泛化能力。

## 2. 三种范式

| 范式 | 代表 | 优点 | 致命问题 |
|---|---|---|---|
| 稀疏 ID | HSTU、GenRec | 无碰撞、特征交互自由、工程成熟 | 词表爆炸、无语义、冷启动差 |
| 文本 ID | M6-Rec、TallRec、P5 | 语义丰富、零样本泛化、可解释 | 表示冗长（30+ token）、grounding 困难 |
| 语义 ID | TIGER、OneRec、OneSearch | 固定词表、层次结构、可推理 | 量化有损、多阶段目标不一致 |

文本 ID 的问题容易被低估：一个商品描述约 30 个 token，自注意力是 \(O(n^2)\)，序列翻倍计算量变四倍；更麻烦的是生成结果难以精确落回候选集——「Apple 手机」可能匹配几百款机型，还可能生成不存在的商品。BIGRec 用「先生成再算 L2 距离重排」补救，但这已经违背端到端初衷。

语义 ID 是折中方案：固定长度、固定词表的 token 序列。TIGER 把「NBA 扣篮集锦」编码为 `[10, 5, 42]`（体育 → 篮球 → 扣篮），OneRec 用约 8000 的词表，OneSearch 用 4000～6000 的电商词表支撑数亿商品。

它的三个结构性好处：

- **可控词表**：\(K=8000, L=4\) 时理论可表示 \(8000^4\approx4\times10^{15}\) 个物品；
- **层次结构**：前缀是粗类目、后缀是细属性，相似物品自动共享前缀，天然支持前缀匹配；
- **从记忆到推理**：模型学会「用户喜欢篮球」后，可迁移到所有 `[10, 5, ...]` 开头的物品，包括没见过的。

## 3. VQ-VAE：离散化的起点

三阶段：编码器 \(z_e=f_\theta(x)\) → 最近邻量化 \(z_q=e_{k^*}\) → 解码器 \(\hat{x}=g_\phi(z_q)\)。

  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_vq_vae_simple.png" width="46%" alt="VQ-VAE 结构" />
  <p>图 1：编码、量化、重建三段</p>
</div>

损失由三项组成：

$$
\mathcal{L}_{VQ} = \underbrace{\|x-\hat{x}\|_2^2}_{\text{重建}} + \underbrace{\|\mathrm{sg}[z_e]-z_q\|_2^2}_{\text{码本}} + \underbrace{\beta\|z_e-\mathrm{sg}[z_q]\|_2^2}_{\text{承诺}}
$$

两处 `sg`（stop gradient）分工明确：码本项只更新码本，承诺项只更新编码器。承诺损失的作用是防止编码器把输出空间拉得任意大——没有它训练会不稳。

量化是硬决策、不可导，所以用**直通估计器**：前向严格执行最近邻，反向把量化当作恒等映射，梯度直接透传。数学上是个近似，但实践中意外有效。

## 4. RQ-VAE：残差量化

单个 token 的困境是「精度 vs 码本规模」：码本大则难训，码本小则装不下多维语义（一部电影同时是科幻、悬疑、反乌托邦）。

RQ-VAE 把一次量化拆成 L 层，每层只拟合上一层剩下的残差：

$$
k_\ell = \arg\min_j \|r_{\ell-1}-e^{(\ell)}_j\|_2,\qquad r_\ell = r_{\ell-1}-e^{(\ell)}_{k_\ell}
$$

最终表示是所有层码字之和 \(z_q=\sum_\ell e^{(\ell)}_{k_\ell}\)，语义 ID 就是索引序列 \([k_1,\dots,k_L]\)。

  <p>图 2：逐层逼近残差，误差从 0.5 降到 0.1</p>
</div>

一个一维例子最能说明问题：目标 5.5，第一层码本 `{0,5,10}` 选出 5，残差 0.5；第二层码本 `{0,0.4,0.8}` 选出 0.4，残差 0.1。重建 5.4，误差从 0.5 降到 0.1。

**层次语义是涌现的**：前层捕获粗粒度（体育），后层细化（篮球 → 扣篮）。它像对焦——只看前缀 `[10,5]` 也知道是篮球视频，这为模糊匹配与泛化提供了结构基础。

损失按层累加，每层独立优化自己的码本与承诺项，STE 在每层量化处分别应用。

## 5. 工业级方案：解耦与混合

RQ-VAE 的端到端训练在工业上有维护难题：模型一更新，所有物品的语义 ID 都要重算。

**RQ-Kmeans** 把「表示学习」与「码本构建」解耦：先用任意编码器（BERT/CLIP/多模态）得到物品向量，再在向量上直接跑 K-means 建码本，逐层对残差聚类。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_rq_kmeans.png" width="62%" alt="RQ-Kmeans" />
  <p>图 3：聚类替代梯度学习，新物品只需向量检索</p>
</div>

好处很实际：新物品用 Faiss 检索即可分配 ID，无需重训；K-means 的均匀聚类特性还缓解了码本坍塌。

**RQ-OPQ** 补另一个漏洞：残差 \(r_L\) 被丢弃了，而它恰恰装着无法被层次聚类捕获的独特属性（品牌型号、价格区间、商家特征）。于是用 OPQ 对残差做乘积量化，旋转投影后切子空间、各自量化：

$$
\mathrm{ID}_i = [\underbrace{s^{(1)},\dots,s^{(L)}}_{\text{层次语义}},\ \underbrace{q_1,\dots,q_M}_{\text{独特属性}}]
$$

OneSearch 的实部署配置是 `(4096, 1024, 512 | 256, 256)`——3 层 RQ-Kmeans + 2 层 OPQ，每个物品 5 个 token。以 iPhone 15（粉色 256G）为例：

- RQ 部分给出 `[102, 8, 1]`：电子产品 → 手机通讯 → Apple；
- OPQ 部分给出 `[56, 99]`：粉色、256G 这类正交属性。

合起来 `[102, 8, 1, 56, 99]`，既保留层级身份，又能精确区分具体 SKU。这正是搜索场景需要的。

## 6. 三个未解难题

**SID 冲突**。量化有损，不同物品可能落到同一序列，根源是码本利用不均——大量物品挤在少数中心。缓解分两类：训练时优化（均匀分配、限制中心容量）与推理时补救（混合编码，用后几层区分）。

**目标不一致**。表示提取、SID 量化、生成模型训练三段各自优化：表示模型的目标与推荐无关，量化不考虑下游偏好，生成模型只能被动接受固定 SID。思路是联合优化（梯度打通）或自监督对齐（循环一致性、迭代互适应）。

**多模态融合**。内容语义、协同信号、场景属性的分布并不一致，简单拼接或加权平均吃不满互补性。可在表示层融合（门控、对比学习），也可在量化层融合（模态专属码本、MoE 动态权重）。

## 7. 选型建议

- **物品量小、协同信号强**：稀疏 ID 仍可用，不必为了「生成式」硬换语义 ID；
- **冷启动与跨域是核心痛点**：语义 ID 收益最大，优先 RQ-Kmeans（工程轻、易迭代）；
- **搜索/电商需要精确区分 SKU**：上 RQ-OPQ 这类混合编码，纯层次量化不够；
- **码本大小按业务定**：几千到一万是常见区间，太小冲突多、太大难训练；
- **一定要监控冲突率与码本利用率**：这两个指标恶化时，下游生成质量会无声下滑。
