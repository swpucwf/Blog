# 排序序列建模：DIN、DIEN 与 DSIN

## 1. 从「物品袋」到「行为序列」

前面的交叉模型把用户历史当成一个无序的物品袋，池化成一个固定向量。问题在于：同一个用户向量，无论推荐跑鞋还是手机，都是一样的——它试图一视同仁地装下所有兴趣，结果是对具体候选不够聚焦。

序列建模换了个前提：**用户的行为有顺序，兴趣会随时间演化**。先看鼠标再看显示器，和先看小说再看显示器，指向的意图完全不同。

三个代表性模型沿着「相关 → 演化 → 会话」递进。

## 2. DIN：局部激活

DIN 的观察很直接：一次点击通常只被历史兴趣中的**一部分**激活。给数码爱好者推机械键盘时，起作用的是他最近看的游戏鼠标和显卡，而不是上个月的跑鞋。

所以用户表示不该固定，而应随候选变化：

$$
v_U(A) = \sum_{j=1}^{H} a(e_j, v_A)\, e_j = \sum_{j=1}^{H} w_j e_j
$$

其中 \(a(\cdot)\) 是一个小网络，输入「历史行为 + 候选广告」，输出注意力权重。

三个实现细节值得记住：

- **多角度交互**：注意力输入拼成 `[query, keys, query-keys, query*keys]`，比单纯点积更能刻画相关性；
- **不做 softmax**：权重不归一化，\(\sum w_j \neq 1\)，这样向量模长能表达兴趣的**强度**而不只是方向；
- **mask 处理**：变长序列要屏蔽 padding，否则注意力会落到填充位上。

```python
att_inputs = tf.concat([tf.tile(query, [1, length, 1]), keys,
                        query - keys, query * keys], axis=-1)
scores = tf.keras.layers.Dense(1)(ffn_layer(att_inputs))
user_interest = tf.reduce_sum(keys * (scores * mask), axis=1)
```

## 3. DIEN：兴趣的演化

DIN 仍把行为当集合，忽略时序依赖。DIEN 的目标是建模「兴趣状态」如何随时间变化，分两阶段。

**第一阶段：兴趣提取**。用 GRU 按时间处理行为序列，并加一个辅助损失——让 \(t\) 时刻的隐状态去预测 \(t+1\) 时刻的真实行为（正样本），同时与负采样行为区分：

$$
L_{aux} = -\frac{1}{N}\sum_i\sum_t\left[\log\sigma(h_t^i, e_{b[t+1]}^i) + \log(1-\sigma(h_t^i, \hat{e}_{b[t+1]}^i))\right]
$$

总损失是 \(L = L_{target} + \alpha L_{aux}\)。这一步的意义是：隐状态不只是「记住历史」，还要能「预测下一步」，否则它学不到真正的兴趣。

**第二阶段：兴趣演化**。直接对兴趣序列跑 GRU 会被兴趣漂移干扰，所以 DIEN 设计了 AUGRU——用注意力缩放更新门：

$$
a_t = \mathrm{softmax}_t(h_t W e_a),\qquad
\tilde{u}_t' = a_t \cdot u_t',\qquad
h_t' = (1-\tilde{u}_t')\circ h_{t-1}' + \tilde{u}_t'\circ\tilde{h}_t'
$$

与候选越相关的历史兴趣，更新门权重越大，信息更容易传递下去；不相关的漂移被削弱。这相当于把 DIN 的「按候选聚焦」从空间维度延伸到了时间维度。

## 4. DSIN：会话内同质、会话间异质

真实行为是间断的：一个会话里集中看裤子，下一个会话转向戒指。用一条 RNN 硬串长序列，模型得花很大力气学「兴趣突变」。

DSIN 把会话作为基本单元，分四层：

1. **会话划分**：行为间隔超过阈值（如 30 分钟）就切一个新会话；
2. **会话兴趣提取**：会话内用多头自注意力聚合，得到每个会话的兴趣向量；
3. **会话兴趣交互**：会话序列用 Bi-LSTM 建模跨会话的演进；
4. **会话兴趣激活**：以候选物品为 query，对会话兴趣做注意力加权，拼接得到最终表示。

## 5. 实测：一个反直觉的结果

| 模型 | AUC | GAUC | 评估用户数 |
|---|---|---|---|
| DIN | 0.5999 | 0.5654 | 928 |
| DIEN | 0.5649 | 0.5539 | 928 |
| DSIN | 0.5456 | 0.5521 | 99 |

DIN 最好，DIEN 明显下降，DSIN 更低——这与论文里的结论相反。三个可能原因：

- **序列长度不足**：DIEN/DSIN 依赖长序列才能体现演化，公开小数据集的平均序列长度太短，GRU 与会话切分都学不到东西；
- **参数与数据不匹配**：AUGRU、Bi-LSTM 增加了不少参数，小样本下更容易过拟合；
- **评估口径**：DSIN 的评估用户数只有 99，与另外两个（928）不可直接比，这个数字本身不可靠。

这组结果比「谁更强」更有价值的地方在于提醒：**序列模型的收益与序列长度强相关**。行为序列短于 10 条的场景，用 DIN 甚至静态池化就够；只有用户行为足够长、且候选差异明显时，DIEN 的演化建模才有发挥空间。

## 6. 落地判断

- **行为长度是前置条件**：短序列先做 DIN，别急着上 GRU；
- **辅助损失值得单独试**：即使不上 DIEN，给序列编码器加「预测下一行为」的辅助任务也常有收益；
- **会话切分阈值要按业务调**：30 分钟是电商经验值，内容平台可能更长；
- **注意评估口径**：不同模型评估用户数不一致时，AUC 不可直接横比。

## 写在最后

序列建模解决了「兴趣随时间变化」，但真实业务还有两个约束：多个目标要同时优化、多个场景要共用一套模型。下一篇看多目标建模：ESMM 如何解决样本选择偏差，MMoE 如何用专家网络缓解任务冲突。
