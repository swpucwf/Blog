# 推荐系统是什么

## 1. 三个层次看推荐

推荐系统常被描述为「帮用户找到感兴趣的内容」，但这句描述解释不了它为什么难。把它拆成三个层次看会更清楚：微观的单个预测、工业的规模流水线、宏观的生态平衡。

### 1.1 微观：两个根本范式

任何推荐都要先理解三件事：

- **用户**：历史行为、显式反馈、画像信息、当前会话里的实时意图；
- **物品**：内容属性（类别、时长、质量）与社会化证明（播放量、评分、趋势）；
- **场景**：时间、位置、设备与当下状态——通勤时更想看短视频，居家时更愿意看深度内容。

理解之后，有两种截然不同的问法。

**判别式推荐**把问题定义为「给定用户-物品-场景三元组，预测正面行为的概率」：

$$
\mathrm{Score} = f(\mathrm{User}, \mathrm{Item}, \mathrm{Context})
$$

系统对每个候选逐一打分，再择优推荐。像一位评委挨个给选手打分。

**生成式推荐**改变了问题本身：不再评估候选，而是直接生成结果序列。

$$
[I_1, I_2, \ldots, I_k] = g(\mathrm{User}, \mathrm{Context})
$$

模型以历史交互序列和场景为输入，自回归解码出推荐物品。像一位了解你品味的朋友，直接告诉你「接下来该看这几个」。

两者的输入相同，问题却完全相反：判别式在有限候选里**择优**，生成式在开放空间里**创造**。这一差异会一路影响到架构、优化目标与工程实现。

### 1.2 能力演进的四个阶段

把时间线拉开，推荐算法呈现出一条清晰的能力升级路径：

| 阶段 | 物品表示 | 核心能力 | 代表方法 |
|---|---|---|---|
| 纯 ID 记忆 | 原子符号 | 记住「看过 A 的人也看 B」 | 协同过滤 |
| 深度学习泛化 | 原子 ID + 特征 | 泛化到未见过的用户-物品组合 | Wide&Deep、DIN |
| 语义 ID 理解 | 结构化语义 Token | 新物品无需行为数据即可推荐 | TIGER、语义 ID |
| 大模型推理 | 语义 + 推理链 | 显式分析意图并给出理由 | OneRec-Think |

四个阶段不是替代关系，而是层层叠加：今天的工业系统里，ID 协同过滤仍是召回的重要通路，深度模型支撑召回与排序，语义 ID 与大模型推理在最前沿的生成式架构中落地。

## 2. 工业：两条规模化路线

数亿用户、上亿物品、毫秒级延迟——这是推荐系统工程化的核心矛盾。

**判别式的解法是漏斗**：召回从全量物品里快速筛出几千候选（求全不求准），排序用复杂模型精确打分（求准），重排再优化整张列表的多样性、新颖性与业务规则。三阶段各司其职，把计算量控制在可接受范围。

**生成式的解法是端到端**：既然模型能直接生成结果，就不必逐级筛选。把历史交互当上下文，自回归解码出推荐 Token 序列，一个模型完成整条链路。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_e2e_generative_pipeline.svg" width="62%" alt="端到端生成式架构" />

</div>

端到端消除了流水线的三个痛点：**目标不一致**（召回优化相关性、排序优化点击率、重排优化多样性，各自为战）、**信息损失**（召回阶段漏掉的优质物品后续永远看不到）、**计算碎片化**（异构模块难以吃满 GPU）。

代价是新的挑战：生成效率、物品空间覆盖、工程部署。目前两条路线并行——流水线在成熟场景稳定服务，生成式在前沿探索中验证潜力。

## 3. 宏观：生态而非指标

一个技术上完美的推荐，未必是好的推荐。经典的「准确率陷阱」：用户刚把手机加入购物车，系统再推荐这款手机，点击率接近 100%，但对用户没有任何增量价值。

推荐系统的目标不是指标最大化，而是构建可持续的生态，三个支点相互依存：

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_ecosystem_balance.svg" width="40%" alt="推荐生态三角" />
  <p>图 5：用户、内容与平台的三角关系</p>
</div>

- **用户与创作者**：用户要发现真正感兴趣但尚未接触的内容，而不是被困在越看越窄的过滤气泡里；创作者需要合理的分发空间，PGC、UGC、AIGC 三类供给各有其位；
- **内容**：作为分发的原子单位，既要分发热门，也要持续发掘潜力内容，避免「头部集中、长尾沉没」；
- **平台**：协调者角色，有时要牺牲短期指标换长期信任，例如降低标题党权重。

## 4. 技术地图

这套笔记沿着判别式与生成式两条主线组织：

- **上篇·级联架构**：召回（协同过滤、向量召回、双塔、序列与流式索引）→ 排序（记忆与泛化、特征交叉、序列建模、多目标、多场景）→ 重排（贪心与个性化）；
- **下篇·生成式范式**：生成式基础与 Tokenizer → Scaling Law 架构 → 端到端建模（推荐、搜索、广告）→ 推理型推荐 → 扩散推荐；
- **收尾**：一个完整的生产级电影推荐项目，串起离线训练、在线服务、前端与部署。
