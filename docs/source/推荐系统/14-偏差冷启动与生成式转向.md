# 偏差、冷启动与生成式转向

## 1. 数据本身可靠吗

推荐系统的训练数据来自真实交互，而真实交互受系统策略、用户习惯、物品流行度共同影响。更麻烦的是**反馈闭环**：模型的推荐影响用户行为，行为又成为新训练数据，偏差会被滚雪球式放大。

  <p>图 1：反馈闭环如何放大各类偏差</p>
</div>

偏差分两层：

**数据偏差**（采集阶段）

| 类型 | 场景 | 后果 |
|---|---|---|
| 选择偏差 | 显式评分只来自愿意评价的用户 | 高估整体满意度（MNAR） |
| 曝光偏差 | 隐式反馈里未交互≠不喜欢，可能只是没看到 | 把潜在正样本当负样本 |
| 从众偏差 | 好评多的商品更容易被继续给好评 | 反馈不独立 |
| 位置偏差 | 排在前面的物品天然获得更多点击 | 点击率随位置急剧衰减 |

**结果偏差**（模型输出）：流行度偏差（热门越推越热）、不公平性（对某些群体系统性歧视）。

两类偏差通过闭环互相强化：热门获得更多曝光→更多交互→在训练数据中占比更大→更热。这就是推荐里的马太效应。

## 2. IPS：用倒数为稀有样本加权

逆倾向得分的思路来自因果推断：把「物品被展示」看作一次干预，用样本被观测到的概率 \(P(O_{ui}=1)\) 的倒数做权重。

$$
\hat{R}_{IPS} = \frac{1}{|U||I|}\sum_{(u,i)\in D_O}\frac{1}{P(O_{ui}=1)}\delta_{u,i}
$$

直观理解：容易观测到的样本（热门、首位）降权，难以观测到却仍被交互的样本（长尾、低位）加权——后者往往携带更强的偏好信号。

一个电影推荐的例子：恐怖片爱好者看爱情片的概率只有 0.1，但一旦评分往往给低分；看恐怖片概率 0.8 且给高分。朴素统计会高估两类片子的偏好差距，而 IPS 让罕见的低分获得 10 倍权重、常见的高分只有 1.25 倍。

**工程要点**：倾向得分未知，需要单独估计（朴素贝叶斯或逻辑回归）；当 \(P\) 很小时倒数会爆炸，必须做权重截断或归一化，否则训练不稳定。

验证纠偏效果的标准做法是**半合成实验**：先用矩阵分解把真实评分矩阵补全当「真值」，再设计偏差模型（如 \(r\ge4\) 以概率 \(k\) 观测，\(r<4\) 以 \(k\alpha^{4-r}\) 观测）生成有偏数据，最后比较朴素估计与 IPS 估计相对真值的偏差。有实验显示 \(\alpha=0.25\) 时 IPS 的误差比朴素估计小 2～3 个数量级。

## 3. PAL：从结构上拆开位置与偏好

IPS 靠调数据，PAL 靠改结构。它的观察很关键：用户点击包含两个连续事件——**先看到，再决定点不点**：

$$
p(click\mid u,i,pos) = p(seen\mid pos)\times p(click\mid u,i,seen)
$$

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_pal_framework.png" width="46%" alt="PAL 框架" />
  <p>图 2：ProbSeen 管位置，pCTR 管偏好</p>
</div>

双模块分工：

- **ProbSeen**：只输入位置，输出该位置被看到的概率，可以简单到一张查找表；
- **pCTR**：输入用户、物品、上下文，**完全不包含位置特征**，专注真实偏好。

训练时两者相乘得 bCTR 并联合优化，模型自动分配「这次点击多少归因于位置、多少归因于内容」；**推理时只用 pCTR**，天然得到去位置偏差的预估。这个技巧解决了「推理阶段位置未知」的根本问题。

## 4. 冷启动：两种对象、四条路线

冷启动分物品与用户两类，共同点是「没有交互数据，ID 记忆失效」。

### 4.1 物品冷启动

**CB2CF** 学「内容 → 协同过滤表示」的映射：内容编码器把文本、图像、类别编码成向量，映射网络把它映射到协同过滤嵌入空间，再用余弦相似度约束对齐。新物品只要拿到内容特征，就能得到一个「像老物品一样」的 CF 向量。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_cb2cf_arch.png" width="46%" alt="CB2CF 架构" />
  <p>图 3：内容特征映射到协同过滤空间</p>
</div>

**MetaEmbedding** 不映射表示，而是学「怎么初始化」：用元学习在现有物品上反复模拟「初始化 → 少量交互适应 → 评估」，让生成器学会产出「初始就可用、且能快速收敛」的 embedding。

$$
\phi^{init}=h_w(u),\qquad
\phi' = \phi^{init} - a\nabla l_a(\phi^{init}),\qquad
l_{meta}=\alpha l_a(\phi^{init})+(1-\alpha)l_b(\phi')
$$

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_meta_embedding_alg.png" width="56%" alt="MetaEmbedding 两阶段" />
  <p>图 4：初始化与适应两阶段联合优化</p>
</div>

\(\alpha\) 控制「初始质量」与「可适应性」的平衡——这是元学习在冷启动上的典型用法。

### 4.2 用户冷启动

**MeLU** 把每个用户的偏好学习当成一个任务，用 MAML 学一个好的初始化：内循环用用户少量交互做本地适应，外循环更新全局参数。它的改进是参数分离——\(\theta_1\) 学共享的用户/物品嵌入，\(\theta_2\) 学决策网络，前者保证表示质量，后者负责快速个性化。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_melu_arch.png" width="56%" alt="MeLU 双阶段" />
  <p>图 5：内循环适应 + 外循环元更新</p>
</div>

**POSO** 从架构侧入手，指出真正的问题不是数据少，而是**个性化淹没**：新用户远少于老用户，即使模型有 `is_new_user` 特征，也会被多数老用户数据主导而学会忽略它。POSO 的做法是为不同群体准备并行的子模块，再用个性化门控加权：

- **POSO-MLP**：K 个并行 MLP + 门控；
- **POSO-MHA**：K 组注意力头 + 门控；
- **POSO-MMoE**：底层共享专家 + 顶层专家组 + 任务门控与个性化门控双重加权。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_poso_arch.png" width="58%" alt="POSO 结构" />
  <p>图 6：按用户群体分组的子模块 + 门控</p>
</div>

POSO 的可复用洞见是：**不平衡特征不能只靠「加一列特征」解决，要在结构上给它独立的容量**。

## 5. 生成式转向：三条演进路径

上篇的流水线走到这里，已经暴露出结构性的问题：多阶段目标不一致、逐级筛选丢信息、异构模块吃不满 GPU。生成式推荐提出另一种问法：不逐一打分，直接生成结果。

三个关键设计维度：**输入怎么组织**（ID 序列 → 事件流）、**输出生成什么**（原子 ID → 语义 ID / 会话）、**目标与架构怎么取舍**。

三条路径：

| 路径 | 代表 | 核心改动 |
|---|---|---|
| 生成式召回 | HSTU、TIGER | 输入统一为事件流；输出改为语义 ID |
| 生成式排序 | GenRank、MTGR | 预测动作而非物品；用户样本聚合 |
| 端到端统一 | OneRec | 一次生成整个推荐会话 |

两个技术点先记住：

- **HSTU**：把属性、行为、时间戳拉平成统一事件流；用点向聚合替代 softmax，避免归一化扭曲兴趣强度；
- **TIGER**：用 RQ-VAE 给物品生成语义 ID，把推荐变成序列到序列生成，从而支持语义共享与冷启动。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_onerec.png" width="62%" alt="OneRec 端到端" />
  <p>图 7：OneRec 用单一模型生成推荐会话</p>
</div>

**OneRec** 是目前最完整的一步：Encoder-Decoder 直接生成 5～10 个物品的会话；用语义 token 表示物品；解码器前馈层引入 MoE 扩容量；再用迭代偏好对齐（IPA）解决「推荐没有显式偏好对」的问题——奖励模型给多个候选会话打分，最高/最低分别作 chosen/rejected，用 DPO 更新。线上报告用户总观看时长提升 1.68%。

## 6. 上篇收束

从召回、排序到重排，再到偏差与冷启动，级联架构的方法论已经完整。它的强项是「分而治之」——每一段都可以独立优化、独立评估；弱点是段与段之间的目标与信息损失，以及越来越高的工程复杂度。

生成式推荐正是针对这些弱点提出的另一种组织方式。下篇沿着「基础 → 规模化 → 端到端 → 推理 → 扩散」展开，看它如何一步步把流水线压缩成一个模型。
