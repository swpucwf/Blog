# 个性化重排：PRM 与 PRS

## 1. 启发式重排的两个天花板

MMR 与 DPP 便宜、可解释，但有两个绕不过去的限制：

- **目标函数靠手工设计**：\(\lambda\)、核矩阵、相似度定义都需人工调，难以表达高阶、非线性的物品关系；
- **用户偏好没有进入列表级优化**：同一张候选列表，对所有用户用同一套重排逻辑。

个性化重排换个做法：把「整张列表」当作建模对象，用数据驱动的方式直接学「什么样的排列对当前用户更好」。

## 2. PRM：Transformer 做列表建模

PRM 的思路是把排序列表当成一个序列，用 Transformer 编码物品间相互影响，再用 softmax 输出每个位置的概率。

### 2.1 三段结构

**输入层**给每个物品准备两类信息：

$$
E = [\underbrace{x_j}_{\text{物品特征}};\ \underbrace{pv_j}_{\text{个性化向量}}] + \mathrm{PE}_j
$$

- \(x_j\)：物品 ID 嵌入、类别、标签等基础特征；
- \(pv_j\)：用户对物品的个性化偏好向量；
- \(\mathrm{PE}_j\)：位置嵌入，利用「初始排序本身带有信息」这一点。

**编码层**用多层 Transformer 编码器块（多头自注意力 + 前馈）建模列表内交互。关键点在于：用户点不点第 j 个物品，可能受第 k 个物品影响——替代、互补、或者提供了多样性。这种影响是长距离的，不受初始位置限制。

**输出层**对每个位置做线性映射得到 logit，再对整张列表做 softmax：

$$
P(y_i\mid X, PV) = \mathrm{softmax}(\text{logits})
$$

softmax 的两个作用值得注意：一是归一化成概率分布；二是**隐含建模相对关系**——每个物品的概率取决于它与其他物品分数的比较，这正是列表级优化想要的。

### 2.2 PV 从哪来

个性化向量不是端到端学出来的，而是**从预训练 CTR 模型里借**：取该模型输出层之前那个隐藏层的激活值。它浓缩了「用户 u 对物品 i 的偏好」，比原始特征更有判别力。

这个设计很实用：预训练模型已经在海量行为上训练过，PV 相当于免费复用了它的表征能力。代价是 PRM 的效果被预训练模型封顶——PV 里没有的信息，重排阶段补不回来。

```python
# 用户侧向量平铺到序列维，物品侧保留序列维
page = concat([tile(user_emb), item_features, pv_emb, item_emb])
enc = page + PositionEncoding(max_len)(page)
for _ in range(blocks):
    enc = TransformerEncoder(heads, dropout)(enc)
score = softmax(Flatten(Dense(1)(Dense(dim, "tanh")(enc))))
```

### 2.3 实测

| MAP@5 | new_P@5 | old_MAP@5 | old_P@5 |
|---|---|---|---|
| 0.2207 | 0.0926 | 0.2824 | 0.1196 |

这里有个值得记录的现象：**PRM 反而低于基线（old_MAP@5 0.2824）**。在小数据集上，Transformer 的参数量与数据量不匹配，端到端列表建模容易过拟合；而基线是稳定的 point-wise 排序。这与 DIEN/DSIN 在序列建模上的表现一致——**复杂结构需要足够数据与足够长的序列才能兑现收益**。

## 3. PRS：把排列本身当变量

PRM 仍有一个盲区：它评估每个物品的分数，却忽略**排列顺序本身**对行为的影响。

经典例子：用户看到 [A, B, C] 毫无兴趣，看到 [B, A, C] 却买了 A——把贵的 B 放前面，A 显得便宜。这叫**排列变异影响（Permutation-Variant Influence）**。

n 个物品有 n! 种排列，穷举不可行。PRS 拆成两阶段：

- **PMatch**：用搜索快速筛出少数候选排列；
- **PRank**：用神经网络评估候选排列，选最优。

</div>

### 3.1 PMatch：两个预测模型 + Beam Search

离线先训两个 point-wise 模型：

- **CTR 模型**：\(P_{CTR}(i\mid u)\)，物品被点击的概率；
- **Next 模型**：\(P_{Next}(i\mid u)\)，用户看完这个物品后继续浏览的概率。

Next 模型的引入是关键：物品不仅要能吸引点击，还要能**引导用户继续往下看**。

在线用 FPSA（快速排列搜索）逐步扩展序列，每步用奖励函数排序并保留 Top-k：

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_prs_fpsa.png" width="36%" alt="FPSA" />
  <p>图 4：Beam Search 构建候选排列</p>
</div>

奖励由两个量融合：

- **rPV**：浏览到列表末尾的概率，等于沿序列连乘 Next 概率；
- **rIPV**：期望点击数，等于每个位置「曝光概率 × 点击概率」之和。

$$
r = \alpha \cdot r_{PV} + \beta \cdot r_{IPV}
$$

曝光概率逐位递减，模拟真实浏览行为：越靠后的位置越少人看到。这个建模比「每个物品独立打分再排序」更贴近真实收益。

### 3.2 PRank：DPWN 评估排列

PMatch 给出候选排列后，PRank 用 Bi-LSTM 网络（DPWN）评估：

$$
h_t = [\overrightarrow{h_t};\ \overleftarrow{h_t}],\qquad
z_t = [h_t;\ x_u;\ x_{v_t}],\qquad
p_t = \sigma(\mathrm{MLP}(z_t))
$$

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_prs_dpwn_architecture.png" width="46%" alt="DPWN" />
  <p>图 5：双向 LSTM 编码排列上下文</p>
</div>

排列得分是各位置点击概率之和：

$$
LR(O) = \sum_{t=1}^{|O|} p_t
$$

选 \(LR\) 最高的排列输出。

## 4. 三种重排方案对比

| 方案 | 优化对象 | 是否个性化 | 需要训练 | 主要代价 |
|---|---|---|---|---|
| MMR / DPP | 多样性 vs 相关性 | 否 | 否 | 目标手工设计 |
| PRM | 列表级点击概率 | 是（PV） | 是 | 依赖预训练模型、参数多 |
| PRS | 排列级收益 | 是（用户特征） | 是（CTR + Next + DPWN） | 两阶段、工程复杂 |

三者不是替代关系：MMR 适合快速上线与规则兜底；PRM 适合有成熟 CTR 模型、列表长度适中的场景；PRS 适合「顺序显著影响决策」的场景（电商、内容流），但需要同时维护三套模型。

## 5. 落地判断

- **先看列表长度**：PRM 的 Transformer 与 PRS 的 Beam Search 都随长度快速变贵，Top-10 以内比较现实；
- **PV 的质量决定 PRM 上限**：预训练 CTR 模型差，重排再好也补不回来；
- **PRS 的收益来自 Next 模型**：只优化点击会推出「标题党」，加上继续浏览概率才能兼顾深度；
- **小数据别上重排模型**：实测 PRM 低于基线是明确信号，先攒数据、先做 MMR。
