# LLM 三阶段与推荐映射

## 1. LLM 是规模化的 Transformer

大语言模型本质上就是把 Transformer 堆到数十亿乃至数万亿参数，再在海量文本上训练。但从早期的 BERT、GPT-2 到现在的 LLaMA、GPT-4，真正的分水岭不是参数量，而是**训练范式的系统化**：预训练 → 指令微调 → 偏好对齐。

## 2. 预训练：学语言本身

**目标**是因果语言建模（下一个 token 预测）：

$$
\mathcal{L}_{CLM} = -\sum_{i=1}^{n}\log p_\theta(x_i\mid x_{<i})
$$

**数据**是网页、书籍、论文、代码、对话的混合。数据多样性与质量直接决定模型能力上限。

**架构**以 Decoder-Only 为主（GPT、LLaMA），参数量从 7B 到万亿不等，训练需数千到数万张卡、数周至数月。因此绝大多数团队选择从开源权重起步，而不是从零预训练。

规模上去之后会出现**Scaling Laws**：性能随参数、数据、计算量增长而稳定提升，并伴随零样本、少样本等涌现能力。

## 3. 指令微调：学会按要求做事

预训练模型只是个「文本补全器」，给它一段话它自然续写，但并不等于听指令。SFT 用「指令-输入-输出」三元组教它理解任务：

```text
指令：总结下面这段文字的主要内容。
输入：[一段关于人工智能发展历史的文字]
输出：[人工智能从1950年代诞生至今，经历了...]
```

损失只在输出部分计算：

$$
\mathcal{L}_{SFT} = -\sum_{i=1}^{m}\log p_\theta(y_i\mid y_{<i}, c)
$$

指令与输入不参与梯度更新——这样模型专注学「给定指令如何生成正确输出」。训练可用全参微调，也可用 LoRA 等参数高效方法；数据量通常数万到数十万条，训练数小时到数天。

效果上，SFT 让模型获得「理解指令」这一元能力，零样本与少样本表现显著提升。

## 4. 偏好对齐：对齐「什么更好」

SFT 只教了「人类会怎么答」，没教「什么样的答案更好」，于是仍有啰嗦、幻觉、不安全等问题。RLHF 分三步：

1. **收集偏好数据**：同一 prompt 生成多个输出，人工排序，得到 \((c, y_w, y_l)\)；
2. **训练奖励模型**：

$$
\mathcal{L}_{RM} = -\mathbb{E}\left[\log\sigma\left(r_\phi(c,y_w)-r_\phi(c,y_l)\right)\right]
$$

3. **策略优化**：用 PPO 最大化奖励，同时用 KL 约束防止偏离参考模型：

$$
\mathcal{L}_{RL} = \mathbb{E}[r_\phi(c,y)] - \beta\cdot D_{KL}\left(p_\theta \| p_{ref}\right)
$$

RLHF 的问题是要额外训奖励模型、要跑强化学习，流程重且不稳定。**DPO** 把奖励模型隐式地表达在策略模型里，直接从偏好对优化：

$$
\mathcal{L}_{DPO} = -\mathbb{E}\left[\log\sigma\left(\beta\log\frac{p_\theta(y_w|c)}{p_{ref}(y_w|c)} - \beta\log\frac{p_\theta(y_l|c)}{p_{ref}(y_l|c)}\right)\right]
$$

训练像监督学习一样简单稳定，效果常与 RLHF 持平，因此成为当前主流。

## 5. 三阶段如何映射到推荐

| 阶段 | LLM 做法 | 推荐适配 | 核心挑战 |
|---|---|---|---|
| 预训练 | 大规模文本 CLM | 行为序列 + 多模态内容预训练 | 语言能力与协同信号如何配比 |
| 指令微调 | 指令-输出对 | 召回/排序/重排/解释任务指令化 | 物品是 ID，模型不认识 |
| 偏好对齐 | 人工排序 + RLHF/DPO | 隐式反馈对齐、多目标权衡 | 反馈隐式、目标多维 |

三处都需要重新设计，不能直接照搬：

**预训练的数据配比**。偏语言能力，模型会忽视协同过滤信号；偏行为数据，语义理解与泛化会退化。新闻、视频这类内容驱动的场景应更偏语言；电商、音乐这类协同信号丰富的场景应更偏序列建模。

**指令化的输入输出格式**。推荐任务多且形态不同（召回给候选、排序给分数、解释给文本），要统一成「指令 → 输出」。更麻烦的是物品 ID 对语言模型是完全陌生的符号，必须翻译成语义表示——这就是物品 Tokenizer 要解决的问题。

**偏好信号的构造**。推荐没有「人类排序」，只有点击、时长、跳过这些隐式反馈；目标也不是单一的「有用」，而是点击率、停留、留存、生态健康的多维权衡。这使推荐的对齐比 LLM 更微妙。

## 6. 推荐特有的四个硬约束

- **物品 Token 化**：ID 无语义，怎么注入？用语义 ID、文本描述还是混合方案，直接决定模型能否泛化与冷启动；
- **协同信号融合**：「买了 A 的人常买 B」这类知识不在内容描述里，必须专门设计注入路径；
- **冷启动**：内容特征能救新物品，但要设计成「有交互靠协同、无交互靠内容」的自适应切换；
- **实时性**：自回归逐 token 生成，延迟可能到数百毫秒，而线上要求几十毫秒。量化、KV Cache、推测解码只是基础，还需要离在线结合与缓存策略。

## 7. 迁移的边界

LLM 给推荐带来的不只是技术，更是**组织方式**的转变：从「召回/排序/重排分而治之」转向「统一生成框架端到端建模」。

但也要清楚代价：推荐无法直接复用 LLM 的预训练权重（词表与模态都不同），能借的是架构设计、优化技巧与训练框架；生成式模型的推理成本比判别式高一个量级，落地必须做取舍。

一个务实的路径是：**先借 LLM 的架构与训练范式做排序/重排，再逐步向召回与端到端扩展**。
