# 语义对齐与自主推理

## 1. 一道语义鸿沟

推荐靠**协同语义**（用户-物品交互学出来的相似性），LLM 懂的是**语言语义**。把 `item_12345` 直接喂给 LLM，它就是 OOV 符号；换成商品标题，LLM 能懂字面意思，却感受不到「买过 A 的人也买 B」。

理想表示要同时满足两件事：**语言可理解**、**能承载协同信号**。

## 2. LC-Rec：让索引既能读又能算

### 2.1 索引学习

先用 LLM 编码标题描述得到文本嵌入，再用 RQ-VAE 逐层量化成索引序列 `<a_5><b_2><c_6><d_7>`。层次化带来两个性质：语义逐层细化、相似物品共享前缀——为自回归生成提供结构化先验。

真正的难点是**索引冲突**：不同物品落到同一序列。TIGER 靠加一层索引解决，但那层不携带语义，等于往表示里塞噪声。

LC-Rec 的办法是**均匀语义映射**：最后一层量化加均匀分布约束，把分配建模成最优传输问题：

$$
\min \sum_{r_H\in\mathcal{B}}\sum_k q(c_H=k\mid r_H)\|r_H-v^H_k\|^2
$$

约束是每个样本概率和为 1、每个码字分到 \(|B|/K\) 个样本，用 Sinkhorn-Knopp 求解。码字利用率上去了，冲突率自然下来，且不必增加无语义层。

### 2.2 三层对齐任务

有了索引还不够，LLM 得学会它的含义。LC-Rec 设计了三层递进：

1. **序列物品预测**：给历史索引序列预测下一个——学协同模式；
2. **显式索引-语言对齐**：索引→标题描述、标题描述→索引，双向互译建立桥梁；
3. **推荐导向的隐式对齐**：非对称预测（索引序列→标题）、基于意图的物品预测（评论意图→索引）、个性化偏好推理（索引序列→偏好总结）。

三层下来，两种语义在模型内部形成统一空间，并出现三个可观测现象：

- **层次被内化**：`<a_66>` 生成「Nintendo 游戏」，加到 `<a_66><b_197><c_236>` 收敛到「Pokémon 系列 - 3DS」；
- **协同优于纯文本**：同一个游戏，纯文本检索会返回同名不同平台版本，索引生成会返回同类型同平台；
- **全库检索**：索引总量远小于物品数，模型可直接自回归生成，不依赖候选集。

## 3. PLUM：工业级对齐

学术方案到 YouTube 规模有三道坎：多模态、增量更新、十亿级检索。PLUM 的三阶段值得逐段看。

### 3.1 语义 ID：内容 + 协同

视频用三个编码器：文本（标题/描述/ASR）、视觉（关键帧）、音频。三者直接拼接而非注意力融合——实验发现码本会自然学到「音乐视频看音频、教程看文本、游戏看视觉」。

更关键的是补上协同嵌入 \(e_{cf}\)（图网络或矩阵分解学「谁和谁常被一起看」）：

$$
e_{final} = [e_{text}\oplus e_{visual}\oplus e_{audio}\oplus e_{cf}]
$$

两个细节保证层次不乱：**多分辨率码本**（128/256/512/1024，逐层变细）与**渐进式掩码训练**——只给前 k 层索引、其余 mask，要求解码器重建原嵌入，逼每层都携带增量信息。

### 3.2 持续预训练：三类数据、五五开

新增的 1024 个 ID token 不是随机初始化，而是**语义引导**：找到每个码字最近的若干视频，用它们标题的 LLM 嵌入均值作初值。

三类训练数据：

| 数据 | 作用 | 占比 |
|---|---|---|
| 纯 ID 序列 | 学协同模式 | 约 50% |
| 领域文本 | 防语言退化、学平台语言习惯 | 约 50% 中的一部分 |
| ID-文本交错 | 建立双向映射 | 元数据语料内约 60–70% |

交错样本长这样：`视频 <A1991><B5><C2><H10> 的标题是：健康管理：如何应对慢性疼痛`。大量配对之后，注意力会自动学会「看到前缀激活对应语义、生成 ID 时按内容选码字」。

零样本的层次理解是最直观的验收：`<A37>` → 任天堂内容，加一层 → Switch 游戏，再加 → 塞尔达系列，最后 → 旷野之息武器收集攻略。没人告诉它每层代表什么。

### 3.3 微调与上线结果

输入把三种模态混在一条 prompt 里：语义 ID（协同）、自然语言（周六晚 8 点、手机）、离散化数值（完播率高/中/低）。自注意力自己学它们的交互。SFT 再加一层奖励加权 \(r(u,v)\)——长看、点赞的样本权重高，误点、秒退的低，避免把噪声编码进语义空间。

线上数据：

- ID 唯一性 96.7%（LC-Rec 基线 94.0%）；
- 覆盖 95% 曝光所需视频数：长视频改善 2.6 倍、短视频 13.2 倍；
- 参数是传统大嵌入表的 100 倍，但 900M MoE 只需 2.5 亿样本，总 FLOPs 仅为 LEM 的 0.55 倍。

最后一条最值得记：**对齐带来的样本效率，抵消了参数膨胀**。

## 4. 从「认识」到「思考」

PLUM 解决了认识物品，但不会解释为什么推。OneRec-Think 走的是「教」的路线：先用推理脚手架（分析用户 → 评估候选 → 生成推荐）的模板做监督，再做物品对齐的多任务训练，最后用强化学习激活推理能力。

问题在于这仍是**模仿学习**：模板是人定的、教师认知有偏、每换一个场景就得重设一套。三个后果——推理路径被模板限制、知识停在静态、迁移成本高。

## 5. RecZero：完全自主学习

既然模板是拐杖，那就撤掉。RecZero 只给一个**结构性框架**，不给内容：

```text
<analyze user>…</analyze user>
<analyze item>…</analyze item>
<match>…</match>
<rate>…</rate>
```

模板规定「有这四步、按这个顺序」，但每一步写什么、关注哪些特征、怎么权衡，全留给模型探索。

**奖励极简**：

$$
r(s,a) = -|y_{true}-y_{pred}|
$$

只评最终评分误差。但因为推理路径与评分是联合生成的，梯度会反传到整条轨迹——**哪种思考方式系统性带来更准的预测，就被强化**。

机制上用 GRPO：同一输入采样 K 条轨迹，算相对优势 \(\hat{A}_k=r_k-\bar{r}\)，增强高于平均的轨迹：

$$
\mathcal{L}_{GRPO} = -\frac{1}{K}\sum_k \hat{A}_k\log\pi_\theta(s_k,a_k\mid \text{Prompt})
$$

不需要 critic，也不需要「唯一正确答案」——推荐里同一对用户-物品本来就可以有多种合理解释，GRPO 允许保留多种有效模式。

**涌现出来的四种能力**：

- **分层推理自发形成**：从「用户喜欢历史书→4 分」进化到多维画像 + 多因素权衡；
- **会用负面信号**：历史里的低分被显式写进推理（「用户对恐怖题材评分低，应避免」）；
- **按信息量调整深度**：冷启动走群体统计的保守推理，历史丰富才做深度个性化；
- **跨领域迁移**：图书里学的「区分主题与文风」，到电影自动变成「区分故事与拍摄风格」。

代价是**初期探索太贵**：从零开始要大量无效采样才能撞见「先分析用户」这种基本策略。

## 6. RecOne：冷启动 + 强化学习

RecOne 的折中很像教学：先给少量高质量范例，再让学生自己练。

**冷启动样本两类**：

- **对齐样本**：教师模型预测正确，保留完整推理；
- **纠偏样本**：教师预测错了，但保留前三步（分析用户、分析物品、匹配），只把最后 `<rate>` 换成正确评分。

第二类很有意思——它教模型「思路对了、最后一步错了也能救」，避免因为结论错误就否定整条推理。

数据量只要数千到数万条（传统蒸馏要数十万到百万级），小样本反而防止过拟合教师的表面模式，给 RL 留出优化空间。

**效果**：

- 达到 RecZero 同等性能所需步数减少约 60%；
- Amazon-book：RMSE −6.7%、MAE −16.8%；Amazon-music：RMSE −12.2%、MAE −29.9%；
- 总计算量为 RecZero 的 40～50%。

为什么有监督起步反而上限更高？因为纯 RL 会掉进**局部最优**：早期发现「标签匹配」这个还不错的策略就停止探索。冷启动把它放到更接近全局最优的起点，后续探索才能往精细方向走。

一个更准确的总结：**监督学习给「语言」（怎么组织思考），强化学习给「智慧」（何时用什么方式思考）**。

## 7. 三种范式的取舍

| 方案 | 监督来源 | 推理自由度 | 主要代价 |
|---|---|---|---|
| OneRec-Think | 人工模板 + 教师 | 低 | 场景迁移成本高 |
| RecZero | 仅任务奖励 | 高 | 初期探索昂贵 |
| RecOne | 少量冷启动 + 任务奖励 | 中高 | 需设计冷启动样本 |

## 8. 尚未解决的问题

- **单步 vs 序列决策**：现在是「给定历史与候选预测评分」，真实推荐是序列决策，要权衡长期价值与探索；
- **推理忠实性**：生成的推理可能只是事后合理化，如何验证它真是决策依据；
- **可控性**：业务规则、价值观怎么注入而不破坏自主性；
- **通用性**：跨领域迁移已有苗头，但离「一个通用推理引擎适配任意场景」还很远。

## 写在最后

语义对齐解决了「模型认识物品」，自主推理解决了「模型会思考」。下一篇换个生成范式：不再逐 token 自回归，而是从噪声里一次性去噪出整条推荐——扩散推荐。
