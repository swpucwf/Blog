# 向量召回：从 Word2Vec 到 EGES

## 1. 序列建模的起点

Word2Vec 的假设很朴素：**在相似语境中出现的词，含义也相似**。把它迁到推荐只有一步：把「词语」换成「物品」，把「句子」换成「用户行为序列」。

两种架构里，Skip-Gram 用中心词预测上下文，CBOW 反过来。推荐场景多用 Skip-Gram，因为它在稀疏序列上的表现更好。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_w2v_skip_gram.svg" width="46%" alt="Skip-Gram 结构" />
  <p>图 1：Skip-Gram 用中心词预测上下文</p>
</div>

条件概率用 softmax 表示：

$$
P(w_{t+j} \mid w_t) = \frac{e^{v_{w_{t+j}}^T v_{w_t}}}{\sum_{k=1}^{|V|} e^{v_{w_k}^T v_{w_t}}}
$$

分母要遍历整个词表，代价过高，于是有了负采样：把多分类拆成多个二分类，正样本拉近、负样本推远。

$$
\log \sigma(v_{w_{t+j}}^T v_{w_t}) + \sum_{i=1}^{k} \mathbb{E}_{w_i \sim P_n(w)} \log \sigma(-v_{w_i}^T v_{w_t})
$$

这套「正样本拉近、负样本推远」的范式，后面所有双塔与对比学习模型都在沿用。

## 2. Item2Vec：最直接的迁移

Item2Vec 直接调用 Word2Vec 的 Skip-Gram，把每个用户的交互历史当成一个「句子」：

```python
from gensim.models import Word2Vec

model = Word2Vec(
    train_hist_movie_id_list,   # 每个元素是一个用户的物品序列
    vector_size=64,             # 嵌入维度
    window=5,                   # 上下文窗口
    min_count=1,
    workers=4,
)
```

它的贡献是把「序列建模」这条路走通了，局限也很明显：

- 把交互历史当成**无序集合**，丢掉时间顺序；
- 商品只靠 ID 共现，**新物品没有向量**；
- 窗口内的共现没有区分行为强度（点击与购买等价）。

## 3. EGES：用属性信息补足稀疏

EGES 针对上面两个问题各给一招。

**第一招：会话级商品图 + 带权随机游走**。不再把用户全部历史串成一条序列，而是以 1 小时为窗口切会话，会话内相邻出现的商品之间建有向边，边权是转移频率。然后在图上按边权概率随机游走生成训练序列。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_eges_item_graph.png" width="56%" alt="商品图构建" />
  <p>图 2：会话内的商品转移构成有向图</p>
</div>

**第二招：商品 ID + 属性向量的加权聚合**。商品有 \(n\) 种辅助信息（类别、品牌、价格区间等），为它维护 \(n+1\) 个向量，最终表示按可学习权重加权：

$$
H_v = \frac{\sum_{j=0}^{n} e^{a_v^j} W_v^j}{\sum_{j=0}^{n} e^{a_v^j}}
$$

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_eges_model.png" width="52%" alt="EGES 模型结构" />
  <p>图 3：按商品自适应的权重聚合 ID 与属性向量</p>
</div>

\(a_v^j\) 是商品特定的注意力参数：手机品类里品牌权重更高，日用品里价格权重更高。这比早期 GES 的简单平均更合理。

**冷启动**：没有任何交互的新商品没有 ID 向量，也没有训练好的注意力权重，就用所有属性向量的均值代替。虽然放弃了差异化加权，但至少让新商品能被召回。

训练仍用负采样，损失是标准二分类交叉熵：

$$
L(v,u,y) = -\left[y\log\sigma(H_v^T Z_u) + (1-y)\log(1-\sigma(H_v^T Z_u))\right]
$$

## 4. Airbnb：把业务目标写进目标函数

Airbnb 面临的场景更特殊：房源非标、预订稀疏、地理位置关键。它做了三处改动。

**会话切分**：连续点击间隔超过 30 分钟就切一个新会话，用时间窗口捕捉「一次搜索场景内的连贯意图」。

**行为权重差异化**：预订的信号强度远高于点击，训练时要给更高权重。

**全局上下文**：不只窗口内的物品是上下文，会话最终预订的房源与序列中每一个浏览房源都构成正样本对，不管距离多远：

$$
\arg\max_\theta \sum_{(l,c)\in\mathcal{D}_p}\log\frac{1}{1+e^{-v_c^Tv_l}}
+ \sum_{(l,c)\in\mathcal{D}_n}\log\frac{1}{1+e^{v_c^Tv_l}}
+ \log\frac{1}{1+e^{-v_{l_b}^Tv_l}}
$$

  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_airbnb_global_context.png" width="56%" alt="Airbnb 全局上下文" />
  <p>图 4：预订房源与序列中每个浏览房源构成正样本</p>

**同市场负采样**：如果负样本从全国随机抽，模型会偷懒学到「地理位置」这个简单特征，而不是房源本身的差异。改从同一城市抽负样本，迫使模型学同城房源的细微差别。

这一改动的启发是通用的：**负采样策略决定了模型会学到什么 shortcut**。

## 5. 四种方法对比与实测

| 方法 | 序列来源 | 关键改进 | 局限 |
|---|---|---|---|
| Word2Vec | 文本 | 负采样让大规模训练可行 | 不感知业务 |
| Item2Vec | 用户历史 | 迁移最直接 | 无序、无属性、冷启动差 |
| EGES | 会话图 | 属性加权、图上游走 | 图构建与维护成本高 |
| Airbnb | 点击会话 | 全局上下文、同市场负采样 | 强依赖业务假设 |

在 MovieLens 上的召回指标（HitRate@10）：

| 方法 | HitRate@10 | NDCG@10 |
|---|---|---|
| Item2Vec | 0.0082 | 0.0036 |
| EGES | 0.0189 | 0.0097 |

EGES 明显优于 Item2Vec，差距主要来自会话图与属性信息。需要注意的是，这类序列召回方法的 HitRate 绝对值不高——它们通常作为**多路召回中的一路**，负责补足协同过滤覆盖不到的长尾与语义相似。

## 6. 三个可迁移的经验

- **序列的切分方式决定学到什么**。按用户全历史切，学的是长期兴趣；按会话切，学的是即时意图。两者应作为不同召回通路并存。
- **负采样是隐式的业务约束**。样本从哪来，模型就学哪里的差异。同市场负采样、难负样本挖掘都是这个思路。
- **属性是冷启动的桥**。ID 向量靠行为，属性向量靠内容；加权聚合让两者互补，新物品至少能靠属性被召回。
