# 生成式推荐：从判别到生成

## 1. 十年没变的那件事

无论模型从协同过滤走到 DeepFM 再到 DIN，底层范式始终是**判别**：给定候选集，学一个打分函数 \(f_\theta(u,i,c)\)，判断用户会不会交互。

这套体系成熟有效，但三个局限越来越难绕开：

- **参数效率**：Embedding 层占 90% 以上参数量，稀疏、低效，硬件吃不满；
- **语义缺失**：物品被当作互不相关的原子 ID，冷启动无解；
- **级联困境**：召回→粗排→精排→重排，各段目标不一致，且每次筛选都在丢信息——被召回漏掉的物品，后面再好的模型也看不到。

生成式推荐换了个问法：不判断「这个物品该不该推」，而是学「用户接下来会交互什么」的生成过程。

## 2. 序列生成视角

给定用户 \(u\)、上下文 \(c\) 与历史序列 \(i_{1:T}\)，建模整条序列的生成概率：

$$
p_\theta(i_{1:T}\mid u,c) = \prod_{t=1}^{T} p_\theta(i_t\mid i_{<t}, u, c)
$$

这个改写带来三个结构性变化：

| 维度 | 判别式 | 生成式 |
|---|---|---|
| 目标函数 | 候选集内的决策边界 | 全局概率分布 |
| 信息流动 | 前馈，各物品独立打分 | 自回归，依赖历史输出 |
| 架构 | 召回/排序/重排异构模块 | 统一 Transformer |
| 物品表示 | 随机初始化 ID | 文本或语义 ID |

最后一条尤其关键：语义表示让模型能泛化到新物品与跨域场景，这是 ID 记忆做不到的。

## 3. 基石一：Transformer

### 3.1 注意力到底在算什么

用户序列 `[iPhone 手机壳] → [AirPods] → [iPad 保护套] → [MacBook 充电器] → ?`，预测下一个物品时该看哪些历史？最近的充电器暗示当前焦点，更早的手机壳则说明这是苹果生态用户。

  <p>图 1：行为序列的时间轴</p>
</div>

注意力回答的就是这个问题：**给定 Query，序列里哪些 Key 最相关，它们的 Value 该以多大权重聚合**。

三步：

$$
Q = XW^Q,\ K = XW^K,\ V = XW^V
$$

$$
A = \mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right),\qquad Z = AV
$$

三个细节：

- **缩放 \(\sqrt{d_k}\)**：维度大时内积方差大，softmax 会趋近 one-hot、梯度消失；
- **多头**：不同头学不同关注模式（同品牌、同类别、最近行为），参数量与单头相当但表达更强；
- **注意力矩阵可解释**：第 \(i\) 行就是「预测第 \(i\) 个位置时，历史各位置的关注度」。

### 3.2 位置与时间

自注意力本身对顺序不敏感，`[i1,i2,i3]` 与 `[i3,i1,i2]` 结果相同。位置编码补上这一课：绝对位置（正弦或可学习）、相对位置（注意力里加 \(b_{i-j}\) 偏置）。

推荐场景还多一层：**真实时间间隔**。两个用户行为顺序相同，但一个三天内完成、一个跨越半年，兴趣强度完全不同。常见做法是把时间戳按小时/天/周离散成嵌入相加；HSTU 则用相对时间编码：

$$
\mathrm{rab}_{p,t} = W_{rel}\cdot \log(\Delta t_{p,t}+1)
$$

对数压缩让模型对长短周期都保持敏感。

| 维度 | Encoder-Decoder | Decoder-Only |
|---|---|---|
| 注意力 | 双向 + 因果 + 交叉 | 统一因果 |
| 参数分布 | 分散在三处 | 集中在解码层 |
| 计算模式 | 并行编码 + 自回归解码 | 完全自回归 |
| 代表 | T5、TIGER、OneRec | GPT、HSTU、OneRec-V2 |

选择的实用判断：

- **输入输出异构**（多模态特征 → 语义 ID 序列）用 Encoder-Decoder，双塔能自然处理模态差异；OneRec 还把 Encoder 拆成短期/长期/正反馈多条 pathway；
- **追求规模化与 MFU** 用 Decoder-Only。OneRec-V2 报告其 MFU 可达 20% 以上，而 Encoder-Decoder 通常只有 5～10%；
- **数据有限、模型不大**时，Encoder-Decoder 的结构化设计更容易训稳；
- 两者也在融合：OneRec 的 Lazy Decoder 让多层解码共享 Encoder 的 KV 输出。

### 3.4 因果掩码

自回归靠掩码实现：softmax 前给未来位置加 \(-\infty\)。

$$
M_{ij} = \begin{cases}0 & j\le i\\ -\infty & j>i\end{cases}
$$

好处是**训练可并行**：一条长度 T 的序列，一次前向就能同时学到「用前 1 个预测第 2 个」「用前 2 个预测第 3 个」……

掩码还能定制，这是推荐场景的重要设计空间：

- **Session-level**：跨会话边界屏蔽，只建模当前会话；
- **Task-specific**：CTR 看完整序列，CVR 只看已点击子序列；
- **Bidirectional Prefix**：静态特征放序列开头并允许互相可见，后续行为仍保持因果。

## 4. 基石二：Diffusion

Transformer 逐 token 生成，Diffusion 从纯噪声迭代去噪——像雕刻，从模糊石料里逐步琢出形状。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/funrec_forward_reverse_denoizing.png" width="62%" alt="扩散与去噪" />
  <p>图 4：前向加噪与反向去噪</p>
</div>

两个互逆的马尔可夫过程：前向逐步加高斯噪声，反向学一个去噪网络逐步还原。按操作空间分两类：

- **数据空间**（DDPM）：直接对原始数据扩散，理论直接但开销大；
- **潜空间**（Stable Diffusion）：先压到低维再扩散，推荐场景更常用。

条件扩散通过拼接、交叉注意力或分类器引导注入用户历史，让生成受控。

四类推荐应用：特征增强（DiffuASR、CausalDiffRec）、序列生成（DiffRec、DreamRec）、多模态融合（MCDRec、LD4MRec）、图结构建模（CF-Diff、GiffCF）。

需要提前记住的代价：**多步采样带来推理延迟**，工业落地必须配合采样加速或蒸馏。

## 5. 两种范式的边界

生成式不是万能：

- 它擅长**序列依赖强、物品有语义、需要端到端优化**的场景；
- 它的弱点是**推理成本与训练复杂度**——一次生成多个 token，延迟远高于一次打分；
- 判别式在候选集小、延迟敏感、特征工程成熟的场景仍然更划算。

更现实的判断是：**生成式先解决「排序与重排」，再逐步向召回与端到端扩展**。这也是下篇的组织顺序。
