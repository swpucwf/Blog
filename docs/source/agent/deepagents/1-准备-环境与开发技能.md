# 准备：环境与开发技能

## 1. 先理解工具链

课程实验统一由 **AgentSeek** 管理。它是面向 AI 应用开发的模板与生命周期工具：用模板创建项目，再用一组固定命令管理不同项目。

| 阶段 | 命令 | 用途 |
|---|---|---|
| 创建 | `agentseek create` | 从模板生成可编辑的项目 |
| 查看 | `agentseek info` | 查看项目入口、环境要求与任务 |
| 准备 | `agentseek task` | 运行依赖安装等一次性任务 |
| 检查 | `agentseek doctor` | 静态检查文件、uv、Node.js、npm、环境变量 |
| 运行 | `agentseek dev` | 启动模板声明的本地开发进程 |

每个生成项目都带 `.agentseek/lifecycle.toml`，声明当前模板需要哪些工具、环境变量、任务和本地服务。AgentSeek 读取它，但不接管应用自身的框架代码。

## 2. 准备本地环境

以 `deepagents/research` 模板为例，需要：

| 依赖 | 要求 | 用途 |
|---|---|---|
| Python | 3.12 或 3.13 | 运行 AgentSeek 与 DeepAgents 后端 |
| uv | 当前稳定版 | 安装 CLI 与 Python 依赖 |
| Node.js、npm | 当前 LTS | 运行 React 前端 |

**Windows 优先 WSL2**：课程命令以 Bash 为主。管理员 PowerShell 执行：

```powershell
wsl --install
```

重启后创建 Linux 用户，确认 `wsl -l -v` 显示版本 2，再 `wsl -d Ubuntu` 进入。项目放在 `~/projects/` 等 Linux 文件系统目录，不要放 `/mnt/c/`；不要混用 Windows 与 WSL 中的 Python、uv、Node.js、npm 或 Git。设备策略不允许 WSL2 时，留在原生 PowerShell，使用对应的 PowerShell 命令。

安装 `uv`：

```bash
# macOS / Linux / WSL2
curl -LsSf https://astral.sh/uv/install.sh | sh
```

```powershell
# 原生 Windows PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

安装 AgentSeek：

```bash
uv tool install --upgrade agentseek
```

原生 Windows 若提示工具目录不在 PATH，运行 `uv tool update-shell` 后重开终端；只想让当前会话生效可临时执行：

```powershell
$env:Path = "$(uv tool dir --bin);$env:Path"
```

确认命令可用：

```bash
agentseek version
agentseek --help
```

帮助信息中应看到 `create`、`info`、`task`、`doctor`、`dev`。版本会更新，以实际输出为准。

## 3. 创建项目

先查看模板列表（从模板仓库 `main` 分支读取最新批次）：

```bash
agentseek create --list-templates --checkout main
```

课程使用 `deepagents/research`：包含 DeepAgents 研究 Agent、Tavily 搜索与 React 前端。

```bash
agentseek create deepagents/research --checkout main --no-input
cd research_deepagent
```

`--checkout main` 让创建时读取模板仓库当前 `main`，适合跟随最新模板；若需完全复现某次结果，把 `main` 换成当时记录的完整提交 SHA。想自定义项目名、模型与端口，去掉 `--no-input` 按提示填写。

查看项目摘要与可用任务：

```bash
agentseek info
agentseek task --list
```

当前模板会列出两个准备任务：

```text
sync      Install Python dependencies with uv.
frontend  Install frontend dependencies.
```

关键文件：

```text
research_deepagent/
├── .agentseek/lifecycle.toml
├── .env.example
├── frontend/
│   ├── .env.example
│   ├── package.json
│   └── src/
├── langgraph.json
├── pyproject.toml
└── src/research_deepagent/
    ├── agent.py
    ├── prompts.py
    └── tools.py
```

安装依赖：

```bash
agentseek task sync        # uv sync
agentseek task frontend    # npm install --prefix frontend
```

## 4. 配置模型与搜索服务

复制环境文件：

```bash
cp .env.example .env
cp frontend/.env.example frontend/.env
```

课程默认用 SiliconFlow 的 OpenAI 兼容接口，以 GLM 作演示模型：

```bash
AGENTSEEK_MODEL_PROVIDER=openai
AGENTSEEK_MODEL=zai-org/GLM-5.2
OPENAI_API_BASE=https://api.siliconflow.cn/v1
OPENAI_API_KEY=<your-siliconflow-api-key>

TAVILY_API_KEY=<your-tavily-api-key>

LANGSMITH_TRACING=false
LANGSMITH_API_KEY=
```

> SiliconFlow 提供 OpenAI 兼容接口，所以供应商仍写 `openai`，凭证仍放 `OPENAI_API_KEY`；不要改用模板未声明的 `SILICONFLOW_API_KEY`、`GLM_API_KEY`。占位符要替换为真实值，**不要把真实 Key 提交到 Git**。

模型名称会上下线或改名；不可用时去模型广场复制当前可用的完整 GLM 模型 ID。也可以切换其他供应商：

| 供应商 | 关键配置 |
|---|---|
| OpenAI | `AGENTSEEK_MODEL_PROVIDER=openai`、`AGENTSEEK_MODEL=gpt-4.1-mini`、`OPENAI_API_KEY` |
| Anthropic | `AGENTSEEK_MODEL_PROVIDER=anthropic`、`AGENTSEEK_MODEL=claude-sonnet-4-6`、`ANTHROPIC_API_KEY` |
| Gemini | `AGENTSEEK_MODEL_PROVIDER=google_genai`、`AGENTSEEK_MODEL=gemini-2.5-pro`、`GOOGLE_API_KEY` |
| 其他兼容服务 | `provider=openai` + `OPENAI_API_BASE` + `OPENAI_API_KEY` + 完整模型 ID |

> OpenAI 兼容接口适合快速接入，但不代表所有扩展字段与工具行为完全一致。课程已验证 SiliconFlow + GLM 的基础流式输出与 Tool Call；修改 reasoning 模型、解析 `reasoning_content` 或自定义工具协议前，先用 `langchain-dev-guide` 检查兼容性边界。

`TAVILY_API_KEY` 用于研究 Agent 的网络搜索，可在 Tavily 控制台创建。

## 5. 检查并启动

```bash
agentseek doctor            # 检查 uv、Node、npm、文件、依赖、环境变量
agentseek dev --dry-run     # 预览开发进程，不启动
```

预演应看到两个进程：LangGraph 后端默认 `http://127.0.0.1:2024`，React 前端默认 `http://127.0.0.1:5174`。

可选：为下一篇的 Trace 分析开启 LangSmith：

```bash
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=<your-langsmith-api-key>
LANGSMITH_PROJECT=deepagents-course
LANGSMITH_ENDPOINT=https://api.smith.langchain.com
```

Endpoint 对应组织区域：EU 用 `https://eu.api.smith.langchain.com`，APAC 用 `https://apac.api.smith.langchain.com`；Key 与区域要一致。LangChain 与 LangGraph 会自动记录 Trace，不需要改应用代码。**不要**把 Key 写进 Shell 命令或 `--api-key`，命令可能进入历史、进程列表或助手日志；Trace 可能包含提示词、工具参数与模型输出，涉及敏感数据时先配置脱敏。

不用 LangSmith 时保持 `LANGSMITH_TRACING=false`、`LANGSMITH_API_KEY=` 即可。

启动：

```bash
agentseek dev
```

保持终端运行，另开终端检查实时状态：

```bash
agentseek doctor --live
```

打开 `http://127.0.0.1:5174`，输入一个研究问题，例如：

```text
Research what LangGraph 1.0 added vs 0.x. Cite sources.
```

> v0.7 的 Todo 默认关闭：运行前先看生成项目的 Agent 配置。若显式传入 `TodoListMiddleware`，界面与 Trace 会出现 Todo；没有启用时缺少计划面板并不代表运行失败。

正常运行时可以看到：启用 Todo 时 Agent 创建研究计划并更新状态；模型选择委派时展示研究子 Agent 的任务卡；最终报告附来源链接并以 Markdown 渲染。深度研究会多轮调用模型、搜索与读网页，不同模型可能需要几分钟；页面生成 thread URL 后，可用它重新打开同一会话。

## 6. 为编码助手安装开发技能

这里安装的是**编码助手开发技能**，服务对象是 Codex、Claude Code、Cursor 等工具，用来修改和调试项目；第 7 章讲的 **DeepAgents 运行时 Skill** 是给 Agent 用的，通过 `create_deep_agent(skills=[...])` 加载。两者都用 `SKILL.md`，但服务对象不同。

```bash
node --version
npm --version
cd research_deepagent
npx skills add ob-labs/agentseek --list
```

课程重点使用两个：

| Skill | 用途 |
|---|---|
| `langchain-dev-guide` | LangChain、LangGraph、DeepAgents 开发指南 |
| `langsmith-trace` | LangSmith Trace 查询与调试流程 |

安装到当前项目（默认项目级，不加 `--global`）：

```bash
npx skills add ob-labs/agentseek --skill langchain-dev-guide --skill langsmith-trace
# 也可直接指定工具
npx skills add ob-labs/agentseek --skill langchain-dev-guide --skill langsmith-trace --agent claude-code --yes
```

检查安装：

```bash
npx skills list
```

不同助手读取不同目录：Codex/Cursor 用 `.agents/skills/`，Claude Code 用 `.claude/skills/`；全局目录在用户主目录下。

使用 `langchain-dev-guide` 时明确提到技能名并给具体任务，例如：

```text
请使用 langchain-dev-guide 检查这个 deepagents/research 项目的模型配置。
本课程默认通过 SiliconFlow 的 OpenAI 兼容接口使用 GLM。
请核对环境变量，并说明 Tool Call、reasoning_content 等能力的兼容性边界。
```

助手应先读取 `langchain-dev-guide/SKILL.md`，再按需读取被引用的资料；可以要求它说明用了哪个参考文件，确认技能生效。

## 7. 用 langsmith-trace 定位一次慢调用

前置条件：已开启 `LANGSMITH_TRACING=true`，配置了 Key、项目与区域 Endpoint，且至少有一条已完成的 `research` Trace。

确认 LangSmith CLI：

```bash
command -v langsmith
langsmith --version
```

不存在时安装（macOS/Linux/WSL2）：

```bash
curl -fsSL https://cli.langsmith.com/install.sh | sh
```

> PyPI 的 `langsmith` 是 Python SDK，不提供这里的 CLI；不要用 `uv tool install langsmith` 安装。

在项目根目录加载 `.env`：

```bash
set -a
source .env
set +a
```

找到最近项目与根 Trace：

```bash
langsmith --format pretty project list
langsmith trace list --project deepagents-course --name research --include-metadata --limit 5
langsmith trace get <trace-id> --project deepagents-course --include-metadata
```

完整运行树里会看到根 `research`、`research-agent` 子 Agent、`ChatOpenAI` 模型调用、`tavily_search` 工具调用，以及多层 middleware 包装。

让编码助手分析瓶颈：

```text
请使用 langsmith-trace 分析最近一次已完成的 research Trace。
先确认项目和 trace_id，再区分：根 research 流程、research-agent 子 Agent、
run_type=llm 的实际模型调用、tavily_search 等实际工具调用。
分别找出最慢的叶子模型调用和最慢的实际工具调用。
不要把根 Trace、task 子 Agent 包装或 middleware 包装层当成瓶颈。
对候选 Run 使用 run get --include-io 检查输入、输出和错误。
输出表格：调用、类型、耗时、判断证据、可能原因、下一步建议。不要输出凭证。
```

按类型缩小范围，避免一次拉取全部 IO：

```bash
langsmith run list --trace-ids <trace-id> --project deepagents-course --run-type llm --include-metadata --limit 100
langsmith run list --trace-ids <trace-id> --project deepagents-course --run-type tool --include-metadata --limit 100
langsmith run get <run-id> --include-io --include-metadata
```

> 单次 `run list` 上限 100；复杂 Trace 可能超过。先用 `--run-type` 过滤，必要时用 `--name` 再缩小。`task` 是子 Agent 包装，不是实际工具瓶颈。部分 CLI 版本中 `run get --full` 可能返回空 IO，显式用 `--include-io` 更稳。

合格分析至少包含：使用最近一次已完成的 `research` Trace；能区分根流程/子 Agent/模型/工具；找到最慢的 `run_type=llm` 叶子 Run 与最慢的实际工具 Run；给出 `run_id`、耗时、状态与 IO 检查结果；建议与证据对应，而不是只说「换更快模型」。实测一条 Trace 含 162 个 Run、22 个模型 Run、17 个工具 Run，最慢叶子模型约 85.9 秒、最慢实际工具约 25.1 秒——数字会随模型、网络与问题变化，不要当固定预期。

技能更新与移除：

```bash
npx skills update -p          # 只更新当前项目
npx skills update -g          # 只更新全局
npx skills remove langchain-dev-guide langsmith-trace --yes
```

## 8. 网络问题排查

`agentseek create` 需要访问 GitHub。先查仓库连通性：

```bash
git ls-remote https://github.com/agentseek-ai/agentseek-templates.git
```

出现 `Could not resolve host`、`Connection timed out`、`Failed to connect` 时，先排查网络，而不是断定 CLI 异常。AgentSeek 会把远程模板缓存到 Cookiecutter 用户目录，不要为绕过连接问题直接删缓存——可能丢失可用缓存，或长期停留在旧模板。

需要代理时，新开专用终端设置标准代理变量（示例端口 7890，换成实际地址）：

```bash
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export NO_PROXY=127.0.0.1,localhost
```

`NO_PROXY` 避免把本机 2024/5174 端口也发给代理。这些变量会被同一终端启动的 Git、uv、npm、Python HTTP 客户端与 `agentseek dev` 子进程继承；设置后重跑 `git ls-remote`，并从同一终端执行后续命令。若浏览器和模型接口正常、只有 `git` 失败，可单独检查 `git config --global --get http.proxy` 再设置。

要区分三类配置：`HTTP_PROXY/HTTPS_PROXY` 是网络代理，可能影响 Git、依赖安装与运行时 API 调用；`UV_INDEX_URL`/npm registry 只改变包下载来源；`OPENAI_API_BASE` 是模型服务地址，不是代理。三者不能互相替代。Python 依赖下载慢时，可临时为单次同步指定镜像：

```bash
UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple agentseek task sync
```

> 只使用团队批准或自己信任的代理与镜像；公共加速地址的可用性与安全性会变化，不要硬编码进项目模板。

网络受限但已在别处取得模板仓库时，可直接用本地模板路径创建：

```bash
agentseek create /absolute/path/to/agentseek-templates/templates/deepagents/research --no-input
```

## 9. 准备完成的标志

- 有一个可编辑的 `deepagents/research` 项目；
- 有一套由 `.agentseek/lifecycle.toml` 声明的本地开发流程；
- 能通过 `agentseek doctor` 检查、由 `agentseek dev` 启动前后端；
- 启用 LangSmith 时，有一条可供分析的真实研究 Trace；
- 编码助手已装上 `langchain-dev-guide` 与 `langsmith-trace`。

> **补记**：准备篇的关键不是「装好依赖」，而是把**项目生命周期**和**开发技能**分开理解：AgentSeek 管创建、依赖、检查与启动；编码助手 Skill 管改代码与看 Trace；而 DeepAgents 运行时 Skill 是给 Agent 自己用的能力包（第 8 篇展开）。三者的目录、加载方式和作用对象都不同，混用会浪费很多排查时间。
