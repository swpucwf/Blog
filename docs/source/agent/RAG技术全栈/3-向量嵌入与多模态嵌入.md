# 向量嵌入与多模态嵌入

## 1. 嵌入是什么

向量嵌入（Embedding）把文本、图像、音频等高维数据映射成低维稠密向量。想象把每个词、每段话、每张图放进一个巨大的多维空间，给它一个坐标——这个坐标就是向量，它「嵌入」了原始数据的关键信息。

它的意义不在于数值本身，而在于**几何关系承载语义**：语义相近的对象，向量距离更近。三种常用度量：

| 度量 | 计算 | 特点 |
|---|---|---|
| 余弦相似度 | 夹角余弦值 | 最常用，值越接近 1 越相似 |
| 点积 | 向量乘积和 | 归一化后等价于余弦相似度 |
| 欧氏距离 | 空间直线距离 | 距离越小越相似 |

## 2. 嵌入在 RAG 里做什么

四个步骤构成检索闭环：

1. **离线索引**：文档切块后，用嵌入模型逐块转成向量，存入向量库；
2. **在线查询**：用**同一个**嵌入模型把问题转成向量；
3. **相似度计算**：与库中所有块向量比较；
4. **召回上下文**：取 Top-K 块与问题一起送进 LLM。

第 2 步的「同一个模型」是硬要求。换模型等于换了坐标系，索引必须重建，否则相似度没有意义。

嵌入质量直接决定召回质量。好的模型能捕捉「提问方式和原文表述不一致」的深层语义；差的模型召回一堆不相关文本，等于给 LLM 喂噪音。

## 3. 技术演进三段

**静态词嵌入（Word2Vec、GloVe）**：每个词一个固定向量，验证了向量运算的语义能力（国王 − 男人 + 女人 ≈ 王后），但无法处理一词多义。

**动态上下文嵌入（BERT）**：自注意力让同一个词在不同语境得到不同向量，一词多义问题被解决。

**RAG 时代的新要求**：

- **领域自适应**：法律、医疗等专业语料上，通用模型表现会掉，需要微调或指令化（如 INSTRUCTOR）；
- **多粒度与多模态**：从短句到长文档到图像表格都要能编码；
- **效率与混合检索**：向量维度直接影响存储与检索成本；BGE-M3 这类模型同时支持稠密与稀疏检索，为混合召回提供基础。

## 4. 训练原理要点

现代嵌入模型多基于 Transformer 编码器，自监督预训练打底，检索目标微调提升排序能力。

**MLM**：随机遮住 15% 的 token 让模型预测，迫使它学习上下文关系。**NSP**：判断两句是否相邻；后续研究（RoBERTa）发现这个任务过易甚至有害，很多现代模型已移除。

真正决定检索效果的是后两件事：

- **度量学习**：以相似度为优化目标，收集相关文本对，优化向量空间的**相对距离**，而不是追求绝对相似度接近 1；
- **对比学习**：构造 (Anchor, Positive, Negative) 三元组，拉近正例、推远负例。负例的采样质量往往比正例数量更关键。

## 5. 怎么选嵌入模型

从 MTEB 排行榜起步，但要读懂它的四个维度：

| 图中要素 | 含义 | 取舍 |
|---|---|---|
| 横轴：参数量 | 模型大小 | 越大能力越强，显存与延迟越高 |
| 纵轴：平均得分 | 综合性能 | 越高通用语义越强 |
| 气泡大小：维度 | 输出向量长度 | 越高语义越丰富，存储与计算越贵 |
| 气泡颜色：最大 token | 可处理长度 | 决定分块上限 |

榜单只能做粗筛，真正的选型要看六个维度：任务（RAG 关注 Retrieval 排名）、语言（中文必须明确支持）、模型大小、向量维度、最大 token、成本。

最后的决定必须靠私有评测集：

1. 选几个候选作为基线；
2. 用真实业务数据构造「问题 + 标准答案 / 最相关块」样本；
3. 在私有集上跑召回率与相关性，再决定换模型还是改分块。

榜单高分不等于业务高分，这一点在垂直领域尤其明显。

## 6. 多模态嵌入：拆掉模态墙

文本嵌入无法理解「那张有红色汽车的图片」这类查询——文本向量和图像向量处在两个隔离空间，中间隔着一堵墙。多模态嵌入的目标是把不同模态映射到**同一个共享向量空间**，让「一只奔跑的狗」的文字向量靠近真实小狗图片的向量。

**CLIP** 是这个范式的起点：双编码器结构，图像编码器与文本编码器分别把两种模态映射到同一空间，用对比学习训练——最大化正确图文对的相似度，最小化错误配对。

对比学习带来的副产品是**零样本能力**：把分类转成图文检索，判断一张图是不是猫，只需比较图片向量与「a photo of a cat」的文本向量。无需针对任务微调，就能泛化到新类别。

## 7. 现代多模态模型：bge-visualized-m3

BGE 系列的视觉版在 BGE-M3 文本底座上引入图像能力，继承了「M3」三个特性：

- **多语言**：支持 100 多种语言的文本表示，可用于跨语言图文检索；
- **多功能**：文本侧支持稠密检索、多向量检索；
- **多粒度**：文本侧可处理从短句到 8192 token 的长文档。

架构上，它先用视觉编码器提取图像的 patch token，映射成与文本同维度的「图像 token」，再与文本 token 一起送入 BGE 编码器联合建模，输出统一向量。

```python
model = Visualized_BGE(model_name_bge="BAAI/bge-base-en-v1.5",
                       model_weight="Visualized_base_en_v1.5.pth")
model.eval()

text_emb = model.encode(text="datawhale开源组织的logo")
img_emb = model.encode(image="datawhale01.png")
multi_emb = model.encode(image="datawhale01.png", text="datawhale开源组织的logo")

sim = img_emb @ multi_emb.T   # 向量已归一化，点积即余弦相似度
```

它支持三种编码方式：纯文本、纯图像、图文组合。组合编码适合「以图 + 文字描述」混合检索的场景，例如「找一张类似的图，但要是蓝色的」。

## 8. 选型与分块是耦合的

两个容易忽略的约束：

- **最大 token 决定分块上限**。模型窗口 512，块就不能按 1000 token 切；
- **维度决定存储成本**。1024 维、百万级块，仅向量存储就是 GB 量级，检索延迟也随之上升。

因此嵌入模型的选型不能脱离分块策略与检索规模单独讨论。先确定数据规模与延迟预算，再在满足预算的模型里挑效果最好的。
