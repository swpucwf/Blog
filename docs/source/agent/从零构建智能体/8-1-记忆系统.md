# 记忆系统

框架搭好之后，第一个暴露的问题不是能力不够，而是「记不住」。模型本身是无状态的：每次请求都是一次独立计算，上一次说了什么、用户是谁、偏好什么，全都不在它的视野里。另一种缺失更隐蔽——知识停在训练截止那一刻，库里也没有的那部分，模型只能编。

## 1. 两个硬约束

**约束一：无状态导致的遗忘。** 同一实例内的连续对话能带上 `_history`，但这份历史只是临时消息列表：程序重启就没了，跨会话不共享，也不能检索、遗忘、整合。落到体验上是四类问题——早期信息被上下文窗口挤掉、偏好无法沉淀、经验无从学习、多轮之间偶尔自相矛盾。

```python
agent = SimpleAgent(name="学习助手", llm=HelloAgentsLLM())
agent.run("我叫张三，正在学习Python，目前掌握了基础语法")

# 重启程序后重建实例
agent = SimpleAgent(name="学习助手", llm=HelloAgentsLLM())
agent.run("你还记得我的学习进度吗？")      # 答不上来
```

**约束二：知识是静态的。** 训练数据有时间截止点，专业领域的深度不足，幻觉无法根除，答案也缺少可追溯的来源。RAG 针对的正是这一组问题：生成之前先从外部知识库取回相关片段，作为上下文一起给模型。

两者常被混为一谈，其实分工清楚：记忆解决「发生过什么」，跨会话、可演化；RAG 解决「文档里写了什么」，只读、可替换。下一篇讲 RAG，这一篇先把记忆落地。

## 2. 认知科学的参照

人类记忆并非一块平板，而是分层的：感觉记忆只保留零点几秒到几秒，容量巨大；工作记忆维持十几到几十秒，容量只有 7±2 个项目；长期记忆几乎无限，又分为程序性（骑车这类技能）与陈述性，后者再分为语义记忆（「巴黎是法国首都」这类概念）与情景记忆（「昨天开会说了什么」这类经历）。

<img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/helloagents-human-memory.png" width="85%" alt="人类记忆系统的层次结构" />

这张图对工程的价值不在于复刻生物学，而在于指出三条约束：**容量必须分层**（不可能所有信息都进上下文）、**生命周期必须区分**（临时信息要自动过期，重要信息要长期留存）、**检索必须多路**（按语义找概念、按时间找事件，是两种不同的查询）。

## 3. 记忆的生命周期

把认知阶段映射到技术动作，就得到记忆系统的五个环节：编码（把感知转成可存储形式，对应嵌入与结构化）、存储（落到存储后端）、检索（按需取回）、整合（短期转长期）、遗忘（清掉不重要或过时的）。

<img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/helloagents-memory-workflow.png" width="95%" alt="记忆系统的完整工作流程" />

这五环节决定了整套架构的分层方式：最上面是 `MemoryTool`（对智能体的唯一入口），中间是 `MemoryManager`（按类型调度），再往下是四种记忆类型，最底层是存储后端与嵌入服务。分层的好处是每层只回答一个问题——工具答「怎么调用」，管理器答「交给谁」，记忆类型答「怎么打分」，存储层答「存在哪」。

## 4. 四种记忆类型

| 类型 | 存什么 | 生命周期 | 存储方案 |
| --- | --- | --- | --- |
| 工作记忆 | 当前会话的临时上下文 | 会话级，TTL 自动清 | 纯内存 |
| 情景记忆 | 具体事件、交互经历 | 长期，可按时间/主题回顾 | SQLite + Qdrant |
| 语义记忆 | 抽象知识、偏好、规则 | 长期 | Neo4j + Qdrant |
| 感知记忆 | 图像、音频等多模态 | 按重要性与容量动态管理 | 按模态分集合 |

**工作记忆**是短期记忆，默认容量 50 条、TTL 60 分钟，纯内存换取速度。检索用组合词法策略：TF-IDF 稀疏向量相似度占 0.7、关键词匹配占 0.3，再乘时间衰减与重要性权重。

```python
base_relevance = vector_score * 0.7 + keyword_score * 0.3 if vector_score > 0 else keyword_score
final_score = base_relevance * self._calculate_time_decay(memory.timestamp) \
              * (0.8 + memory.importance * 0.4)      # 重要性权重落在 [0.8, 1.2]
```

这里要留一个清醒的判断：TF-IDF 是词法相似度，不是稠密嵌入的语义检索。同一件事换个说法就匹配不上，这是工作记忆「够快但不够懂」的代价，也解释了为什么长期记忆必须换向量库。

**情景记忆**存事件，重点是完整性与时间序列。SQLite 存结构化字段（会话、时间、上下文），Qdrant 存向量，检索时先按时间范围、重要性做结构化预过滤，再做向量召回，最后综合打分：

```python
base_relevance = vec_score * 0.8 + recency_score * 0.2       # 语义为主，时效为辅
score = base_relevance * (0.8 + importance * 0.4)
```

**语义记忆**最复杂，存的是知识而非事件。写入时不只是存向量：先用 NLP 抽实体与关系，写进 Neo4j 图库，再把向量写进 Qdrant；读取时向量检索与图检索并行，合并后加权。

```python
base_relevance = vector_score * 0.7 + graph_score * 0.3      # 关系推理作补充
combined_score = base_relevance * (0.8 + importance * 0.4)
```

向量占七成、图占三成的比例是有讲究的：语义相似是主路径，图谱负责补上「A 认识 B、B 参与 C」这类隐含关联。若把图检索权重调高，容易召回一堆关系上相邻、语义上无关的内容。

**感知记忆**处理多模态，做法是**按模态分集合**——文本、图像、音频各建一个向量集合，维度各自独立。这样避免了不同编码器维数不一致的麻烦，代价是跨模态检索需要额外的语义对齐。时间近因性用指数衰减：

```python
decay_factor = 0.1
recency_score = math.exp(-decay_factor * age_hours / 24)
return max(0.1, recency_score)      # 保留 0.1 底分，避免旧记忆被彻底清零
```

底分这行容易被忽略但不能省：没有下限时，超过两三天的记忆得分趋近于零，等于系统只会看最近的内容。

## 5. 统一入口：MemoryTool

按第七章「万物皆为工具」的原则，记忆不是新的 Agent 类，而是一个工具。`MemoryTool` 用单一 `execute(action, **kwargs)` 分发给九种操作：

```python
def execute(self, action: str, **kwargs) -> str:
    if action == "add":         return self._add_memory(**kwargs)
    elif action == "search":    return self._search_memory(**kwargs)
    elif action == "summary":   return self._get_summary(**kwargs)
    elif action == "stats":     return self._get_stats(**kwargs)
    elif action == "update":    return self._update_memory(**kwargs)
    elif action == "remove":    return self._remove_memory(**kwargs)
    elif action == "forget":    return self._forget(**kwargs)
    elif action == "consolidate": return self._consolidate(**kwargs)
    elif action == "clear_all": return self._clear_all(**kwargs)
```

用一个入口而不是九个方法，是为了适配函数调用协议：模型只需要记住「有个 memory 工具，参数是 action 加内容」，不必理解九个函数签名的差异。`**kwargs` 让每种操作保留自己的参数，代价是类型提示失效——所以描述字段要把可用 action 列全，否则模型会自己编一个不存在的操作。

`add` 除了内容，还会补齐三样上下文：会话 ID（缺失时按时间戳生成）、时间戳、以及 0.0–1.0 的重要性。感知记忆还会按文件路径推断模态：

```python
metadata.update({"session_id": self.current_session_id,
                 "timestamp": datetime.now().isoformat()})
memory_id = self.memory_manager.add_memory(
    content=content, memory_type=memory_type,
    importance=importance, metadata=metadata, auto_classify=False)
```

`search` 则把结果格式化成模型可读的清单，而不是返回对象：

```python
for i, memory in enumerate(results, 1):
    label = {"working": "工作记忆", "episodic": "情景记忆",
             "semantic": "语义记忆", "perceptual": "感知记忆"}.get(memory.memory_type)
    preview = memory.content[:80] + "..." if len(memory.content) > 80 else memory.content
    lines.append(f"{i}. [{label}] {preview} (重要性: {memory.importance:.2f})")
```

截断到 80 字、带类型标签、带重要性，三个处理都是为同一个目的：这些文本会直接进上下文，占的是 Token 预算。`min_importance` 默认 0.1 也起同样作用——低质量记忆不该挤进上下文。

## 6. 遗忘与整合

只会写不会删的记忆系统，最终会变成一堆互相干扰的噪声。遗忘提供三种策略：

```python
memory_tool.execute("forget", strategy="importance_based", threshold=0.2)   # 按重要性
memory_tool.execute("forget", strategy="time_based", max_age_days=30)       # 按时间
memory_tool.execute("forget", strategy="capacity_based", threshold=0.3)     # 按容量
```

三种策略对应三种不同的失效原因：重要性低的是噪声，时间久的是过期，容量超限则是被迫取舍。生产上通常组合使用——定期清过期、超限时按重要性淘汰。

整合（consolidate）做的是反方向的事：把重要的工作记忆提升为长期记忆，模拟记忆固化。

```python
memory_tool.execute("consolidate", from_type="working", to_type="episodic",
                    importance_threshold=0.7)
memory_tool.execute("consolidate", from_type="episodic", to_type="semantic",
                    importance_threshold=0.8)
```

阈值 0.7 与 0.8 的递进关系值得留意：工作记忆→情景记忆是「这件事值得记」，情景记忆→语义记忆是「这件事里提炼出了知识」，后者要求更高。这套机制也回答了记忆系统最难的工程问题——**没有人会手动分类**，系统必须自己判断什么值得留下。

## 7. 分层与取舍

`MemoryManager` 只做调度，按开关实例化各类型模块：

```python
self.memory_types = {}
if enable_working:    self.memory_types["working"] = WorkingMemory(self.config)
if enable_episodic:   self.memory_types["episodic"] = EpisodicMemory(self.config)
if enable_semantic:   self.memory_types["semantic"] = SemanticMemory(self.config)
if enable_perceptual: self.memory_types["perceptual"] = PerceptualMemory(self.config)
```

默认只开前三种，感知记忆要显式打开——它需要 CLIP、CLAP 这类额外编码器，成本与依赖都不是默认该背的。

选择记忆类型时可以按一个简单标准：**问的是「刚才说了什么」用工作记忆，问的是「上次发生了什么」用情景记忆，问的是「关于这个人/这个领域我知道什么」用语义记忆**。三者叠加不是叠加成本，而是叠加召回路径——同一句话可能同时命中工作记忆里的原文与语义记忆里的概括，评分机制负责把更相关的顶上来。

记忆解决的是「发生过什么」，接下来要解决「文档里写了什么」：切片、嵌入、召回、重排，以及把二者拼成一个能问答的助手——[8-2-RAG与文档问答](/source/agent/从零构建智能体/8-2-RAG与文档问答)。
