# 大语言模型基础

智能体的一切决策最终都落在一次模型调用上，所以「模型为什么能推理、在什么条件下会出错、多少钱一次」不是背景知识，而是设计约束。Transformer 的数学细节在[NLP 与 Transformer 理论](/source/大模型/理论篇/README)里更完整，这里只保留对搭智能体有直接影响的部分。

## 1. 语言模型的本质：给词序列打分

语言模型的任务是计算一个词序列出现的概率，用链式法则展开：

\[P(S)=P(w_1)\cdot P(w_2\mid w_1)\cdots P(w_m\mid w_1,\dots,w_{m-1})\]

后半段的条件概率几乎估不出来，于是有了**马尔可夫假设**：只看前面有限的 \(n-1\) 个词，这就是 **N-gram**。概率用最大似然估计，说白了就是数数——`P(agent|datawhale) = Count(datawhale agent) / Count(datawhale)`。

N-gram 有两个死结：**数据稀疏**（没见过的组合概率为 0，平滑只能缓解）和**不会泛化**（见过 `agent learns` 也推不出 `robot learns`，因为词是离散符号）。

解法是**词嵌入**：把词映射到连续向量空间，语义相近则距离相近。2003 年的前馈神经网络语言模型用「前 n-1 个词的向量 → 下一个词的概率分布」来训练，词向量作为副产物学出来。经典验证是 `king - man + woman ≈ queen`——性别、皇室这类抽象关系变成了向量方向。

再往后是 **RNN/LSTM**：用隐藏状态携带「记忆」，打破固定窗口。代价是必须按时间步串行计算，长序列上还有梯度消失，LSTM 的门控只是缓解。

## 2. Transformer：把串行换成交互

2017 年的 Transformer 直接丢掉循环，只靠**注意力**建模依赖，于是整个序列可以并行计算。

<img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/1757249275674-3.png" width="50%" alt="Transformer 整体架构" />

原始结构是为翻译设计的编码器—解码器：编码器负责「理解」，为每个词元产出带上下文的表示；解码器负责「生成」，参考已生成的前文并查询编码器的结果。

**自注意力**是核心。每个词元投影出三组向量：

- **Query**：我在查询什么。
- **Key**：我能被怎样检索。
- **Value**：我携带的内容。

计算就是一次加权检索：

\[\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{T}}{\sqrt{d_k}}\right)V\]

除以 \(\sqrt{d_k}\) 是为了防止点积过大把 softmax 推到梯度极小的区域。**多头**则是把 Q、K、V 在维度上切成 h 份分别算，再拼接做线性变换——让不同的头学不同的关系（指代、时态、从属）。

注意力之后是**逐位置前馈网络**：两个线性层夹一个 ReLU，中间维度放大到 4 倍再压回，负责从聚合后的信息里提更高阶特征。每个子层外面套 **Add & Norm**：残差连接让梯度绕过子层，层归一化稳住每层输入分布。由于自注意力本身不含顺序信息，还要加上**位置编码**（正弦/余弦固定函数），否则 `agent learns` 与 `learns agent` 对模型完全等价。

**Decoder-Only** 是今天的实际形态。GPT 的判断很直接：语言的核心任务就是预测下一个最可能的词。于是丢掉编码器，只留解码器，按**自回归**方式生成：给起始文本 → 预测下一个词 → 拼回输入 → 再预测，如此循环。

训练时为了避免「偷看答案」，在注意力分数过 softmax 之前应用**因果掩码**，把当前位置之后的分数置为负无穷，softmax 后概率为 0。这样训练时的并行计算与推理时的逐词生成在信息可见性上保持一致。

这个结构的好处是目标统一（只学下一词预测）、组件少易扩展、天然适配生成任务，GPT-4、Llama 都是这条路。

## 3. 与模型交互：采样与提示

**采样参数**决定「同一个问题能答成什么样」。它们在 softmax 概率分布上做二次加工：

| 参数 | 作用 | 典型用法 |
| --- | --- | --- |
| Temperature | 改写分布陡峭度：低则保守，高则发散 | 事实问答/代码 0～0.3，对话 0.3～0.7，创意 ≥0.7 |
| Top-k | 只保留概率前 k 个候选再归一化 | 固定截断，k=1 退化为贪心 |
| Top-p | 从高到低累加，取累积概率达 p 的最小集合 | 动态适配长尾分布 |

三者同时设置时按「温度 → Top-k → Top-p」分层过滤；实际候选集是 Top-k 与 Top-p 的交集，通常二选一即可。温度设为 0 时另外两个参数失去意义。

**示例数量**决定模型对任务的把握：零样本靠泛化直接下指令，单样本给一个完整示范，少样本给多个覆盖不同边界的例子——格式复杂或风格要求高的任务，少样本最稳。

**指令调优**改变的是交互方式。GPT-3 时代是文本补全模型，得用示例「教会」它做什么；经过「指令—回答」数据微调后，今天的模型可以直接听懂自然语言指令。这也是为什么提示词从「续写模板」变成了「任务描述」。

基础技巧三项足够日常使用：**角色扮演**收窄语气与知识面；**上下文示例**锁定输出格式（比如固定 JSON schema）；**思维链**用一句「逐步思考」把多步推理显式化，既能提准确率，也让中间过程可检查——这一条在智能体里几乎是默认配置。

## 4. 分词：很多「怪问题」的根源

模型只认数字，**分词器**负责把文本切成**词元（Token）**再映射为 ID。三种策略：

- **按词**：词表爆炸，且遇到未登录词（OOV）直接失效。
- **按字符**：词表极简没有 OOV，但单字符没语义，学习效率低。
- **子词**：常见词保持完整，罕见词拆成有意义的片段，兼顾词表规模与表达力。

**BPE** 是最主流的子词算法，三步循环：初始化为基本字符 → 统计相邻词元对频率 → 合并最高频的一对并加入词表，直到达到预设词表大小。用 `hug/pug/pun/bun` 这种迷你语料能看到 `u+g → ug` 的合并过程；对未见过的 `bug`，分词器会退而求其次切成 `b + ug`。WordPiece 把「最高频」换成「最能提升语料概率」，SentencePiece 则把空格也当普通字符，因此对中文这类不用空格分词的语言更自然。

对智能体开发者的三个实际影响：

- **上下文窗口按 Token 算**，不是按字数。同样一段话，中英文与不同分词器下 Token 数差异很大。
- **API 按 Token 计费**，成本预估取决于分词结果。
- **模型表现异常常源于分词**：`2 + 2` 与 `2+2` 可能被切成不同词元，一个算得对一个算错；大小写差异也可能导致完全不同的切分。

## 5. 模型选型：不是越大越好

选型是性能、成本、速度、部署之间的权衡，常用八个维度：能力（可参考公开竞技场排名）、成本（闭源按 Token、开源折算硬件与运维）、延迟（客服与游戏 NPC 敏感）、上下文窗口（长文档与长记忆必需）、部署方式（API 简单但数据出域，本地部署可控但门槛高）、生态与工具链（LangChain、LlamaIndex 的兼容度）、可微调性、安全与合规。

实践中的顺序通常是：先用较强闭源模型把流程跑通，量化出每步的 Token 消耗与延迟，再判断哪些环节可以换小模型或本地模型。一开始就为了省钱选小模型，往往把时间花在调提示词上。

## 6. 缩放法则与幻觉

**缩放法则**：在对数—对数坐标下，损失与参数量、数据量、计算量都呈平滑的幂律关系。2022 年的 **Chinchilla 定律**修正了「只堆参数」的做法——给定算力预算，参数量与数据量存在最优配比，一个 700 亿参数但用 4 倍数据训练的模型可以超过 1750 亿参数的 GPT-3。这也是后来 Llama 系列的设计依据。

规模跨过阈值还会**涌现**新能力：思维链、指令遵循、多步推理、代码生成，都是到数百亿参数以上才显著出现。对智能体来说，这意味着模型规模决定了复杂规划能力的上限。

**幻觉**是另一半现实。表现上分三类：事实性（与现实不符）、忠实性（摘要翻译没忠实于原文）、内在（与输入直接矛盾）。成因是多重的：训练数据本身有错，自回归机制只预测下一词而没有事实核查模块，复杂推理时链条中某一步出错后继续编。

缓解手段也分三层：

- **数据层**：清洗语料、引入事实性知识、用 RLHF 对齐。
- **模型层**：让模型能表达不确定性（新架构探索）。
- **推理层**：RAG 在生成前检索外部知识、多步推理加自我检查、外部工具（搜索、计算器、代码执行）补精度。

第三层是智能体最常用的抓手：既然幻觉无法根除，就把「需要事实的部分」交给工具和检索，让模型只负责组织与判断。RAG 的具体链路见[8-2-RAG与文档问答](/source/agent/从零构建智能体/8-2-RAG与文档问答)。
