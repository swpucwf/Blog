# 观察与动作空间：模态与时机

## 1. 两个扩展方向

前五章默认了一个前提：**Agent 与世界的交互是轮流的**。用户说完一句，Agent 想一想、调用几个工具，再回一句；在它思考的这段时间里，世界被默认为静止的。

这个前提很少被当成假设写出来，但它并不成立。真实环境不会等模型作出反应：邮件在它思考时到达，用户在它说到一半时插话，页面在两次截图之间已经变了样。

把观察空间与动作空间摊开，各有两个扩展方向：

- **模态**决定观察与动作的形式：只读文本，还是也能听见声音、看见屏幕、感知力矩；只能输出 token，还是也能发声、点击、驱动关节。
- **触发时机**决定节奏：观察是 Agent 主动去取，还是世界主动推来；动作必须在一个回合内做完，还是可以跨回合、中途被打断、被更紧急的事抢占。

| | 观察空间 | 动作空间 |
|---|---|---|
| **内容**（前五章） | 上下文工程、记忆与知识库 | 工具、代码生成 |
| **模态** | 语音、屏幕、物理传感器 | 说话、点击、关节运动 |
| **时机** | 世界主动推送、连续流 | 跨回合、可打断、可抢占 |

**回合制是模型与接口的一种交互约定，不是环境的性质。**

不同场景的时间尺度差异很大：

| 尺度 | 场景 | 观察侧变化 | 动作侧变化 |
|---|---|---|---|
| 秒—天 | 异步与事件驱动 | 被外部事件唤醒 | 先发起，后续靠事件收尾 |
| 10ms—1s | 语音 | 边说边听 | 边想边说，可被打断 |
| 亚秒—秒 | Computer Use | 屏幕在两帧之间持续变化 | 动作后必须重新确认现实 |
| 毫秒 | 机器人 | 传感器连续回流 | 动作分块，可被抢占 |

## 2. 为什么需要异步

同步意味着「做完一件事才能做下一件」，异步意味着「多件事可以同时进行」。

传统同步 Agent 像一个只会排队的柜台，每次只处理一个顾客；真正智能的助手更像一个灵活的秘书，桌上摆着多个待办事项，根据紧急程度决定先处理哪个，处理到一半有更紧急的事也可以暂停切换。

同步模式下，Agent 要么等后台任务完成才能与用户对话，要么等对话结束才能处理新事件，无法应对真实助理场景：

- **异步执行是常态**：许多任务长时间运行，不应阻塞用户交互；
- **事件优先级要动态判断**：紧急事件取消当前操作，常规事件加入队列，独立轻量查询并行处理；
- **中断与恢复要流畅**：被打断的对话或任务应能自然恢复。

把异步范式用于 LLM，先要检查模型与 API 是否支持这种消息时序：

- 有的接口要求先补齐工具结果才能继续——需要事件队列、任务句柄与兼容层；
- 有的已经允许工具挂起、模型继续工作，并在生成中接受用户更新——可以直接使用原生异步协议。

两者都仍需要应用管理事件来源、工具生命周期与结果归属。**不能仅凭代码用了 `asyncio`，就认定模型具备原生异步能力。**

技术上，事件驱动架构不再反复轮询「有没有新消息」，而是在新消息到达时自动触发处理逻辑。所有输入、输出、思考过程与外部交互都被统一建模为**事件流**——一条时间线上依次排列的事件记录。

## 3. 从回合制到持续感知

这一章的四节共享同一条控制骨架：

```text
持续感知
  → 判断当前状态与时机
  → 选择回复或动作
  → 让输出进入环境
  → 观察反馈
  → 继续、修正、重试、停止或重新规划
```

也共享同一组原语：**唤醒、安全点、取消、抢占、快慢分离**。

它们在不同时间尺度上的实现不同：

- 事件驱动：唤醒由外部事件触发，安全点是每轮循环边界；
- 语音：安全点是「一句话说完」或「被打断」的时刻；
- Computer Use：动作后必须重新截图确认；
- 机器人：动作分块，控制层高频执行，模型低频规划。

## 4. 补记

「扩展观察与动作空间」有两种完全不同的含义：加更多工具/知识，是扩展**内容**；让 Agent 能听、能看、能动手、能被事件唤醒，是扩展**模态与时机**。前五章做的是前者，这一章做的是后者。

时机扩展往往比模态扩展更便宜，也更常被忽略。很多「Agent 不够主动」的问题，不是模型不会规划，而是架构只在用户发消息时才运行；加一个事件通道或定时器，行为就会明显不同。
