# 语音交互：从级联到全双工

## 1. 语音不只是声音

语音的价值不只是把文字换成声音。正常说话速度约为打字四倍，而且不占用双手与视线，天然适合把 Agent 放进持续工作、随时可能被打断的输入输出回路。

语音输入法把口述转成文字；语音 Agent 则让用户直接与 Agent 协作。两者都能支持「口述式协作」。

这里同时讨论两个方向：**用户对 Agent 说话**，以及 **Agent 代表用户对外部世界说话**。语音模型决定「能回答什么」，交互架构决定「能否听清、及时回应、自然换手，并在通话中完成确认和工具调用」。

## 2. 三种交互范式

OpenAI 用「级联、轮次式、全双工」概括语音系统的三代演进。它们不是简单的新旧替代，而是不同延迟、成本与可观测性约束下的取舍：

| 范式 | 核心结构 | 优势 | 限制 |
|---|---|---|---|
| 级联 | VAD → ASR → LLM → TTS | 模块清晰、易替换、易调试 | 延迟累积，副语言信息在接口处丢失 |
| 端到端 Omni | 原生音频输入输出，按轮次 | 延迟较低，保留语气、情绪、环境声 | 仍依赖轮次，训练调试成本高 |
| 全双工 | 原生音频输入输出，持续听、说、决策 | 支持重叠说话、自然打断、连续流 | 训练、控制、评估都更复杂 |

主线是：如何摆脱「轮流说话」与 VAD 对发言权的猜测。级联与 Omni 仍要划分轮次，只有全双工把「该谁说话」变成模型的持续决策。

## 3. 级联：模块化但延迟累积

绝大多数商业语音助手基于串行流水线：VAD 判断用户何时说完，ASR 把音频转文字，LLM 理解并生成回复，TTS 把文字念出来。

| 模块 | 作用 | 典型瓶颈 |
|---|---|---|
| VAD | 判断是否说完 | 静音阈值带来等待与误切分 |
| ASR | 音频转文字 | 识别延迟与上下文丢失 |
| LLM | 理解、思考、生成 | 首 token 延迟，开启 reasoning 后更久 |
| TTS | 文字转语音 | 首包合成与播放缓冲 |

简短、不开启 reasoning 的回复中，四段等待会串行累积。

### 3.1 从串行到流式感知

完全串行有三个问题：

1. **延迟累积**：必须等一段静音才能确认说完；
2. **信息丢失**：有声/无声二值信号无法表达犹豫、情绪、附和与环境声；
3. **上下文被切断**：邮箱、人名、专有名词可能被分片识别而出错。

优化方向是**流式感知**，在保留模块化分工的前提下让各阶段尽早产出增量：

- **ASR 边听边转**：VAD 检测到开始说话，就按间隔调用 ASR 生成临时转录；检测到结束后确认最终文本。
- **LLM 推测执行**：临时转录一生成就送给 LLM；最终文本相同则不重复调用，否则取消前序推测、重新调用。
- **LLM 分段输出**：第一段适合播报的文本生成后立即交给 TTS，不等完整回复。
- **TTS 增量合成**：持续返回音频块，让生成、合成、播放重叠。

真正的流式 ASR 需要模型支持。Whisper 解码虽是自回归的，但编码器需要完整音频段，不能直接等同于流式模型。基于 LLM 的流式听觉模型可以从连续音频中输出文本与语义事件，把「识别」与部分「理解」放进同一个模型。

如果只想解决「用户是否说完」，也可以把轮次判断做进流式识别器：综合语义与静音判断一句话是否表达完整。端点判断的训练标签必须只使用决策时刻可见的信息，否则会因「上帝视角」产生线上无法复现的判断。

模型输出的不仅是文字，还可以包含声学事件标记：

- `speak_start/end`、`interrupt`：说话起止与打断意图；
- `emotion`：情感、犹豫；
- `laugh`、`sigh`、`noise`：副语言与环境声。

这些标记与文字 token 形成统一事件流，Agent 可以识别犹豫、打断与环境变化，而不必把所有声音压成纯文本。

## 4. Omni：端到端全模态

级联即使采用流式感知，听、想、说仍通过离散接口交接；情绪、语调、环境声可能在转成纯文本时丢失。

Omni 用同一个模型直接听音频、生成回复并输出语音，有机会保留这些信息，但训练成本更高。

理解方面，Omni 可以理解声音中的停顿与语气；生成方面，可以传递更丰富的副语言信息——唱歌、用特殊语调说一句话。

Omni 仍假设轮流说话，通常靠 VAD 划分发言权。用户报数字时的中途停顿，仍可能被误判为说完。

## 5. 全双工：持续听、持续说

Omni 仍把对话分成「用户说」与「模型说」两个时段，但同声传译等任务要求两者重叠。

全双工模型不再预设轮次，而是持续听、持续说，并不断决定继续、停顿、打断或调用工具。研究上的先声是 Moshi（2024），并行建模用户与模型的音频流，使重叠说话与打断成为自然行为。

Thinking Machines Lab 把这类路线称为**交互模型**：交互性不再靠 VAD 等外部 harness 拼装，而是内建在模型里。微轮次机制以短音频块持续推进，让静音、重叠、打断都作为连续上下文保留。交互模型还可以把完整对话委派给后台推理模型，自己继续维持话头；后台结果返回后，前台在合适时机接入。

GPT-Live 把这条路线带到生产规模：持续处理输入并生成输出，能等待用户、附和、被打断，也能处理实时翻译；复杂任务委派给后台模型，前台继续对话。

## 6. 认知时序：实时交互与深度思考

「交互表现」与「智能上限」是两个维度：前台模型要在用户仍在线时回应，后台模型可以花更多时间思考。三种方案是设计取舍，不是线性迭代。

### 6.1 快思考回应，慢思考回答

快思考在几百毫秒内先给出即时回应，慢思考在后台完成更深推导。

问题是简单问题被重复处理，复杂问题可能出现前后不一致：快模型先建议购买，慢模型随后发现套餐缺少关键功能，用户在几秒内听到相互冲突的答案。根本原因是两个实例各自完成了一次独立思考。

### 6.2 快思考交互，慢思考提醒

后台模型通过状态栏或专门接口向前台提供建议，前台维持话头并决定如何表达。

它比方案一稳定，但通信仍然间接：前台可能误解建议，也看不到后台的中间思考；后台完成前用户追问时，前台仍只能靠自己的能力应答。它可以自然地「等结果」，但不能真正做到边想边说。

### 6.3 端到端思考与表达统一

方案三把思考能力内化到端到端音频模型。Step-Audio R1 用两个互补机制：

- **模态锚定思考蒸馏（MGRD）**：让模型基于声学特征思考，筛选真正引用声学特征的思考过程训练模型，并用强化学习防止跳过思考直接猜答案；
- **MPS 双脑架构**：构思脑持续产出思考片段，表达脑收到后结合已有回复立即生成语音。两者流水线并行，不必等完整思考结束才让用户听到第一句。

### 6.4 取舍

统一模型最紧密地实现「边想边说」，代价是思考与实时表达要一起重新训练；解耦路线更容易替换后台大脑。

在前沿思考模型快速演进时，快慢分离有重要工程优势：前台快模型只负责低延迟倾听、应答、维持对话，后台慢模型负责推理、规划、工具调用；更强的思考模型发布后，只需替换后台，不必重训整套实时语音系统。

这不必然牺牲效果。采用快慢分离架构的语音 Agent 已在同时考察深度推理与实时对话的基准上取得领先，说明解耦并不天然落后于端到端。

要区分「端到端」的两个含义：

- **语音通路端到端**：模型直接接收音频、生成音频，不再由多个模型通过文本串接；Omni 与交互模型都属于这一类。
- **认知架构端到端**：实时交互与深度思考在同一模型内共享状态、共同训练，还是拆成前台快模型与后台慢模型。

两条轴彼此独立。一个系统完全可以在语音通路上端到端，同时在认知架构上保持快慢分离。

## 7. 更像人的语音合成

传统 TTS 过于流畅、零停顿，反而容易暴露机器身份。停顿、填充词与偶尔重复，是人类表达不确定性与思考状态的信号。

可以让主 LLM 在文本之外输出控制标记，如 `THINKING`、`EMO:happy`、`SPEED:0.8x`，由 TTS 映射为停顿、韵律、语速或笑声、叹气等非语言音频。实现上可以自研支持控制标记的 TTS，也可以用语音克隆准备不同情绪与风格的参考音频。

## 8. 补记

语音系统的关键不是「模型能不能听懂」，而是**交互时序**：谁在什么时候说话、被打断后如何恢复、后台思考结果何时接入。级联、Omni、全双工是三种时序架构，快慢分离是第四层认知分工。

一个实用判断：先看延迟预算与可观测性要求。需要拆开调试、替换模块，级联更合适；追求自然打断与低延迟，才考虑全双工；需要深度推理又不牺牲实时感，快慢分离通常比强行统一更务实。
