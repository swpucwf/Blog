# Mid-training 与 SFT

## 1. Mid-training：补知识与基础能力

Mid-training 从已有基础模型出发，在目标数据分布上继续做语言模型训练。它通常仍采用预测下一个词，对文档、代码或推导的**全部 token** 计算损失。

它主要解决两类缺口：

- **知识缺口**：通用预训练没有充分覆盖目标语言、金融/医疗/法律领域、企业内部文档或某类代码库，模型连概念与术语都不理解；
- **基础能力缺口**：任务要求模型尚未形成的长上下文、代码模式、数学推导或跨模态表征。此时不只是格式不对，而是足够多次采样下也几乎得不到正确解。

这也说明为什么不应把 SFT 当主要知识注入工具。SFT 可以记住少量事实，也常放在 Mid-training 后教模型如何回答领域问题；但少量 QA 只覆盖有限问法，更擅长训练「如何访问与表达」，不适合承载大规模、相互关联的原始知识。

反过来，Mid-training 降低了领域文本的语言模型损失，也不保证模型会自动按用户问题取出知识。稳健配方通常是：**Mid-training 吸收知识与能力 → 小规模 SFT 建立输出格式 → 有非零成功率后再 RL。**

### 1.1 数据怎么构造

1. **从失败分布反推数据**：按主题、语言、文档类型、代码模式与上下文长度切分评估，确认低 pass@k 来自哪类底座缺口；只针对缺口补数据，避免把格式错误误诊成知识不足。
2. **构造高密度目标语料**：原始文档建立术语与事实关联，代码仓库学习结构与依赖，教材式推导、合成释义与跨文档关联样本把隐含关系写得更明确。去重、质量过滤、评估集污染检查。
3. **按能力配比**：自然长文本（书籍、长文档、代码仓库）；长文本原子能力（检索、多跳推理、指令遵循、聚合统计）的思维链数据；Agent 必需能力（规划、工具选择与调用、长程状态跟踪、错误恢复）的执行轨迹。思维链与 Agent 轨迹可从较强开源模型蒸馏，或使用现有数据集。
4. **每个阶段做双重回放**：原始短文本与通用数据，保留语言、知识与短上下文能力；「长度提升后的旧任务」，把模型已会的短任务放进当前长度上下文，在不同位置加入相关信息与干扰项，检验同一能力在长窗口中是否仍成立。通用数据最好来自基模原始预训练集；拿不到时可用 FineWeb-2 等开源语料。
5. **用多维门禁决定何时停**：除 loss 外，同时跟踪留出领域任务、通用能力、原有指令遵循与目标任务 pass@1/pass@k。领域指标升、通用保留集降，说明混合或学习率过激；loss 降而 pass@k 不动，要检查数据是否覆盖所需能力，以及后续是否缺少访问知识的 SFT。

### 1.2 长上下文能力要单独验收

Mid-training 后要用 LongBench v2、IFEval、端到端 Agent 评估，验证模型在不同上下文长度下的基础能力没有丢失：

- **位置与检索**：单针、多针、不同位置的关键信息提取；
- **关系与推理**：跨段落、多文档、多跳关系追踪，矛盾消解与证据组合；
- **聚合与统计**：长表格/日志中的计数、分组、排序、比较、趋势；
- **指令遵循**：多指令、矛盾消解、流程与输出格式；
- **长链思考**：复杂数学、逻辑、代码；
- **Agent 原子能力**：任务分解、计划、工具选择、参数构造、状态记忆、失败恢复。

事实需要频繁更新或必须给出原始出处，RAG 仍优于把知识写进权重；Mid-training 更适合稳定、规模较大、需要形成内部表征的领域知识与能力。全参 Mid-training 的计算与遗忘风险明显高于小规模 SFT，要先用小实验验证配比，再扩大预算。

一个继续预训练实验以主要用英语预训练的 7B 模型为基础，用约 80% 韩语 + 20% 英语的维基数据注入韩语能力，再用韩语指令数据 SFT。结果韩语盲评改善，英语能力下降——继续预训练能写进目标分布，但不能免除保留集、事实评估与数据质量审计。

## 2. SFT：固化协议

SFT 的核心价值不在注入新知识，而在**固化输出格式**：把映射关系、交互格式、风格规范写入参数，使推理时无需冗长提示就能产出符合预期的输出。

这种高效率可能以依赖训练分布为代价：需要探索多种正确策略、或部署分布偏离示范时，SFT 容易偏向复现示范模式。

### 2.1 SFT 数据从哪来

工业界基本三条路：

- **人工专家示范**：质量天花板最高，但贵且慢，适合定义格式与风格的「种子数据」；
- **教师模型生成**：让强模型批量产出输入—输出对，过滤后再蒸馏给学生；
- **拒绝采样**：模型对同一问题采样多条候选，用验证器筛出正确样本再训练自己。

三条路常组合。构造流程大同小异：定义任务分布与输出 schema → 批量生成候选 → 规则校验、格式检查、人工抽检 → 去重、平衡配比、保证多样性。

数据不必贪多，数千到数万条高质量样本通常足以固化格式。**与其堆十万条脏数据，不如精修一万条干净数据**：数据里的每一处噪声，SFT 都可能忠实写进参数。

### 2.2 四种典型实验

**语音 SFT**：一种路线把声音波形压缩为 token，通过拼接同一说话者参考音频，让模型学会「用这个人的声音说话」；另一种把笑声、叹气抽象为 `<laugh>`、`<sigh>` 等标记，训练模型「看到标记就发出对应声音」。

SFT 在表达型任务中固化的是风格控制协议与结构化表达习惯，而非事实知识。常见失败：训练数据说话者过少，所有人一个腔调；标记过拟合，产生机械笑。

**多语言思考**：多数思考模型只会用英语思考，因为高质量思考示范基本是英语。对模型做 SFT，在系统指令加 `reasoning language: German`，用英语、西班牙语、法语等思考样例训练；训练数据完全没有中文，但训练后把语言设为 Chinese，模型能用中文完整思考。

这种零样本跨语言泛化不是 SFT 本身的能力——多语言预训练已建立共享表征空间，SFT 只是激活了预训练已有的能力。

**Prompt 蒸馏**：复杂任务常需要数千甚至上万 token 的系统提示，每次调用增加延迟与费用；思考型模型的内部 token 进一步放大成本。思路是把「长提示 + 思考型教师」压缩到「短提示/无提示 + 非思考学生」：教师在完整提示与思考模式下生成高质量答案，训练数据只保留用户输入与最终结论，丢弃提示与中间思考。

两个维度：「大到小」（中小模型替代大模型）与「思考到非思考」（把显式 CoT 折叠为隐式参数化知识，获得 20–30 倍响应速度）。二者常同时使用。

代价是继承教师边界：教师在长尾有系统性错误，学生会硬编码；教师依赖工具保证正确性，纯输出蒸馏会失去工具鲁棒性。产品形态稳定、输入可预期、成本约束明显时，Prompt 蒸馏是好优化；探索期或任务未定型时，保留显式思考与可编辑提示仍是快速试错核心。

**CoT 蒸馏**：把强教师的完整思考轨迹转移给学生。对较强教师做 CoT 蒸馏，同等参数量下可恢复教师 70%–80% 的能力。对不追求刷新前沿、但寻求自主可控的团队，这是最务实的跟随者策略。

一些闭源思考模型会改写或摘要 CoT，最有价值的原始思考被藏在 API 之后——这是选择开源思考模型作教师的原因。但要先确认许可证对蒸馏产物的授权。

具体流程三步：

1. **采集轨迹**：从目标任务分布采样问题，用开源教师生成「思考 + 答案」，用规则验证器过滤掉最终答案错误的轨迹；
2. **SFT 训练**：以「问题 → ` thinking` 思考 `<｜end▁of▁thinking｜>` + 最终答案」为训练对，对小模型做标准 SFT；
3. **对比评估**：在同一基准对比学生、教师，衡量能力恢复比例。

「生成候选—验证过滤—只留正确轨迹」就是**拒绝采样**；用它构造数据做 SFT 即 RFT。它介于纯 SFT 与 RL 之间：不训奖励模型、不做策略梯度，只靠拒绝错误样本来提升数据质量，是可验证任务上性价比极高的手段。

学生也会继承教师的系统性错误与冗长思考习惯，后者可再做二次优化。

## 3. SFT 数据合成

SFT 的上限首先由数据决定。实际项目很少能人工逐条写足够示范，通常把**少量人工种子、教师生成、验证器筛选**组合：人工定义格式与边界，教师放大规模，规则验证或人工抽检守质量。

合成数据的目标不是复述线上日志，而是提炼可复用的**任务结构**：用户意图、初始状态、可用工具、业务约束、常见失败、成功条件。去除身份信息后，为每种任务重新生成虚构人物、订单、文件与状态，放进可重置的隔离环境。既保留真实难点，也避免记住客户数据或内部凭据。

稳妥流水线：**线上数据 → 任务蓝图 → 合成任务 → 多次候选轨迹 → 任务验证与轨迹验证 → SFT 数据。**

- 任务验证：题目是否可完成、难度是否合适、参考结果是否正确；
- 轨迹验证：最终状态、工具调用、业务约束。

能写成单元测试、数据库断言或状态差异的，优先用确定性代码；开放式沟通质量再由模型评价器补充，并人工抽样校准。

同一套任务与验证设施之后可以转成 RL 环境，但用法不同：SFT 只保留验证通过的成功轨迹，学习稳定格式、流程与基本动作；RL 让当前策略重新 rollout，利用奖励探索示范外路径。失败轨迹不应直接当正确示范，可以用来构造偏好对、发现覆盖缺口，或补上诊断与修复后再加入训练。

数据合成的关键不是数量，而是覆盖面、多样性与准确性。训练集按任务模板、客户或时间段去重；评估集必须来自不重叠的任务类型；参考解法、隐藏测试与验证器反馈不能泄露给模型。

## 4. 何时选 Mid-training、SFT 与 RL

先判断缺的是底座、协议，还是策略，不要把「模型做不好」统一归因成需要 RL：

| 现象 | 缺口 | 优先方法 | 进入下一阶段的门槛 |
|---|---|---|---|
| 领域概念/语言/基础操作不会，pass@k 近 0 | 知识与能力不在基模支持中 | Mid-training；动态事实用 RAG | 领域留出集改善，通用保留集可接受，开始出现可验证的正确或部分正确轨迹 |
| 偶尔做对，但格式、工具 schema、语气、流程不稳定 | 行为协议未固化 | SFT 或约束解码 | 解析成功率稳定，关键动作可被验证器可靠评分 |
| 有非零成功率与可靠奖励，但好策略概率低、OOD 泛化不足 | 概率分配与策略优化 | RL | 奖励与目标一致；组内有奖励差异；独立测试集随训练改善 |
| 只有少量稳定示范，尚无可交互环境 | 可模仿数据有、在线反馈无 | SFT/RFT/离线偏好优化 | 先建基线与评估，再判断是否值得建 RL 环境 |

实际决策顺序：

1. **先排除不改权重的方案**：Prompt、工具、代码约束、上下文管理能解决就不训练；事实频繁更新/引用/删除优先 RAG。
2. **测能力支持**：不只看贪心 pass@1，还要在固定采样配置看 pass@k、部分进展率、格式解析率，并人工审计失败原因。pass@k 近零且失败集中在知识/基础能力，先 Mid-training。
3. **用 SFT 立协议，不硬塞知识**：模型「会做但不会按要求做」时，用高质量示范固化 JSON schema、工具调用、术语、流程与风格。
4. **只在有探索空间时上 RL**：当前策略能产生可评分、偶尔成功的 rollout，奖励忠实反映目标时，RL 才能把低概率成功推高。pass@k 近零时先补底座或设计可达课程；全零 rollout 上加 PPO/GRPO 通常只消耗采样预算。

这不是要求每个项目跑完三种训练。强基模可能直接进入 RL，格式型任务可能只需 SFT，稳定领域知识可能只做 Mid-training 后复用原有对齐能力。关键是每一步都有可测的进入条件，而不是把三阶段当仪式化流水线。

## 5. 补记

Mid-training 与 SFT 的边界，常被「都是微调」掩盖：前者对大量原始 token 算损失，目标是形成可调用的内部表征；后者对少量示范的回答 token 算损失，目标是固化输出协议。

判断该用哪个，可以问：模型是「不知道」，还是「知道但不会按要求表达」。前者补底座，后者立协议；把知识硬塞进少量 QA，通常只会记住问法。
