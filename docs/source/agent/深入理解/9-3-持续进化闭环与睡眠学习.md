# 持续进化闭环与睡眠学习

## 1. 双循环

四种更新方式只有进入同一个自主循环，才会从单次优化变成持续进化。

![配图](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiagent_fig9-5.svg)

<p>图 1：在线执行与离线进化的双循环</p>

生产系统更稳妥的结构是：

- **在线执行循环**：只完成任务并记录证据，不直接改写正式 Agent；
- **离线进化循环**：聚合轨迹、诊断根因、生成更新提案，再通过验证门槛发布新版本。

两者通过**版本化的经验库与评估集**连接。

Voyager 展示了一个较完整的循环：在 Minecraft 中根据当前能力选择新目标，通过环境反馈迭代程序，验证成功后把代码存入技能库，再组合旧技能解决更难任务。

三个机制缺一不可：

- **自动课程生成器**：根据当前物品、环境与已掌握技能提出难度适中的目标，避免随机漫游；
- **技能库**：把成功程序保存为可检索、可组合的代码，高级技能可调用基础技能；
- **迭代提示**：把观察、执行错误、自验证结果带回下一轮代码生成，直到真正通过。

只有技能库没有课程，Agent 不知道下一步学什么；只有反思没有环境验证，技能库会积累错误；只有探索没有持久化，每次仍从头开始。

## 2. 发现循环

Voyager 这类系统遵循**假设 → 实验 → 评估 → 反馈**的发现循环，这也是数百年形成的科学方法。

Agent 自我进化要避免自说自话，就必须遵循科学方法：提出假设、实现实验、开展评估、取得结果，再把结果交给下一轮。

在持续进化中，要区分两种经常混在一起的能力：

- **Harness 更新能力**：从轨迹中产生有价值的持久修改；
- **Harness 受益能力**：任务 Agent 在后续运行中找到、激活并正确使用这些修改。

一个 Skill 可能写得完全正确，但较弱的任务模型没有在合适场景加载它，或加载后无法长期遵循——任一种都会让最终成绩看起来「没有进化」。

因此不能只用端到端分数反推更新器好坏。

分层指标：

| 指标 | 回答的问题 | 主要证据 |
|---|---|---|
| 更新提案有效率 | 更新器是否提出了有价值的修改 | 提案在独立验证中的接受率与增益 |
| 产物激活率 | 任务 Agent 是否在正确场景加载了新 Skill/记忆/工具 | 检索、路由与工具调用轨迹 |
| 遵循成功率 | 激活后是否按新规则执行 | 动作序列与过程验证器 |
| 保留任务集增益 | 是否改善未参与进化的任务 | 保留集成功率、质量、成本 |

评估不是学习结束后的考试，而是进化过程的一部分。长期评价至少观察五类结果：

- **回退**：新经验是否与已有经验冲突，原本能通过的案例是否退化；
- **泛化**：新经验在测试集未覆盖场景中的提升；
- **Token 效率**：完成任务消耗的成本；
- **安全性**：规则、隐私、拒绝边界是否随进化漂移；
- **长期工程质量**：维护复杂度、架构一致性、所有权边界、向后兼容性、迁移与调试负担是否恶化。

只解决当前失败、却在其他案例或新领域退化，不是成功的持续进化。

## 3. 「完成」不等于「进步」

前面的闭环在 Coding、工具调用、业务状态变更上最容易成立，因为测试、环境状态或确定性规则能快速反馈。

开放式科研、战略规划、复杂产品设计则不同：评价信号慢，正确答案不唯一，研究品味、长期价值、可维护性很难用分数评判。

此时 Harness 可能把流程执行得很完整，却只是稳定产出「像成果的东西」，没有推动真实目标。

自动科研是压力测试。四次从想法到论文的端到端尝试中，三次在实现或评估阶段失败，只有一次完成整条流水线。三类问题：

- **实现漂移**：原方案一旦变难，Agent 逐渐退回训练数据中更熟悉、但已偏离研究假设的普通实现；
- **认识论过度乐观**：信号可能只是噪声，系统却开始解释结果、添加补丁、宣布发现；失败与阴性结果更容易被忽略；
- **隐性判断力不足**：能运行实验，却未必知道什么基线重要、哪个异常值得追踪、何时应放弃假设。

这类任务不能靠换模型彻底解决，而要改变证据与监督结构：

- **结论与证据分离**：引用、数字、方法、结论分别记录来源，最终文稿只是证据图的一种呈现；
- **保留负面结果**：失败实验、被拒提案、停止原因写入日志，否则进化模块只看到幸存方案，反复探索已证伪路径；
- **维护搜索多样性**：不只保留当前最高分的一条链，备选池保留若干暂时低分但类型不同的分支；
- **让人类在更高层介入**：不只在高风险工具调用前点「批准」，还包括定义问题、审查评价标准、解释反常结果、决定何时停止。

## 4. 安全边界

Agent 的自我进化能力可能把一次错误变成长期风险：

- 网页、邮件、工具输出中的**提示注入若被总结成经验**，可能跨会话反复生效；
- 自动搜索到的恶意软件包若被封装成工具，影响会从一次沙盒运行扩散到所有后续任务；
- 有缺陷的验证器可能持续批准看似进步、实际退化的版本。

因此除了验证「是否更强」，还必须限制「谁能改什么、依据来自哪里」。

### 4.1 证据与指令隔离

原始网页、工具输出及其 LLM 摘要都属于**不可信证据**，不能当指令执行，也不能直接纳入 Skill 等长期能力。

LLM 总结只是提高可读性的转换，不是把输入变得无害的净化过程。

系统应按固定 schema 提取主张、原文位置、采集时间，同时保留原文与来源；提取出的字符串绝不能作为指令执行。模型给出的置信度也只是未经验证的估计，不能充当批准门槛。

待发布内容还要通过确定性 schema、允许列表、来源检查，再以版本化 PR 提交；独立 reviewer 对照原始证据审查，高风险 Skill 上线前人工批准。

### 4.2 待验证能力与正式能力隔离

新知识、Prompt、Skill、程序、参数都先进入**不可服务真实流量的待验证区**。新代码与外部依赖还要经过沙盒、权限检查、供应链扫描与行为测试。

安全检查和回归通过后，才能服务真实流量。

### 4.3 安全机制不可自我修改

业务 Agent 可以修改 Prompt、Skill、知识库、工具，但不能修改批准自身更新的验证器、测试用例、发布门槛、审计日志、稳定版本备份。

否则，Agent 只需降低测试阈值或删除失败用例，就能把退化伪装成进步。

## 5. 睡眠学习：整合、遗忘与能力保鲜

「睡眠学习」是对离线整合的认知类比，不要求任务真在夜间运行。

在线 Agent 的首要职责是完成当前任务并追加不可变证据；后台学习进程在空闲期或满足门控条件时读取一批新经历，比较新旧结论、合并重复、解决冲突、提出提案并运行回归。

把采集与整理分开，可以防止一次偶发成功、网络故障或恶意输入立刻改写长期能力，也允许用更大批量、更便宜的模型完成整理。

一个典型周期五步：

1. **触发**：达到时间间隔、新增轨迹数量、存储容量或错误频率门槛，并确认没有高优先级在线任务；
2. **定向**：读取正式知识、Prompt、Skill 目录及版本，了解已有能力与不可修改边界；
3. **采集与整合**：从近期已评价轨迹寻找新信号，合并重复，标记冲突与适用条件，优先生成局部补丁；
4. **验证与审批**：在迁移集、保留集、安全集评估，高风险写入等待人工批准；
5. **修剪与索引**：更新检索索引，把长期不用或被推翻的能力标记过期、归档或删除，保留来源与回滚版本。

用户记忆是直观例子，但要与行动经验区分。Claude Code 的自动记忆为每个项目维护 `MEMORY.md` 索引与按主题拆分的详细文件，会话启动只加载索引的有界前缀，其余按需读取；索引接近上限时要求 Agent 合并或移走细节。

它说明纯文本记忆也需要容量约束、分层加载与主动整理，但当前公开机制主要是在会话中持续写入，不等于固定的夜间后台任务。

Hermes 是更完整的后台记忆进化案例：长期信息分成有界的 `MEMORY.md` 与 `USER.md`、基于 SQLite/FTS5 的历史会话检索、按需加载的 Skill、可选外部记忆。历史检索返回原始消息而非先由 LLM 摘要，避免把检索与生成混成不可审计步骤。

当任务包含较多工具调用、从错误/死路恢复、收到用户纠正，或发现非显而易见的工作流时，后台复盘可以创建或局部修订 Skill；写入可经审批门控。独立的 Curator 跟踪 Skill 的使用、陈旧与归档，在空闲期做确定性修剪，可选 LLM 合并；变更前保存快照，错误整理可回滚。

持续进化也不是让知识、Prompt、工具无限增长。第二章的上下文腐化会在更长时间尺度重现：经验文档冲突、Prompt 被边界规则淹没、Skill 库重复、多次微调造成遗忘。

需要周期性离线整理：

- 合并重复经验，保留来源与版本；
- 把局部规则从全局 Prompt 移到领域 Skill，保持全局 Prompt 整洁；
- Prompt 与 Skill 保持结构清晰；
- 重新验证长期未使用的工具；
- 删除被新证据推翻的知识；
- 从原始基座重新训练 LoRA。

## 6. 补记

持续进化的完整链路不是「反思 → 改 Prompt」，而是：**在线记录证据 → 离线归因与聚合 → 生成最小提案 → 独立验证 → 灰度/回滚 → 定期修剪。**

三个边界最容易被忽略：证据不等于指令；待验证能力不能直接服务真实流量；安全机制不能被被约束者修改。没有这三条，进化越快，风险放大越快。
