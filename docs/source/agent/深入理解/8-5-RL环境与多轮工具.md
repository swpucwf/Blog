# RL 环境、多轮与工具

## 1. 环境是训练场

RL 训练的瓶颈往往不在算法，而在**环境是否足够真实、可重置、可并行**。

真实 Agent 的电话、付款或文件修改可能昂贵且不可逆，不能靠无限重试弥补一次错误；评估环境可以提供验证器，但训练还需要让 Agent 反复试错、承受副作用，并在数百万次交互中保持稳定。

环境工程的三个事实：

- **环境一旦失真，策略就会失效。** 仿真客服总按固定套路回话、错误信息与生产对不上，模型就学到一套只在仿真里管用的「应试策略」。这是 RL 项目最常见的失败——不是算法不行，而是练习场与考场不同。
- **构建高保真环境常比训练更贵。** 能大规模并行、可复现、反馈真实的环境，往往需要比调模型更多的工程资源。真实 API 有速率限制、会封号、有副作用，不能直接用于训练，必须先造一个稳定可控可重放的「影子世界」。
- **环境的另一半是奖励函数。** 它既模拟「世界怎么变」，也判定「做得好不好」。

在调算法之前先问：**我的仿真环境，真的像真实世界吗？** 这比选 PPO 还是 GRPO 重要得多。

## 2. 造不出环境：让模型扮演环境

很多场景里，高保真环境不是贵，而是根本造不出来——真实 API 不能乱调，真实用户不能试错，物理世界没法快进。

一个越来越主流的思路是：**用模型模拟环境**。两个层次：

**模型合成工具返回值。** ZeroSearch 训练「会搜索的模型」时，直接用一个 LLM 扮演搜索引擎：学生发 query，模拟引擎生成检索结果。它还采用课程式设计——初期返回高质量、强相关文档，随训练推进逐步掺入噪声、降低质量，促使学生学会从不完美结果中提取信息。训练全程没见过真实搜索引擎，直接对接真实搜索仍表现良好。

**模型仿真整个环境动态。** 不只是单个工具返回值，连「执行动作后世界会变成什么样」也交给模型。DreamGym 把环境动态蒸馏进一个推理式经验模型：给定当前状态与动作，逐步推理状态转移与反馈，从而在不访问真实环境时批量合成 rollout。客服、销售类 Agent 常用 LLM 扮演用户，τ-bench 系列正是建立在用户模拟器上——同一个模拟器，既能当考场，也能当练习场。

风险必须指出：**模拟器的世界知识就是训练的天花板，模拟器的系统性偏差会被策略照单全收。**

如果模拟客服比真实用户更有耐心、模拟搜索从不返回垃圾，学生学到的就是一套只在「模型扮演的世界」里成立的策略；更糟的是，RL 会主动寻找并利用模拟器漏洞，进行 reward hacking。

稳妥做法是**混合**：模型模拟承担大部分交互量，辅以真实环境交互，并定期用真实交互校准模拟器偏差。

## 3. 任务分布与评估隔离

环境必须可重置、可并行、可复现，并在状态转移后给出可信验证。

训练任务来源与 SFT 数据合成一致：从真实业务日志提炼任务蓝图，去除身份信息后重新生成虚构人物、订单、文件与状态。

隔离要求相同，但 RL 多一条：**训练环境与评估环境可以共享任务生成器与验证代码，却不能共享同一批任务。** 测试用例、隐藏状态与参考解法应留在验证器一侧。

还要先用少量 rollout 检查「任务是否可完成、验证器能否区分对错」，再扩大采样。**验证器有系统性偏差，RL 只会更快利用它。**

环境工程顺序：**任务蓝图 → 可重置模拟器 → 确定性验证器 → 训练/评估隔离 → 少量真实交互校准。**

确定性验证器「便宜」不等于「没有成本」。Lean kernel、测试运行器或容器执行可能让 CPU 验证远慢于 GPU 生成；这时吞吐取决于并行验证 worker，而不是继续堆 GPU。

## 4. 多轮与信用分配

![配图](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiagent_fig8-14.svg)

<p>图 1：单轮 RL 与多轮 RL 对比</p>

从单轮到多轮，复杂性发生质变：策略不仅选当前最优动作，还要考虑未来状态价值；不仅处理即时反馈，还要在延迟奖励下做**信用分配**——判断多步序列中哪一步对最终结果贡献最大。

客服 Agent 用 10 轮解决问题获得好评：该归功于第 2 轮的精准提问，还是第 7 轮的耐心解释？

多轮交互就是 ReAct 循环：每轮是「思考 → 行动 → 观察」，奖励延迟来自「最终结果好坏要在多轮后才能判断」。

![配图](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiagent_fig8-15.svg)

<p>图 2：多轮交互中的信用分配</p>

V-IRL 让 Agent 在真实城市街景连续导航：训练用纽约路线，测试迁移到不同城市，同时改变方向表达与视觉外观。RL 在规则与视觉 OOD 上都明显优于 SFT，说明多轮任务中策略需要根据当前观测重新规划，而不是复现训练轨迹。实验使用带价值网络的 PPO，逐步反馈能缓解长时序信用分配。

SimpleVLA-RL 在机器人任务中只用成功/失败结果奖励。每个任务仅用一条演示轨迹做 SFT 冷启动，随后 RL 把成功率从 17.3% 提升到 91.7%，并发现演示中没有的「推切」动作。

两者形成对照：**过程信号容易定义时能加速学习；最优路径未知时，稀疏结果奖励反而保留更大探索空间。**

## 5. 工具调用：把环境带进 Agent

多轮任务接入外部工具后，动作不再只是「移动或回答」，而是搜索、执行代码、修改文件、查询数据库、组合多个 API。信用分配、环境工程与安全约束都成了核心问题。

![配图](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiagent_fig8-16.svg)

<p>图 2：工具调用 RL 奖励循环</p>

Search-R1 代表检索增强路线：模型自主决定何时搜索、搜什么，并利用结果继续推理。ReTool 把代码解释器嵌入思考循环，模型要学会何时执行代码、如何读反馈、如何根据报错修正。AWorld-train 提供 MCP 多工具沙盒，进一步引入工具选择、依赖管理、状态重置与可重放性。

工具轨迹有一个关键实现细节：**环境返回的 token 不是策略生成的，计算策略梯度时应屏蔽这些反馈 token，只对模型自己的思考与工具调用参数回传梯度。** 否则模型会被训练去预测沙盒输出，而不是学会使用工具。

![配图](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiagent_fig8-17.svg)

<p>图 3：ReTool 交织文本—代码思考与沙盒执行反馈循环</p>

ReTool 在 SFT 预热后，用交织的文本思考、代码执行与解释器反馈做 PPO 训练。它展示工具反馈如何改变思考策略：模型逐渐学会主动执行、读取错误并自我修正。AIME 2024 上从约 25% 提升到 67.0%；相比纯文本 RL，代码反馈让模型更快学会精确计算与纠错。

![配图](https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/aiagent_fig8-18.svg)

<p>图 4：AWorld-train MCP 沙盒训练架构与工具生态</p>

AWorld-train 使用 MCP 服务器沙盒，提供 Web、文档、多媒体、代码、知识检索等工具。这个开放式实验的重点不是刷新 GAIA 指标，而是跑通可重置、可重放的多工具训练链路，并观察工具调用成功率与组合策略是否随训练改善。

这些场景共同说明：多轮 Agent 的训练难点不是「有没有更复杂的优化器」，而是环境反馈是否可靠、动作链是否可验证、最终奖励如何归因到中间决策。

## 6. 补记

环境工程的优先级高于算法调参。一个失真、不可重置或验证器有偏差的环境，会让任何算法都学到错误策略；反过来，环境真实、奖励可靠时，PPO/GRPO 的差异往往没有想象中大。

多轮与工具场景还要守住两条实现纪律：**环境返回的 token 必须屏蔽**；训练任务与评估任务必须隔离，隐藏测试与参考解法不能进入模型上下文。前者防止模型学「预测沙盒输出」，后者防止模型记住答案。
