# 模型量化实战

## 1. 小资源干大活：量化的直觉

量化就是**用较少的信息表示数据，在尽量不损失性能的前提下降低资源开销**。深度学习模型普遍存在**参数冗余**：1989 年 LeCun 的《Optimal Brain Damage》指出大量参数可删而不影响准确率；「彩票假设」进一步证明密集网络中存在一个极小子网（「中奖彩票」）性能可与原网络媲美。量化正是利用这一特性，把非关键参数的精度降低（如 FP16→INT4）。

类比：几十 MB 的 RAW 无损照片压成几百 KB 的 JPG，丢了人眼难察觉的细节，但人物风景依然清晰。量化也一样——削掉对输出影响不大的微小精度，实现**「瘦身不降智」**。

**两大收益**：

- **降显存**：FP16 是 16 位，INT8 显存减半，INT4 只剩 1/4——原本需多张 A100 的千亿模型，量化后可能一张消费卡就能跑；
- **提速度**：数据量减少即内存带宽压力降低，LLM 推理是典型**内存受限（memory-bound）** 场景，权重加载更快直接转化为更快的 token 生成。

## 2. 精度与显存估算

**精度谱系**：

- **FP32**：单精度，**4 Bytes**，训练默认，推理通常用不到这么高；
- **FP16 / BF16**：半精度，**2 Bytes**。FP16 数值范围小易溢出；**BF16** 牺牲小数位精度换与 FP32 相同的数值范围（指数位），训练更稳，是大模型训练主流；
- **INT8**：**1 Byte**；**INT4**：**0.5 Byte**（4 bit）。

**估算公式**：

$$ \text{权重显存} \approx \text{参数量} \times \text{每参数字节数} $$

以 Qwen2.5-7B（$7\times10^9$ 参数）为例：FP16/BF16 ≈ **14 GB**；INT8 ≈ **7 GB**；INT4 ≈ **3.5 GB**。

> 这只是权重静态占用。实际运行还要预留 **KV Cache**（与上下文长度成正比）、**激活值**（与 batch、序列长度相关）、**框架开销**（PyTorch/CUDA context），实际需求通常比估算高 **20%~30%**——7B 的 INT4 模型（3.5GB 权重）建议至少 6GB 显存起步。

## 3. Transformers 中的三大主流方案

HF `transformers` 中最常用的三类是 **GPTQ**、**AWQ**、**bitsandbytes（bnb）**，代码上统一走 `from_pretrained(..., quantization_config=...)` 配 `GPTQConfig`/`AwqConfig`/`BitsAndBytesConfig`。

按场景区分：**GPTQ 与 AWQ** 主要面向**推理部署加速**，属 PTQ（训练后量化），产物是量化检查点，加载后显存低、推理快；**bnb** 既常用于 8/4-bit 推理，也是 QLoRA 等**低显存微调**方案的核心依赖，擅长让大模型在单卡上完成 4-bit 训练。

### 3.1 GPTQ：二阶信息补偿

面向大规模生成式 Transformer 的**训练后量化**，是经典 OBQ 算法在超大模型上的高效进化，基于**近似二阶信息**做一次性权重量化。它解决了简单「四舍五入」（RTN）在百亿级模型上精度崩塌的问题，把 175B 模型压到 3/4-bit 且几乎无损。量化目标是最小化量化前后激活值的平方误差：

$$ \min_{\widehat{W}} \|WX - \widehat{W}X\|_2^2 $$

三大关键机制：

1. **二阶信息补偿**：用海森矩阵 $H = 2XX^\top$ 判断权重重要性——曲率小（平坦）的方向上权重微小变化对误差影响小、是「冗余」的；反之「关键」。用其逆 $H^{-1}$ 更新剩余权重，补偿当前量化误差 $\delta$：

$$ \delta_F = -\frac{w_q - Q(w_q)}{[H_F^{-1}]_{qq}} (H_F^{-1})_{:,q} $$

（这是分块/局部近似形式，核心是「用二阶信息做误差补偿」的思想。）

2. **任意顺序 + 延迟批量更新（Lazy Batch-Updates）**：大模型不需要 OBQ 式昂贵贪心排序，按顺序量化即可；把计算密集的更新按 128 列一组分块执行，提升 GPU 利用率；
3. **Cholesky 分解**：解决大模型下 $H^{-1}$ 数值不稳定问题，保证千亿规模稳健运行。

### 3.2 AWQ：激活感知的权重量化

AWQ 更适合**端侧**部署，思路更直觉：**权重的重要性不取决于权重本身大小，而取决于它所处理的激活值大小**。实验发现，仅保留 **1%**「显著权重」（对应激活值大的通道）为 FP16 就能极大恢复性能；而按权重 L2 范数选这 1%，效果与随机选差不多——**按激活值幅值选才立竿见影**。

工程上不真存混合精度（拖慢推理），而是**数学等价变换**：给重要通道的权重乘放大系数 $s$、输入除以 $s$，输出不变（$y=\mathbf{wx}$），但被放大的权重在量化时的**相对误差更小**。优化目标是找一组最优缩放因子：

$$ s^* = \arg\min_s \mathcal{L}(s), \qquad \mathcal{L}(s) = \| Q(W \cdot \text{diag}(s))(\text{diag}(s)^{-1} X) - WX \| $$

好比用尺子量物体，把物体放大后再量，读数的相对精度自然更高。

### 3.3 BitsAndBytes：LLM.int8() 与离群值

GPTQ/AWQ 是「精打细算」的量化算法，bnb 则是 **LLM.int8()** 与 **QLoRA** 等研究的工程基石。它解决的是大模型量化的**离群值**难题：模型超过 **6.7B** 后，Transformer 层会系统性涌现少量数值巨大的**离群特征（Emergent Outliers）**，只占约 0.1% 参数却对性能极关键；传统 8-bit 量化会截断/粗量化它们，导致精度瞬间崩塌。

<div align="center">
  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/basellm_13_1_4.png" width="60%" alt="模型规模与量化性能的关系" />
  <p>图 4：模型规模与量化性能的关系</p>
</div>

**LLM.int8()** 用**混合精度分解**：99.9% 常规值用**向量级量化**压成 8-bit 做矩阵乘：

$$ C_{f16} \approx \frac{1}{c_x \otimes c_w} C_{i32} $$

0.1% 超过阈值（如 6.0）的离群维度 $O$ 拆出来保持 FP16，最后合并：

$$ C_{f16} \approx \sum_{h\in O} X^h_{f16} W^h_{f16} + S \cdot \sum_{h\notin O} X^h_{i8} W^h_{i8} $$

  <img src="https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/basellm_13_1_5.png" width="80%" alt="LLM.int8() 混合精度分解示意图" />
  <p>图 5：LLM.int8() 混合精度分解</p>
</div>

「抓大放小」让模型几乎无损地以 INT8 显存开销运行。在此基础上 bnb 进一步演进为 QLoRA 的主要依赖，引入为正态权重定制的 **NF4** 类型（信噪比高于标准 INT4）。如今一个 `BitsAndBytesConfig` 就能在消费级显卡上既加载又微调大模型。

## 4. Qwen2.5 推理量化实战（llmcompressor）

用 `llmcompressor` 对 `Qwen/Qwen2.5-1.5B-Instruct` 分别做 GPTQ 与 AWQ 量化。

**工具定位**：LLM Compressor 面向 vLLM 部署优化，可带来最高 5 倍推理提速。支持 GPTQ、AWQ、SmoothQuant、SparseGPT 等；与 HF 生态深度集成；产物为 `safetensors` 压缩格式、可被 vLLM 直接加载；借助 accelerate 支持超大模型压缩。流程：输入 HF 模型 +（可选）校准数据 → 压缩算法 → 输出压缩检查点 → 加载进 vLLM 推理。

### 4.1 GPTQ 量化

```python
from llmcompressor.modifiers.quantization import GPTQModifier
from llmcompressor import oneshot

gptq_recipe = [GPTQModifier(
    scheme="W4A16",        # 权重 4bit，激活 16bit
    targets="Linear",      # 只量化线性层
    ignore=["lm_head"],    # 输出头保持高精度
)]
oneshot(model="Qwen/Qwen2.5-1.5B-Instruct", dataset="open_platypus",
        recipe=gptq_recipe, output_dir=gptq_out_dir,
        max_seq_length=2048, num_calibration_samples=128)
```

- **W4A16**：权重 4-bit（体积压到 1/4）、激活保持 16-bit 浮点——既省显存又能用 INT4 Tensor Core 加速，同时保住计算精度；
- **targets="Linear"**：Transformer 参数主要在 Linear 层；
- **ignore=["lm_head"]**：输出头负责把特征映射回词表，对精度极敏感，4-bit 量化常导致乱码/逻辑崩坏，必须排除。

**校准不可或缺**：GPTQ 是 PTQ，不需全量训练，但要少量真实数据「观察」激活分布以算海森矩阵。`dataset="open_platypus"` 是高质量指令数据集（逻辑推理、代码生成等），能代表真实输入分布、防特定领域退化；`num_calibration_samples` 通常 **128~512** 足够，再多边际收益递减。

日志会逐层打印 `Quantizing model.layers.0.self_attn.q_proj using 128 samples` 与每层耗时/误差。加载后检查结构：

```text
GPTQ q_proj layer type: <class 'compressed_tensors.linear.compressed_linear.CompressedLinear'>
quantization_config: ... num_bits: 4, group_size: 128, symmetric: true, type: int ...
```

层类型变为 `CompressedLinear`、配置记录 `num_bits:4 / group_size:128`，说明按 W4A16 分组量化成功。推理测试（「用两三句话解释量子计算」）输出逻辑清晰——4-bit 在大幅压缩体积的同时保住了核心能力。

### 4.2 AWQ 量化与差异

```python
from llmcompressor.modifiers.awq import AWQModifier
awq_recipe = [AWQModifier(scheme="W4A16", targets="Linear", ignore=["lm_head"])]
oneshot(model=..., dataset="open_platypus", recipe=awq_recipe, output_dir=awq_out_dir, ...)
```

参数看起来一样，但算法逻辑截然不同：AWQ 不依赖海森矩阵逆，而是按**激活值幅度**搜索最优缩放因子，把重要通道「放大保护」。

日志中会出现 `Running SmoothQuant for model.layers.0.self_attn.q_proj` 的 **Smoothing** 阶段——这是 llmcompressor 实现 AWQ 平滑/缩放步骤的内部命名（算法本身是 AWQ，与 SmoothQuant 论文方法不同）。本质是在执行**网格搜索**，所以 AWQ 比 GPTQ 慢很多：GPTQ 的 $H^{-1}$ 是确定性解析计算，而 AWQ 要对每层在校准数据上反复试不同 $s$ 找最优解。多花的时间换来的是对**离群尖峰**的鲁棒性——Smoothing 把尖峰压力平滑分摊到权重上，不增推理计算量却显著降低量化噪声；且 AWQ 产物在 vLLM 等引擎里往往有更好的原生加速支持。

> **补记**：三种方案可以按「解决什么问题」记——RTN 是基线（简单四舍五入，大模型必崩）；GPTQ 用**二阶信息补偿**误差（适合通用推理部署）；AWQ 用**激活幅度缩放**保护重要通道（端侧友好、vLLM 加速好）；bnb 用**混合精度分解 + NF4** 处理离群值与低显存微调（QLoRA 的底座）。选型口诀：要快速部署选 GPTQ/AWQ，要在单卡上训选 bnb/QLoRA。
