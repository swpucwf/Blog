# 权重的五种拿法

权重下载看着只是 `git clone` 或一行 `snapshot_download`，但真正决定成败的是三件事：从哪个源拿、断线后能不能续、拿完怎么确认没缺分片。

## 1. 一个模型目录里到底有什么

先认清文件族，才知道下载器在做什么、缺文件会报什么错：

| 文件 | 作用 | 缺失后果 |
|---|---|---|
| `config.json` | 层数、隐藏维、KV 头数、模型类型 | 无法实例化，报模型类型不识别 |
| `model-0000x-of-0000y.safetensors` | 分片权重 | 加载到一半报文件缺失 |
| `model.safetensors.index.json` | 分片名与张量的映射、`total_size` | 不知道要下哪些分片 |
| `tokenizer.json` / `tokenizer_config.json` | 词表与特殊 token | 分词错位，输出乱码 |
| `generation_config.json` | 默认采样参数、eos | 生成行为与官方不一致 |
| `chat_template.jinja`（部分模型内置在 tokenizer_config） | 对话模板 | `apply_chat_template` 报错 |
| `modeling_*.py`（部分模型） | 自定义结构实现 | 需要 `trust_remote_code=True` |

`index.json` 里的 `total_size` 是最实用的校验锚点：拿它和本地文件总字节数比，差几个 GB 就是缺分片。

## 2. 五条路径

| 路径 | 适合场景 | 是否需要凭证 | 断点续传 |
|---|---|---|---|
| Hugging Face CLI | 官方源、完整生态 | 部分 gated 模型需要 token | 默认支持 |
| hf-mirror 镜像 | 国内直连 HF 慢 | 否 | 支持 |
| ModelScope | 国内模型首发地 | 否 | 支持 |
| git-lfs | 需要版本历史、增量 | 视仓库 | 支持 |
| OpenXLab | 特定国产模型仓库 | 需登录 | 视接口 |

### 2.1 Hugging Face CLI

```bash
pip install -U huggingface_hub
huggingface-cli download --resume-download Qwen/Qwen3-8B \
  --local-dir /data/models/Qwen3-8B
```

`--local-dir` 建议用绝对路径，避免相对路径在不同工作目录下重复下载。`--resume-download` 是旧参数，新版 CLI 默认续传，报参数不支持时去掉即可。需要私有或 gated 仓库时先 `huggingface-cli login`，token 只放在本机凭据文件里，不要写进脚本。

### 2.2 hf-mirror 镜像

镜像只改域名，命令不变。临时生效用环境变量：

```bash
export HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download --resume-download Qwen/Qwen3-8B \
  --local-dir /data/models/Qwen3-8B
```

Python 里则先写 `os.environ["HF_ENDPOINT"] = "https://hf-mirror.com"` 再调用下载接口。镜像站的使用方式见 [HF Mirror](https://hf-mirror.com/)。

### 2.3 ModelScope

魔搭是多数国产模型的首发渠道，速度通常最稳。Python 接口：

```python
from modelscope import snapshot_download

model_dir = snapshot_download(
    "Qwen/Qwen3-8B",
    cache_dir="/data/models",
    revision="master",
)
print(model_dir)
```

命令行接口更适合写进脚本：

```bash
pip install modelscope
modelscope download --model Qwen/Qwen3-8B --local_dir /data/models/Qwen3-8B
```

注意 `snapshot_download` 的 `cache_dir` 会在其下再拼一层 `models/<org>/<name>`，而 `--local_dir` 是直接落到指定目录，两者最终的模型路径不同，后续脚本里的路径要跟着改。

### 2.4 git-lfs

需要保留版本历史或做增量更新时用 LFS：

```bash
git lfs install
git clone https://huggingface.co/Qwen/Qwen3-8B
```

代价是整个仓库都要走 LFS 带宽，几十 GB 的模型第一次克隆很慢，而且 `.git` 目录会额外占一份空间。只做推理时，前三种方式更省。

### 2.5 OpenXLab

部分国产模型在 OpenXLab 有独立仓库，接口是「按仓库名 + 文件名下载」：

```python
from openxlab.model import download

download(model_repo="OpenLMLab/InternLM-7b",
         model_name="InternLM-7b",
         output="/data/models")
```

## 3. 让推理框架自己去拉

vLLM 支持直接从 ModelScope 取权重，省掉「先下载再指路径」这一步：

```bash
VLLM_USE_MODELSCOPE=true vllm serve Qwen/Qwen3-8B \
  --served-model-name Qwen3-8B --max_model_len 8192
```

这个开关只在「有 ModelScope 同名仓库」时有用，且下载发生在启动过程里，服务启动日志会安静很久。生产环境更推荐先落盘再启动，原因很简单：启动失败时不必重新下载。

## 4. 缓存目录与磁盘账本

三种下载器各有缓存变量，混用会导致「明明下过却又要下」：

| 变量 | 作用 |
|---|---|
| `HF_HOME` | Hugging Face 缓存根目录 |
| `HF_ENDPOINT` | Hugging Face 域名替换 |
| `MODELSCOPE_CACHE` | ModelScope 缓存根目录 |
| `VLLM_USE_MODELSCOPE` | 让 vLLM 走 ModelScope |

磁盘估算按「单份权重 × 份数」算，而不是按参数量拍脑袋：

- BF16 权重约等于 `2 × 参数量` 字节，8B 约 16 GB；
- 量化仓库通常同时提供多个档位（Q4/Q5/Q8），一个 GGUF 仓库可能 30 GB 起；
- 训练时的 checkpoint 会额外占一份甚至多份，`save_total_limit` 不设就会持续增长。

一个可用的目录约定：

```text
/data/models/
├── Qwen3-8B/              # BF16 原始权重，服务化用
├── Qwen3-8B-GGUF/         # 量化档位，本地图形端用
└── lora/qwen3-8b-huanhuan # LoRA adapter，几十 MB
```

## 5. 下完先校验，再加载

三步足够挡住绝大多数「下坏了」的问题：

```bash
# 1. 文件数与总大小
ls -l /data/models/Qwen3-8B | wc -l
du -sh /data/models/Qwen3-8B

# 2. 与 index.json 的 total_size 对账
python -c "import json;print(json.load(open('/data/models/Qwen3-8B/model.safetensors.index.json'))['metadata'])"

# 3. 分片是否齐全
ls /data/models/Qwen3-8B/*.safetensors | wc -l
```

如果 `index.json` 说 4 个分片，本地只有 3 个，vLLM 启动会在加载权重时报 `No such file` 或张量缺失，而不是在下载阶段报错——所以校验必须在下完当下做。

## 6. 量化权重的来源是另一回事

原始权重（safetensors，BF16/FP16）与量化权重（GGUF、GPTQ、AWQ）是两个生态：

- GGUF 面向 llama.cpp / LM Studio / Ollama，仓库里常带 `Q3_K_M`、`Q4_K_M`、`Q8_0` 多个档位；
- GPTQ / AWQ 面向前述 GPU 推理框架，需要模型定义里有对应量化层支持；
- 社区量化仓库（如 `lmstudio-community/*-GGUF`）由第三方转换，精度与行为以该仓库说明为准。

选择档位时回到上一篇的显存账本：4-bit 大约是 BF16 的四分之一，但 Q4_K_M 与 Q8_0 之间还有一档质量差，8 GB 显存优先 Q4_K_M，16 GB 以上可以直接 Q8_0。

## 7. 可交付物与练习

产出一份 `models/README.md` 清单，每个模型记四行：仓库 ID、下载方式与命令、本地路径、总大小与分片数。这份清单在换机器或多人协作时能直接复用。

练习：同一份 8B 权重分别用 ModelScope 与 hf-mirror 各下一次，比较耗时、最终目录结构与 `snapshot_download` 返回路径的差异。
