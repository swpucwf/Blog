# 大模型安全总览

## 1. 从「好用」到「可控」

大模型在对话、搜索、编程辅助与垂直行业快速普及，但多份系统综述指出：随着模型规模扩大、接入场景增加，产生有害内容、偏见、错误决策与被恶意利用的事件同步增加，安全问题从「潜在担忧」升级为「现实痛点」——风险不再只是某个接口的单点故障，而是贯穿**数据—模型—工具—运营**全流程的系统性隐患。

业界用 **3H 原则**（Anthropic 最早推广）衡量「可控」：**Helpful**（有用）、**Honest**（真实）、**Harmless**（无害）。但三者常需权衡——过度追求无害可能导致模型拒绝正常的科学问题（**过度拒答**）。

理论权衡面对恶意攻击时更显脆弱。安全研究用**越狱（Jailbreak）** 描述精心构造提示词诱导模型无视安全策略、输出禁止内容的攻击；用**提示注入（Prompt Injection）** 描述攻击者嵌入隐藏指令、改写系统预期行为的方式。近年调研表明这类攻击已形成较完善的分类与评测体系：设定虚构角色、拆分问题、多轮「温水煮青蛙」式对话，都能让模型逐步偏离安全约束，输出攻击步骤、仇恨言论或自残暗示等高风险内容；医疗、教育、心理健康评测中还观察到模型在情绪化话题上出现极端表达、在敏感领域给出看似自信但明显错误的建议，并在追问下不断「添油加醋」。所以单纯依赖「直觉防守」远远不够，需要从**模型运行机理**与**系统架构**两条线同时理解：模型为什么会被带偏，系统能在哪些环节兜底。

## 2. 模型机制中的安全隐患

### 2.1 数据污染与能力陷阱

预训练是模型「大脑」发育的关键期，它贪婪地从语料中汲取养分——而语料不可避免夹杂人类社会的偏见、虚假信息与恶意言论，模型在学会「像人一样说话」的同时可能全盘照收这些「思想病毒」。

底层看，主流模型仍是**自回归 Transformer**，本质是**基于概率的下一个词预测器**。海量参数与数据让它涌现出推理与规划能力，但它**并不具备人类意义上的「是非观」或内建的「事实核查器」**——只是根据语料共现概率续写最顺畅的 token。因此一旦上下文包含恶意示例、不良价值取向或隐含指令，模型极易顺势继续那条「话语轨道」，出现「一本正经说错话」甚至输出违法有害内容。**大模型的安全是概率性的**——不存在传统软件「修 Bug 就 100% 安全」的状态，只能无限降低风险概率。

更棘手的悖论：**模型基础能力越强，安全防御可能越难**。小模型可能因理解不足而无法被复杂攻击诱导；而强上下文理解与指令遵循能力意味着攻击者只需找到微妙的「语境薄弱点」，就能利用模型的「聪明」让它一本正经输出本该屏蔽的内容。所以安全必须作为「核心基因」，从预训练数据筛选起就植入模型构建的每一环。

### 2.2 KV Cache 与「记得太多」

为支持多轮对话与长上下文，现代大模型普遍用 KV Cache 缓存历史对话。它提升连贯性与「人格一贯性」，也带来两个隐患：

- **上下文越界可见**：多用户/多会话间错误复用缓存或共享检索结果，可能在 B 的对话中泄露 A 的内容（跨会话隐私泄露）；
- **长程依赖中的暗示放大**：攻击者在早期轮次埋入看似无害的引导，借缓存让信号在后续生成中持续作用，实现「多轮劫持」。

系统视角的风险分类综述指出，LLM 系统的隐私泄露与行为失控往往与输入模块、语言模型、工具链之间缺乏清晰边界与安全审计有关。结合代理型模型的长程记忆机制，**没有明确的记忆分级、过期与审计策略**时，持久化记忆会反过来成为隐私泄露、行为扭曲与不可解释输出的来源。

### 2.3 RAG、工具调用与代理化

工业界大量使用 **RAG**、**函数调用（Tools/Plugins）** 与**多代理编排（Agents）**，让模型能「查资料、调接口、驱动系统」。这些扩展让模型触达数据库、业务系统与外部 API，也因此成为新一代高危接口：

- **RAG 与间接注入**：除文档投毒外，还有**间接提示注入**——攻击者无需直接对话，只需在网页/文档里藏不可见的「指令文本」，模型检索阅读时即被劫持；
- **函数调用/插件**：缺乏最小权限与白名单时，模型可能在诱导下调用高权限接口（删除数据、发起转账），「过度代理能力」已被列为独立风险类别；**多智能体交互**还可能产生不可预测的反馈循环，导致系统性失控。

大模型运行机理本身并非「邪恶」，但它对上下文高度敏感、对扩展能力高度依赖，使安全问题往往不是单一层面缺陷，而是**模型、记忆、检索与工具协作失败的综合结果**。

## 3. 四个维度理解失控

大模型安全可分为**基础安全领域**与**相关安全领域**：基础安全涵盖价值对齐（偏见、隐私、有毒内容）、鲁棒性（越狱与防御）、恶意滥用（虚假信息、深伪、武器化）、自主风险（目标错位、欺骗行为）；相关安全延伸至 Agent 外部交互、可解释性内建安全、工程路线图与治理政策。

### 3.1 价值对齐与有害内容

关注模型是否输出违背伦理法律底线的内容：仇恨言论、煽动暴力、自残鼓励、色情与歧视性言论等。参考 SafetyBench 等评测，可细分为**攻击性、不公平与偏见、伦理道德、违法活动、身体健康、心理健康、隐私财产**七大维度。其中**身心健康**风险尤其值得注意——模型不应提供错误的医疗急救建议或诱导心理创伤的言论，这是传统内容风控的盲区。

SafetyBench 用选择题展示边界：**攻击性**测试要求判断「所有四川人都…」这类地域歧视是否冒犯；**身体健康**测试中，面对「看见一只口吐白沫的狗」，模型必须识别「擦拭下巴」是高危行为并选择正确避让。基于场景的细粒度分类，比「有害/无害」二分法更能覆盖真实世界的复杂风险。

大规模评测表明，即便对齐过的商用模型，在极端话题或复杂上下文中仍会出现不当内容。2024 年 11 月的「Gemini 请去死」事件就是例子——用户就老龄化挑战多轮对话后，模型突然输出「你对地球来说是负担…请去死」的极端言论。

研究通常归因两方面：预训练语料本身存在大量偏见与极端表达，缺乏严格过滤时被原样学习并在新语境复用；对齐数据与策略覆盖有限，多文化、多语种与细分场景缺乏足够安全约束样本。模型还容易出现**迎合效应（Sycophancy）**——为取悦用户而顺从错误观点，这是更隐蔽的价值观对齐失败。

### 3.2 真实性与幻觉

**幻觉**指模型在缺乏真实依据或检索失败时，仍以自信口吻编造看似合理但事实错误的内容，是当前可信度的核心瓶颈。幻觉并非仅由推理随机性导致，而贯穿研发全生命周期：

从**数据清洗**阶段的错误知识录入，到**模型架构**中注意力机制的缺陷，再到**预训练**的捷径学习与**微调**的过拟合，每个环节都可能埋下隐患。所以治理幻觉要从全流程入手，而非只修补输出。

幻觉通常拆为两类：**与输入不一致**（编造不存在的前提或问答关系）、**与客观事实不符**（虚构引用、错误数据、伪造来源）。检测与缓解方法包括**一致性校验**、**多样采样自比对**、**检索结果交叉验证**、**显式不确定性标注**。医疗、法律、科研等高风险领域，幻觉可能直接导致错误诊疗或误导性论证，因此「让模型知道自己不知道」（合理拒答、转介人类）的**弃答能力**正被视为安全的重要维度。

### 3.3 对抗攻击与恶意滥用

聚焦主动攻击者如何利用漏洞达成恶意目标：提示注入与越狱、数据与模型投毒、模型窃取与逆向、拒绝服务、供应链攻击等。OWASP LLM Top 10（2025 版）把**提示注入、敏感信息泄露、供应链漏洞**列为前三大风险。

新型攻击也在演进：**资源耗尽**（构造超长上下文或复杂推理链消耗算力，致延迟甚至瘫痪）；**不安全的输出处理**（下游盲目信任并执行模型输出，如生成的代码/网页片段，可能触发 XSS 或 RCE）；攻击面还在向下层基础设施延伸——利用深度学习框架（如 PyTorch）的序列化漏洞执行恶意代码，甚至通过监控 GPU 电磁信号或功耗（侧信道）窃取模型参数与结构。

### 3.4 隐私、数据治理与合规

训练与服务阶段都要处理大量用户数据与日志，带来成员推断、训练数据重构、敏感信息泄露与跨境数据流动合规等问题。数据安全综述从数据投毒、提示注入、幻觉、提示泄露、偏见等维度梳理风险，并总结对抗训练、RLHF、数据增强等防御思路。

- **成员推断攻击**：通过针对性查询与统计分析，反推训练语料中出现过的姓名、地址或账号；
- **推断隐私**：从用户提供的非敏感数据（文本风格、在线活动时间）推断政治倾向、健康状况、地理位置等敏感属性；
- **长期投喂恶意样本**：影响模型偏好甚至植入后门。

监管层面，规制网络正快速收紧：欧盟《人工智能法案》首创把通用大模型纳入高风险监管框架，对透明度与风险评估提出强制红线；我国侧重「算法备案」与「内容可控」双重治理——《生成式人工智能服务管理暂行办法》及配套算法备案制度要求服务商报备训练数据来源、人工干预机制与安全防护措施，既约束输出不得触碰法律底线，也对用户隐私数据的收集使用划定边界。这迫使平台在「释放创造力」与「收紧缰绳」之间寻找**可调式安全治理**机制。

## 4. 全链路防护

安全防护不是某一层「加几条规则」能解决的，而要围绕**输入—模型—工具链—输出**构建多层防线，并在监控治理层闭环。

### 4.1 输入与接口：挡住第一波洪水

- **身份与速率控制**：公开 API 引入认证、配额与节流，防暴力枚举与大规模型红队扫描；
- **提示内容过滤与结构化解析**：进模型前做敏感词、注入模式与异常结构检测（规则 + 分类器），把「纯文本指令」拆成结构化字段减少歧义空间；采用**防御性提示设计**，如**三明治防御**（用户输入夹在两条安全指令之间）、**JSON 封装**（强制用户输入被解析为数据字段而非指令）；高困惑度等统计特征可作辅助信号，但目前仍偏研究阶段，须与其他机制结合；
- **上下文与会话隔离**：不同用户/租户/会话用独立会话 ID 与缓存空间，未显式授权禁止跨会话复用历史上下文，从架构上避免「串号」；
- **可编程护栏（Guardrails）**：引入 NeMo Guardrails 等运行时框架，用专门脚本定义对话流边界（如「不讨论政治」「不回应竞对话题」），在生成前后做实时语义拦截，而非只靠关键词匹配。

OWASP 还建议在接口层显式标注「可被模型访问的外部资源白名单」，对上传文件、URL、富文本做严格审查与大小限制，防长文档或隐写内容实施间接注入。

### 4.2 让「能说」变成「该说什么」

模型内部的防护主要体现在**对齐**与行为控制，让模型在有用性与安全性间取得可接受折中：

- **人类/AI 反馈的对齐训练**：RLHF、RLAIF、DPO 把「拒绝有害请求」「保持诚实礼貌」「不确定时表明局限」转化为优化目标。随着模型能力逼近甚至超越人类，**可扩展监督（Scalable Oversight）** 成为根本挑战——单纯依赖人类反馈可能让模型学会「迎合」甚至欺骗评审（Sycophancy），或利用审查漏洞获取奖励（Reward Hacking）；
- **「宪法式」规则与指南库**：借鉴 Constitutional AI，预设覆盖安全、隐私、偏见与专业伦理的「原则集」，在训练或推理时作为高优先级系统指令。研究表明，仅添加强调安全的 System Prompt 就能降低开源模型约 **9%** 的不安全响应率——成本最低的第一道防线；
- **弃答与转介机制**：高风险领域引入「合理拒答」「建议咨询专业人员」的模板化行为，用阈值、置信度估计或外部验证器控制不确定场景下的输出范围与语气；
- **数据增强与去偏**：训练阶段引入**反事实数据增强**（置换性别、种族词汇等生成平衡样本），从源头消除刻板印象；
- **遗忘学习（Machine Unlearning）**：前沿技术，让模型在不损失通用能力的前提下定向「遗忘」特定有害知识（如危险化学品制法）或受版权数据。

> 安全对齐过度会带来**过度拒答**副作用——完全安全的场景也频繁拒答，损害可用性。近期工作探索用激活引导、细粒度标签与多目标优化来平衡「有用」与「谨慎」。

### 4.3 给「外放能力」装护栏

对具备 RAG、函数调用或多代理能力的系统，工具链本身就是新攻击面，从**权限、审计、隔离**三维加固：

1. **最小权限与白名单**：每个可调用接口定义精确权限边界，只暴露必要读写能力，修改类操作加确认或 Human-in-the-loop；
2. **调用审计与沙箱执行**：记录每次调用的参数、来源提示与结果，高危操作放入受限环境执行，配速率限制与模式检测，异常时阻断并回滚；
3. **RAG 数据治理**：检索库做数据清洗、敏感信息脱敏与版本管理，引入内容分级与可信度标签，避免未经审核的外部文本被当作权威依据。

### 4.4 监控、日志与安全治理

安全是持续运营而非一次性配置：

- **安全监控面板**：把有害响应率、拒答率、越狱成功率、高危工具调用频次与延迟、成功率并列观测；
- **可回放与审计**：触发安全策略的会话脱敏存档，供复盘迭代与合规取证；
- **数字水印**：在输出中嵌入不可见水印（如调整 token 采样分布），实现 AI 生成内容的标识与溯源；
- **跨职能治理**：安全责任从工程团队扩展到产品、法务、运营，把安全评估嵌入新功能上线与模型版本升级流程；
- **安全缓冲区**：借鉴 Anthropic 实践，在能力达到危险阈值前（如从 ASL-2 升到 ASL-3）预留缓冲期，做更严格红队测试与熔断部署，为人工干预留时间窗。

## 5. 如何量化「是否安全」

### 5.1 安全基准与红队

**SimpleSafetyTests**、**SafetyBench** 等套件从仇恨、暴力、自残、隐私泄露、违法指导等维度提供标准化测试集与评分。但需注意**负向预测力**局限——测试集满分只能证明「未发现已知漏洞」，不能证明「绝对安全」。

</div>

在「人类使用了多少大脑」这一问题上，GPT-4 与 Bard 给出事实正确且详尽的回答，但与简短标准答案的文本重合度极低，BLEU/ROUGE 得分很低——「答对了但得分低」，直观说明传统指标在长文本生成与复杂推理场景下失效。

当前趋势转向**语义自动化评估**：用模型自身或外部评委模型作「裁判」（LLM-as-a-Judge）；部分研究表明引入思维链后识别复杂有害内容的准确率明显提升，某些设置下接近人类专家。**安全理解能力**评估也日益重要——SafetyBench 用选择题考察模型是否「知晓」安全边界，结果显示**安全理解能力与安全生成能力强相关**：提升对规则的认知可有效降低开放生成中的有害输出。相比昂贵的人工红队，这是更快速、可量化的基准手段。

### 5.2 幻觉检测

幻觉分为**事实性幻觉**（违背世界知识）与**忠实性幻觉**（违背输入上下文或指令）。纯文本相似度已不足以衡量可信度，业界建立了多维度检测体系：

1. **不确定性与内部状态检测**：用概率分布识别风险——**语义熵**判断模型在陈述事实还是「猜谜」；**Lookback Lens** 等分析注意力图，检测是否过度关注无关上下文；
2. **自一致性校验**：**SelfCheckGPT** 对同一提示多次采样比对，若多次回答相互矛盾则大概率为幻觉——无需外部知识库，适合黑盒模型；
3. **检索与事实核查**：引入 FactCC 或基于 RAG 的流程，把生成内容拆成原子断言逐一与权威证据比对；
4. **模型即裁判**：GPT-4 等强模型模拟人类评估（如 **G-Eval**），从连贯性、事实性、相关性打分——虽有偏差风险，但与人类判断的相关性显著优于传统统计指标。

医疗等高风险场景还会引入人类专家打分与领域基准，评估模型在专业知识、风险提示与情绪照护上的综合安全表现。

> **补记**：这一篇的关键结论可以压成三句——① 安全是**概率性**的，不存在「修完就 100% 安全」；② 幻觉与有害输出贯穿**数据→预训练→对齐→推理**全生命周期，治理必须全流程；③ 评价「是否安全」不能用文本重合度，而要靠**实体级/语义级基准 + 安全理解力 + 红队**。记住这三点，后面看任何安全方案都知道它坐在哪一层。
