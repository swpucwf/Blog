# 文本表示与词向量

## 1. 分词：把文本敲碎成积木

**分词（Tokenization）** 的任务是把连续的文本序列切分成具有独立语义的基本单元（词或词元）。英文天然有空格分隔，分词相对简单；中文、日文等语言的文本是连续字符流，词之间没有明确边界——`"给阿姨倒一杯卡布奇诺"` 需要算法切成 `["给", "阿姨", "倒", "一杯", "卡布奇诺"]`。

分词质量决定上层建筑（信息检索、机器翻译、情感分析）的稳固程度。传统流程中分词是独立且「硬性」的预处理步骤，微小切分错误会在后续链条中不断放大，产生**级联效应（Cascading Effect）**：搜索引擎把「南京市长江大桥」错分为 `["南京", "市长", "江大桥"]` 后，很难再还原正确的地理位置含义。现代 NLP 通过更灵活的切分策略（见第 6 节）在很大程度上缓解了这个问题。

## 2. 通过 jieba 认识基于规则与词典的分词

`jieba` 是经典、简单、开源的中文分词库。大模型兴起后传统「语言学分词」的应用场景在减少，但 jieba 仍是理解分词思想、学习 NLP 基础工程实践的重要工具。

### 2.1 原理：词典 DAG + 最大概率路径

jieba 默认模式的核心是**一部大型词典 + 一套匹配规则**：先基于**前缀词典（Trie 树）**构建包含句子所有可能词语组合的**有向无环图（DAG）**，再用动态规划找概率最大的路径。分词路径 $w_1, ..., w_n$ 的概率近似为：

$$ P(w_1, w_2, ..., w_n) \approx P(w_1) \times P(w_2) \times ... \times P(w_n), \quad P(w_i) = \frac{\text{词 } w_i \text{ 的词频}}{\text{词典总词频}} $$

两个工程细节：

- **Log 概率防下溢**：大量小于 1 的概率直接相乘会趋近 0（浮点数下溢），jieba 用对数把累乘转成累加，即求 $\arg\max_w \sum_i \log P(w_i)$。对数单调递增，log 概率和最大等价于原始概率最大。例如「给 阿姨 倒 一杯 卡布奇诺」与「给 阿姨 倒 一 杯 卡布奇诺」两条路径，「一杯」是高频词，$\log P(\text{一杯}) \gg \log P(\text{一}) + \log P(\text{杯})$，故前者胜出。
- **动态规划提效**：从句子末尾**从后向前**递推计算每个位置的最优切分路径及 log 概率和，记入 `route` 表，再从句首回溯出结果，避免暴力枚举所有路径。

对应代码中四个方法与流程一一映射（简单了解即可）：`cut` 用正则把汉字区块与非汉字部分分开；`get_DAG` 扫描词典画出所有「走法」的有向无环图；`calc` 反向动态规划打分并记录最优路标；`__cut_DAG_NO_HMM` 按 `route` 表回溯输出 `['我', '在', '梦里', '收到', '清华大学', '录取', '通知书']`。

### 2.2 精确模式实践与自定义词典

```python
import jieba

text = "我在梦里收到清华大学录取通知书"
seg_list = jieba.lcut(text, cut_all=False)  # cut_all=False 表示精确模式
# ['我', '在', '梦里', '收到', '清华大学', '录取', '通知书']
```

切得理想是因为「清华大学」「通知书」在词典中有稳定统计信息。遇到词典未收录的新词（如「奔波儿灞」）就会被切碎，此时可用**自定义词典**人工干预。`user_dict.txt` 每行格式为 `词语 [词频] [词性]`（后两项可选、空格分隔）：

```python
jieba.load_userdict("./user_dict.txt")
text = "九头虫让奔波儿灞把唐僧师徒除掉"
# 加载前: ['九头', '虫', '让', '奔波', '儿', '灞', '把', '唐僧', '师徒', '除掉']
# 加载后: ['九头虫', '让', '奔波儿灞', '把', '唐僧', '师徒', '除掉']
```

这解决的正是 **OOV（未登录词）** 问题——相对某个词典未被收录、本该整体的词被错误切碎的现象。加词但不指定词频时，jieba 会先对新词试切（`["奔","波","儿","灞"]`），基于组成部分的词频计算概率，再给整体赋予**略高于**其组成概率之积的词频，从而「强制」成词。

### 2.3 统计学习时代：HMM 识别新词与词性标注

为摆脱对人工词典的过度依赖，统计学习把分词看作**序列标注**问题：给每个字打位置标签，`B`（Begin）/`M`（Middle）/`E`（End）/`S`（Single），「我爱北京」标注为 `S S B E`，分词就转化为寻找最合理标签序列。**隐马尔可夫模型（HMM）** 是经典生成式解法，学习字与标签的发射概率、标签间的转移概率。jieba 用 HMM 识别词典外的 OOV：`__cut_DAG` 采用**「单字缓冲，二次加工」**策略——路径上的单字先攒进缓冲区，遇到多字词或句尾时，把缓冲区里的连续单字串交 HMM 二次分词，试图用统计规律把字「粘」回成词：

```python
text = "我在Boss直聘找工作"
jieba.lcut(text, HMM=True)   # ['我', '在', 'Boss', '直聘', '找', '工作']
jieba.lcut(text, HMM=False)  # ['我', '在', 'Boss', '直', '聘', '找', '工作']
```

HMM 能发现新词，但其两个核心假设（观测独立、齐次马尔可夫）过于严格，无法利用丰富上下文特征，复杂歧义场景效果不如后续 CRF。

词性标注用 `jieba.posseg`，策略是**词典查询 + HMM 混合**。自定义词若未给词性会标默认值 `x`（非语素字）；标签体系兼容 **ICTCLAS** 标记集（`n` 名词、`nr` 人名、`v` 动词、`a` 形容词、`m` 数词、`q` 量词、`t` 时间词、`p` 介词、`c` 连词、`u` 助词、`w` 标点等）。一个有意思的实验：把 `user_dict.txt` 改成 `九 10000000 n`、`头 1000000 n` 再重新加载，「九头虫」会被刻意拆成 `['九','头','虫']`——单字被赋予超高词频后，动态规划认为「九」+「头」路径概率远大于「九头」。**词频即投票权**，这是理解词典法行为的关键。

## 3. 为什么需要词向量

以文本分类判断「国足爱吃海参」是否「负面」为例：无论分出的词还是单字，对计算机都只是字符串。机器学习与深度学习模型处理的输入必须是**数值形式**（特征向量或矩阵）。核心任务是**弥合自然语言（符号世界）与数学模型（向量空间）之间的鸿沟**——把词元序列整体转成模型可处理的数字，统称**词向量表示（Word Representation）**；文献中常见的**词嵌入（Word Embedding）** 特指神经网络学出来的稠密、高效的词向量，是词向量家族的重要成员。

仅仅转成数字不够：好的词向量不仅要唯一标识每个词，还要**蕴含语义信息**——「国王」与「女王」的向量距离应远小于「国王」与「香蕉」的距离。

## 4. 离散表示：One-Hot、词袋、TF-IDF、N-gram

深度学习普及前的方法把每个词视为独立不可再分的单元，生成的**离散向量**维度高且稀疏。

### 4.1 独热编码（One-Hot）

构建词典 → 分配索引 → 用长度等于词典大小的向量表示每个词，对应索引位置为 `1` 其余为 `0`。词典 `["我","先","挣","它","一个","亿"]` 中「我」即 `[1,0,0,0,0,0]`。

优点是实现简单、能清晰区分词语。缺点有两个：

- **维度灾难**：词典数万词，向量维度就数万，数据极稀疏，浪费计算与存储。
- **语义鸿沟**：任意两个不同词的独热向量**正交**（点积为 0）——每个向量只有一个 1，不同词的 1 必然错开，乘积项全为 0。几何上正交即「同等不相似」，「国王-女王」与「国王-香蕉」的距离完全一样，语义信息严重丢失。

### 4.2 词袋模型（BoW）与余弦相似度

独热表示单词，词袋表示**文档**：**忽略词序和语法**，把文本视作装满词的「袋子」，用袋中每个词的出现统计量表示整个文档——相当于把文档里所有词的独热向量相加。词典同上时：

```text
vec(我 先 挣 一个 亿) = [1, 1, 1, 0, 1, 1]
vec(我 挣 它 一个 亿) = [1, 0, 1, 1, 1, 1]
```

每一维代表对应词在文档中的出现次数。**余弦相似度**通过夹角余弦衡量相似性，非负向量取值 `[0,1]`，越接近 1 越相似：

$$ \text{similarity} = \cos(\theta) = \frac{\mathbf{A} \cdot \mathbf{B}}{||\mathbf{A}|| \cdot ||\mathbf{B}||} $$

上例两文档点积 4、模长各 $\sqrt{5}$，相似度 $4/5 = 0.8$，数学上证明二者高度相似。每维的统计方式可选：**频数**（长文普遍偏高）、**频率**（除以文档总词数）、**二进制**（只记是否出现）。

词袋优点同样是实现简单，且在**文本分类**上表现不错——这类任务核心在「文档里有什么词」而非「词如何关联」。缺点：**丢失词序**（「我爱你」与「你爱我」表示完全相同）；**未考虑词的重要性**（「的」「是」等停用词频次高却对区分主题贡献寥寥）。

### 4.3 TF-IDF：给词加权

为了解决「常见词权重过高」导致文档混淆，**TF-IDF** 的理念是：一个词的重要性与其在**当前文档中出现的次数**成正比，与其在**整个语料库中出现的频率**成反比。当前文档越常见、其他文档越罕见，权重越高。

$$ TF(t,d) = f_{t,d} \ \text{或归一化} \ \frac{f_{t,d}}{\sum_{t' \in d} f_{t',d}}, \qquad IDF(t,D) = \log \frac{|D|}{|\{d \in D: t \in d\}|}\ (\text{平滑版分母 } +1) $$

$$ TF\text{-}IDF(t,d,D) = TF(t,d) \times IDF(t,D) $$

应用广泛：**关键词提取**（按 TF-IDF 降序排列，jieba 内置）、**文本相似度**（TF-IDF 向量 + 余弦）、早期搜索引擎里衡量查询词与网页相关性的核心指标。

### 4.4 N-gram：预测下一个词的鼻祖

词袋和 TF-IDF 彻底丢了词序，**N-gram** 通过统计连续词组弥补，更重要的是它最早引入**预测下一个词**的思想，可视为现代大模型的**鼻祖**。核心是**马尔可夫假设**：一个词出现的概率只取决于前面 N-1 个词。Unigram 词间独立；Bigram 依赖前 1 词；Trigram 依赖前 2 词。「我喜欢玩 GTA6」的 Bigram 特征是 `{"我 喜欢","喜欢 玩","玩 GTA6"}`，由此区分「我 喜欢」与「喜欢 我」。

> 现在的 GPT 等大模型，本质上可以被视为一个 **N 非常非常大**（比如 N=128000）的超级 N-gram 模型，都在执行根据上文预测下一个词这一任务。

代价也巨大：**组合指数级爆炸**（1 万词词典的 Trigram 有 $10^{12}$ 种组合）与**数据稀疏**（绝大多数词组合从未出现，概率为 0），为此发展出**平滑技术**和**基于类的 N-gram**。也正是为从根本上解决这些限制，诞生了词向量和神经网络语言模型。

## 5. 序号化表示：深度学习时代的最小预处理

现代深度学习模型只做最少的预处理：不再设计复杂特征工程（如 TF-IDF）来告知模型哪些词重要，而是把文本转成最基础的**整数 ID 序列**，把「学习词语的含义和重要性」**交给模型自己完成**。过程三步：

1. **构建词典**：深度学习里通常是**字级别**（BERT）或**子词级别**（GPT），而非词级别。
2. **增加特殊词元**：`[PAD]`（ID 通常 0，批处理时把短句填充至同批次最长长度）、`[UNK]`（ID 通常 1，表示未登录词），按任务可加 `[CLS]`、`[SEP]` 等。
3. **ID 映射**：词元 → 整数 ID。

实践中很少为小数据集从零建词典，通常直接用预训练模型的 `vocab.txt`（Google 中文 BERT 约 21128 个词元）。完整实例——词典 `{'[PAD]':0, '[UNK]':1, '比':2, '方':3, '说':4, '我':5, '先':6, '挣':7, '它':8, '一':9, '个':10, '亿':11}` 处理三个句子：

```text
我挣一个亿 -> [5, 7, 9, 10, 11]
比方说我   -> [2, 3, 4, 5]     -> 填充 -> [2, 3, 4, 5, 0]
我先挣钱   -> [5, 6, 7, 1]     -> 填充 -> [5, 6, 7, 1, 0]  （「钱」不在词典，映射 [UNK]=1）
```

得到 3×5 整数矩阵即为模型输入。**序号化本身并未解决语义鸿沟**——整数 ID 不具备数学意义，其真正价值是作为后续**嵌入层**的输入：嵌入层把 ID 查询映射为低维稠密浮点向量，映射关系在训练中**学习**得到。

## 6. 从「分词」到「分块」：现代模型的两种粒度

BERT/GPT 等预训练模型兴起后，传统「切分成标准词语」的范式被**「无分词」或「弱分词」**策略取代，文本被处理成更基础的数据驱动单元：

- **字粒度**（BERT 中文）：每个汉字一个 Token。常用汉字有限，可轻松建全覆盖字表，彻底解决 OOV、摆脱词典依赖。代价：**词汇语义丢失**（「博物馆」拆散后模型要花更多资源学组合关系）；**序列长度显著增加**，计算负担加重。
- **子词粒度**（GPT 系列，主流算法 **BPE**）：在语料上迭代合并高频**相邻**字节对（字符对）为新单元加入词表——「deep」和「er」常相邻出现就合并成「deeper」。在「词」和「字」之间取得平衡：高频词完整保留、低频词拆成有意义小单元，词表大小可通过合并次数控制。局限：基于统计频率而非词根词缀等语言学规则，可解释性差、对训练语料依赖强，领域外文本可能过度切分。尽管如此，子词切分凭词表大小与语义表达的出色平衡，成为当前大语言模型处理文本的**标准方案**。

## 7. 寻找理想的词向量：主题模型路径

以上离散方法都无法表达词语间语义关系。**分布式表示（Distributed Representation）** 的目标是把词映射到低维、稠密、蕴含语义的连续向量空间，需同时满足两个标准：

- **语义蕴含**：向量距离度量语义相似度，原理是**分布式假设**——两个词经常在相似上下文共同出现，向量就应靠近（「被子」与「床铺」近，「椰子」与「企鹅」远）。
- **低维稠密**：维度是较小的可控超参数而非词典大小，每一维都是有意义的浮点数。

第一条路径是**主题模型**：关键假设是**一篇文档由多个主题按比例混合，一个主题由多个词按概率组成**。词之所以共现，是因为都在描述同一潜在主题，于是**一个词的向量就可用它与各主题的关联强度表示**。核心技术是矩阵分解：

$$ X_{m \times n} \approx W_{topic\, m \times k} \times H_{topic\, k \times n} $$

以 TF-IDF 填充巨大的**词-文档矩阵 $X$**，做 **SVD** 分解为「词-主题矩阵 $W_{topic}$」和「文档-主题矩阵 $H_{topic}$」，$k$ 是期望发现的潜在主题数。$W_{topic}$ 的每一行就是 $k$ 维稠密词向量：「CPU」和「GPU」若常共同出现在「硬件」主题文档中，在对应主题维度上都有高值，向量自然接近。

从机器学习视角，主题模型本质是**聚类算法**：$H_{topic}$ 把文档软分配到主题（一篇文档可能 70% AI、30% 数学），$W_{topic}$ 揭示词的主题倾向，一定程度缓解同义词问题（「番茄」「西红柿」写法不同但都高频出现在「烹饪」主题中，向量相似）。局限也很明显：大型语料 SVD 计算量和内存开销极大；依赖全局粗粒度的文档级共现，忽略局部上下文与词序，难以捕捉精细语义；「先统计再分解」无法与深度学习模型端到端联合训练。

## 8. Word2Vec：局部上下文预测

Google 2013 年提出的 Word2Vec 把视角从全局文档统计转向**局部上下文**，思想直接来自 Harris 的分布式假设：**一个词的含义由其上下文中的词语决定**。

### 8.1 定位：浅层网络是手段，词向量表是目的

Word2Vec 是**浅层神经网络**——移除了传统神经概率语言模型（NNLM）中计算昂贵的非线性隐藏层，投影层直连输出层，因此能在大规模语料上高效训练。理解它的关键是区分**最终目标**与**实现手段**：网络结构只是手段，真正目标是高质量的**词向量查询表 $W_{in}$**（每行一个词的稠密向量）。为此设计一个「伪任务」——根据上下文预测中心词（或反之），把 $W_{in}$ 作为模型参数在训练中优化；训练结束，预测网络本身**丢弃**，只保留词向量表。

ID 转稠密向量概念上分三步：输入词 ID → 独热编码 → 乘以可学习矩阵 $W_{in}$。由于独热向量只有一个 1，乘法等效于从 $W_{in}$ 中**抽取**对应行。实践中不做真矩阵乘法，而是直接**查表**。PyTorch 的 `nn.Embedding` 层本质上就是这个 $W_{in}$ 查找表，接收整数 ID 查表输出稠密向量，参数随整个模型训练（反向传播）自动更新——后续章节搭模型的第一层通常就是它。

数据流（以 $B{=}2, S{=}6, |V|{=}10000, D{=}128$ 为例）：输入形状 $(2,6)$ 的上下文词 ID → 查 $W_{in}$ 得 $(2,6,128)$ → 对 6 个词向量**求平均**得上下文向量 $h$，形状 $(2,128)$ → 乘输出矩阵 $W_{out}^T$ 得 $(2,10000)$ 得分 → Softmax 转概率与真实中心词算交叉熵，反向更新 $W_{in}$、$W_{out}$。损失为负对数似然：

$$ J = -\log P(w_c | context) = -u_c^T h + \log \sum_{j=1}^{|V|} \exp(u_j^T h) $$

### 8.3 Skip-gram：中心词预测上下文

方向恰好相反，且把一个预测任务拆成多个独立子任务。中心词查表得 $v_c$ 后乘 $W_{out}^T$ 得 $(2,10000)$ 得分，该得分向量被**复用 6 次**，分别与 6 个真实上下文词算交叉熵并**全部相加**——一个输入对多个标签，本质是**多标签分类**，实现上拆为 S 个独立单标签 Softmax。

$$ J = -\sum_{j=0, j \neq m}^{2m} u_{c-m+j}^T v_c + 2m \log \sum_{k=1}^{|V|} \exp(u_k^T v_c) $$

> **Skip-gram 与 N-gram 的关系**：名字确源于传统的 k-skip-n-gram（允许跳过中间词的 N-gram），但 Word2Vec 的 Skip-gram 是**预测模型**而非统计模型，目的不是「修复」N-gram，而是高效学习稠密词向量——用「中心词预测上下文」强迫模型学到语义特征，彻底解决了 N-gram 的稀疏性与维度灾难。

为每个「中心词-上下文词」对建立独立学习任务，让 Skip-gram 能学到更精细的词间关系，处理**低频词**和**大数据集**时词向量质量通常更高；代价是任务量为 CBOW 的 $S$ 倍，训练更慢。

### 8.4 滑动窗口如何「逼」出语义

以 CBOW、窗口 $k=7$ 为例：窗口中心在第 8 词时用 $[w_1..w_7; w_9..w_{15}]$ 预测 $w_8$；右移一格后用 $[w_2..w_8; w_{10}..w_{16}]$ 预测 $w_9$——两次样本有 12 个上下文词完全相同，**上下文向量极其相似**。模型却要对相似上下文分别预测不同目标，梯度下降找到的「捷径」是：**当 $w_8$ 与 $w_9$ 的词向量本身足够接近时，一个相似的上下文向量就能同时预测好两者**。这个现象在全语料重复：「笔记本」和「电脑」频繁出现在「键盘、屏幕、CPU」等相似上下文，为降低总损失，它们的向量被推向彼此——语义相似性就是这样被「逼」出来的。

数学上，目标是让得分向量中真实目标词的维度值最大，而 $\text{score} = x \cdot u_{target}$，点积是余弦相似度的分子，最大化点积即在**促使上下文向量与目标词向量夹角尽量小**。实际训练为避免对整个词表做 Softmax 归一化的开销，用 **Hierarchical Softmax** 与**负采样**近似加速。

## 9. Word2Vec 的局限：静态词向量

里程碑之余，Word2Vec 有一个根本局限——产生的是**静态词向量**：

1. **上下文无关**：任意一个词只有一个**固定**向量，是整个语料训练出的「平均」语义。「小米」在「农民伯伯正在收割小米」和「小米公司发布了新手机」两个语境中向量**完全相同**，无法解决一词多义。
2. **静态的本质**：输出是一张巨大的查询表，训练完成即固定，使用时按 ID 查行，不涉上下文的动态分析。

> **补记**：这条从 One-Hot 到 Word2Vec 的线索，可以归纳成一句「语义从哪来」的演进史——离散表示里语义靠人设计特征（TF-IDF 加权）；主题模型里语义来自全局文档统计的矩阵分解；Word2Vec 里语义来自局部上下文的预测任务。静态词向量的天花板（一词一向量）正是下一站 ELMO/BERT「上下文动态词向量」要突破口。
