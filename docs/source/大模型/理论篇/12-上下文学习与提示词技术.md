# 上下文学习与提示词技术

## 1. 不更新权重，模型怎么「学会」新任务

学 GPT 时提过**上下文学习**及其提示模式（Zero/One/Few-shot）：推理阶段不做任何梯度反向传播或权重更新，主要靠提示词就能在很多任务上获得可观效果。既然没有实际的学习更新，模型是如何做到的？这一篇深入它的机制，并看在难度瓶颈时如何用提示词技术进一步激发推理潜能。

## 2. 零样本与少样本机制

### 2.1 零样本学习（Zero-Shot）

**零样本学习**指提示词中仅提供任务指令和待处理输入、不给任何预期输出示例，模型凭预训练积累的广博知识直接处理未见任务。典型设定（情感分析）：

```text
阅读以下评论，并判断一下评论表达的情感：

评论：这部电影的剧情有些拖沓。
情感：
```

在 DeepSeek 网页端测试，模型不是机械弹出标签，而是输出完整自然语言「评论表达的情感：负面。」并精准给出 `负面` 判断。能做到这点得益于模型在海量语料预训练建立的**共享语义空间**——它不仅学到「电影」「剧情」「拖沓」的表征，还学到这些词与「负面」情感概念在潜空间的深层关联。下达自然语言指令时，零样本往往还依赖模型经对齐微调形成的**指令遵循能力**：解析指令意向后，自回归生成把新任务映射到已构建的底层语义概念，这种基于先验的语义映射直接影响预测下一 token 时的**概率分布**——生成到表达核心态度那步，代表「负面」的 token 因上下文语义引导获得更高概率，从而在不更新任何权重下完成任务。

### 2.2 少样本学习（Few-Shot）

零样本的泛化高度依赖数据中固有的常见模式。若要模型严格遵循特定输出格式、或处理边界模糊的复杂情况，仅靠指令可能不稳——模型常像上例那样输出多余解释性文本或判断偏差。于是引入具「观摩」作用的**少样本学习**：在上下文补充几个规范输入输出示例，清晰演示预期效果。**单样本（One-Shot）** 是只给一个示例的特例：

```text
评论：画面非常唯美，配乐也很震撼！
情感：正面

评论：这部电影的剧情有些拖沓。
情感：
```

有了这个约束，输出变得非常干净（只出 `负面`）。但任务复杂、反直觉或高度定制化时单样本就捉襟见肘——加一条极违常规的规则「情感词倒序输出」（正面→面正、负面→面负），由于只看了一个反直觉例子，模型无法确信这是偶然拼写错误还是硬性规定，可能干脆放弃顺应规则，不仅没逆序还补充多余对话文本。

要克服预训练语言先验与对齐对话范式对新规则的干扰，让上下文构建的任务模式主导输出概率，就得增加示例数、用**少样本**强化这种非标准映射（示例给足「面正/面负/性中」三个）：

```text
评论：画面非常唯美，配乐也很震撼！    情感：面正
评论：演技太令人尴尬了，中途就想离场。  情感：面负
评论：一般般，没有预期的那么好看……     情感：性中
评论：这部电影的剧情有些拖沓。         情感：
```

有了几个示例铺垫，模型捕捉到隐藏规则——这不是拼错，而是要把情感分类词逆序输出。少样本之所以有效，是因为它在上下文窗口中**构建了一个临时任务概率分布**：受多个一致性示例驱动，注意力机制敏锐提炼并模仿这种有悖常理的映射、稳健泛化到目标输入。这证明大模型不仅能回忆静态知识，还能在复杂上下文中实时做动态的全新模式匹配与学习。

### 2.3 上下文学习的三种内在机制

为解释「不更新权重却能学会新任务」，学术界提出几种主流假设：

1. **感应头机制（Induction Heads）**：从注意力层面的机械可解释性切入——Transformer 在预训练特定阶段会激发特殊的「感应头」，核心行为是「**匹配并复制**」：当发现当前输入 `A` 此前出现过，就把注意力回溯到前一个 `A`、倾向直接预测其后跟随的 `B` 作输出。这是少样本模式匹配的重要微观基础；
2. **隐式学习动力学（隐式权重更新）**：从「前向计算本身就是学习」角度——自注意力把上下文示例信息写入激活、与后续 MLP 组合，可近似理解为产生一种对后续计算起作用的低秩「权重更新/适配」效应。无需显式反向传播或持久化权重改动，却以瞬时激活形式影响后续 token 的 logits、动态改变输出分布；
3. **（近似）贝叶斯视角及其检验**：把上下文学习理解为「在上下文中对潜在任务/潜变量做（近似）推断」，用先验—后验解释零/少样本差异；也有研究提出可操作的统计检验，并观察到 LLM 的上下文学习会偏离严格贝叶斯性质——贝叶斯更像有启发性的解释框架，而非被普遍证明的严格等价。

三大理论从微观执行（注意力复制）、中观适配（隐式权重更新）到宏观统计（概率推断），共同揭示大模型强大泛化能力的底层本质。

## 3. 进阶提示词技术

仅靠简单示例有时仍解决不了需多步复杂逻辑推理的数学/算法规划问题，于是提示词工程发展出更高级引导策略。

### 3.1 思维链（Chain-of-Thought, CoT）

**思维链**鼓励模型在给最终答案前先显式输出中间推理步骤——既客观增加了生成计算步数、给模型更多「思考时间」，又把复杂大问题拆成多个简单连贯的小逻辑节点。演进路线：最早需手动编写详尽推理示例的 **Few-Shot CoT**；随后发现在提示词末尾加一句 "Let's think step by step" 也可能显著促进推理显式展开，即 **Zero-Shot CoT**；再有让模型自动构建推理示例的 **Auto-CoT**。

用一道含常识与逻辑陷阱的问题感受：

```text
我想洗车，洗车店离我家 50 米。我应该开车去还是走路去？
```

未经深层推理特化的模型常被「距离近应该走路」的表面逻辑误导，给出「抽象」建议。加上中文「让我们一步一步地思考」后，模型虽列出「一步步」分析框架，但关键逻辑仍出严重幻觉（第 3 点假设人走过去车就在那里），最后仍给「走路去」的错误结论。换成英文经典触发词 `Let's think step by step` 后，模型成功发现盲点——「如果走路去，车还在家里，没法洗车」，得出 "you should drive" 正解，且整个推导过程都变英文。

> **为何中英文触发词导致截然不同的结果？** 一定程度反映基础模型多语言推理能力**分布不均**：预训练阶段含严密逻辑推导的高质量数据（数学解答、编程逻辑、学术论文）在英文语料更常见、积累更久，更易形成稳健推理模式；"Let's think step by step" 这类高频经典触发短语在部分微调/评测数据集中反复出现，更易引导出「显式分步推导」模式；中文直译在某些模型上可能只强化了「分点作答」的外观格式、未必稳定触发有效的自我校验。本质是通过显式要求生成中间步骤，模型把前文中间结果当延伸「草稿纸」继续引导下一步，一定程度缓解「直觉短路」的局部逻辑盲区。

思维链生效归根结底高度依赖底层训练数据——常规模型只有在预训练见过海量推理论证逻辑，才可能在推理阶段被某些提示稳定引导出分步推导。随着业界对复杂推理的追求，最新一代专用推理模型（OpenAI o1、DeepSeek-R1）在产品形态上更强调「先推导、后作答」。

### 3.2 思维树（Tree of Thoughts, ToT）

在线性单向 CoT 基础上，**思维树**把推理链条扩展成多分支树状拓扑。对更具挑战、需全局规划或易陷逻辑死胡同的任务（算 24 点、填字游戏、规划调度），单向单线 CoT 很可能有去无回——中间某步微小的评估错误就让推理陷**局部最优**、全盘皆输。核心理念是「**系统性多路径探索 + 智能评估 + 回溯机制**」，交替执行：**生成候选**（当前步生成多种下一步方向）→ **状态评估**（模型自身作「智能裁判」给各候选打分）→ **选择与回溯**（借 BFS/DFS 按评分选最优路径深入，发现死胡同立刻回溯到安全节点换选项）。

用「洗车问题」极简推演：ToT 先让模型生成第一步所有行动候选（`分支A：开车去` / `分支B：走路去`），再触发状态评估判能否达成「洗车」——走 `分支B` 时评估出「人走过去了、车留家里、没车可洗」，于是抛弃该无效路径、回溯选 `分支A`。洗车只是演示，真正价值在「算 24 点」这类搜索空间庞大的复杂任务中，靠状态评分与剪枝回溯的探索机制体现。

> 工程落地须清醒看弊端：一是**算力成本急剧膨胀**（每次分支探索与智能审查都密集消耗推理资源与等待时间）；二是**自我评估偏差**（完全靠模型自身裁判易生认知盲点）；三是**搜索空间爆炸**（迭代轮次过多）。**ToT 只是算法思想，并不强制绑定复杂 AI Agent 框架**——开发者完全可用原生 Python 脚本（数组维护树节点、while 循环做 BFS/DFS、API 调用大模型打分）实现轻量 ToT 链路。只因多步规划与自省机制契合自主智能体诉求，ToT 目前更多被提炼为宏观规划模块融入复杂 Agent 底层，而非日常单次对话最常用的提示技巧。

### 3.3 专用推理模型：底层能力的范式进化

OpenAI o1、DeepSeek-R1 等**专用推理模型**标志着大模型底层能力维度的范式进化——把「探索、试错、自省的推导能力更充分内化于基座权重」。以 DeepSeek-R1 为例，核心机制是多阶段后训练组合：**强化学习主导**阶段——预训练后不再单纯依赖人类偏好对齐，而通过大规模 RL 提升逻辑推导，在数学求解/代码生成等**有明确结果反馈**的场景用基于规则的奖励引导模型自我探索，促其延长推导链换更高奖励、形成更强自我校验纠错；配合**监督微调**阶段——整理、过滤、构建高质量样本，稳定长序列推理的输出风格与可读性。

专用推理模型接到复杂请求时，会在答前自动展开更长推导（耗时数秒到数分钟），外部表现为更倾向自我检查、反思、多步推演（内部是否显式用树状展开/剪枝/回溯则因模型与实现而异）。用 DeepSeek 推理模型测「洗车问题」，其思考内核经历「评估走路（距离近）→ 发现盲点（车没带过去）→ 尝试发散（让人把车开过去但麻烦）→ 最终收敛（必须开车去）」的自省链条。

代价也显著：首当其冲是**推理期算力开销成倍增加**与**首字响应延迟延长**。日常问答、常规翻译、直接信息检索等无需长逻辑链干预的基础任务，调用满血推理模型会造成不小资源浪费。系统工程架构中可引入**路由网关模块**做任务级动态分发——常规类调度给基础生成模型、复杂多步规划路由给推理模型，平衡质量与成本。

> **补记**：理论篇至此完整收官。把整条线拉直看：**架构**（Transformer→BERT/GPT/T5→Llama2/MoE）解决「大脑怎么搭」，**解码**（生成策略）解决「怎么吐字」，**提示**（本篇 ICL/CoT/ToT）解决「不改大脑、只喂什么就能编程它」，三者合起来才是现代大模型从原理到应用的完整认知。而「零样本靠语义先验、少样本靠临时分布、CoT 靠草稿纸、ToT 靠搜索回溯、推理模型靠 RL 把推导内化」这一层层递进，正是把「让模型会推理」从一个黑盒逐步拆成可设计工程对象的过程。
