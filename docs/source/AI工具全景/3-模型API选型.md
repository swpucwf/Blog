# 模型 API 选型

## 1. 国际主流 API

| 模型 | 厂商 | 特点 |
|---|---|---|
| Claude API（Opus 5.5） | Anthropic | 1M 上下文，编码与指令遵循强；同期另有同权重、不同防护等级的 Fable 与 Mythos 版本 |
| GPT-6 Astra / Sol / Luna | OpenAI | Astra 为 1.05M 上下文旗舰，Sol 与 Luna 分旗舰与低成本档；上一代仍在役 |
| Gemini 3.8 Flash / Live、3.1 Pro | Google | 约 1M 上下文，原生多模态突出；Gemini 4 已进入预训练但未发布 |

> 上下文窗口是规格书上的上限，实际可用量受输出预留、计费方式与接入渠道影响。同一模型在不同云渠道的标注可能不一致，以实际接入渠道的文档为准。

## 5. 选型建议

- **日常编码**：Claude Opus 5.5（质量最高）或 DeepSeek-V4.1-Flash（性价比最佳）；
- **中文项目**：Qwen3.8-Max、Kimi K3、DeepSeek-V4.1-Flash；
- **长文档与多模态**：Gemini 3.8 或 GPT-6 Astra；
- **低成本试验**：DeepSeek-V4.1-Flash、GPT-6 Luna；
- **不想分别对接**：OpenRouter 一个网关覆盖多家。

## 6. 三种不是 LLM 的模型形态

「模型」这个词的外延已经扩大，选型时会遇到三类评价标准完全不同的东西：

| 形态 | 代表 | 它做什么 | 关键区别 |
|---|---|---|---|
| 决策模型 | Jev（TypeSafe AI） | 输出带概率的类型化判定：分类、评分、真 / 假 | 不生成文本，结构上无法「胡说」 |
| 世界模型 | Genie 3、Cosmos、Marble、V-JEPA 2 | 理解并预测物理世界演化，生成可交互环境 | 吃视频级算力，主战场是仿真与具身智能 |
| 专家混合（MoE） | 多数前沿开源模型 | 稀疏激活，推理时只调用部分专家子网络 | 是架构而非产品，决定推理成本与吞吐 |

### 6.1 决策模型

Jev 属于「快判断」层：接收结构化状态（工单、消息、JSON），返回带校准置信度的答案，三种提问原语——从至多 255 个选项中选一个、按有序标准打分、是 / 否判断。它的定位是昂贵大模型负责规划，高频原子化判断交给决策模型。

两个使用前提必须记住：prompt injection 可影响其判定，不适合单独作为 agent 的安全门禁；计数、算术、日期处理不可靠，且英文优先。

### 6.2 世界模型

2026 年分成两条路线：生成式直接生成像素（Genie 3、Cosmos），隐空间只预测表征（V-JEPA 2）。目前主要用于自动驾驶仿真、机器人训练与内容生成，**还不能直接替换 LLM API**。

### 6.3 MoE

MoE 是架构而非产品。总参数量决定能力上限，激活参数量决定推理成本——看到「总参数 235B / 激活 22B」这类标注就是这种情况。选型时应关注**激活参数**，而不是总参数。

## 7. 一条务实的判断

榜单与参数表只能做初筛。真正决定选型的是三件事：你的任务分布、可接受的单次成本、以及对延迟的容忍度。同一个模型在通用榜单上领先，放到具体业务里可能因为中文术语、长上下文截断或工具调用格式而落后——**用 20 条真实样本做端到端对比，比看十个榜单可靠**。
