# 端到端实战项目

三个最小项目覆盖最常见的三条链路：RAG 问答、MCP 工具、AI 编程 MVP。每个都给出前置知识、工具组合与可运行代码。

## 1. 三十分钟搭一个 RAG 问答

**目标**：上传一份文档，实现基于内容的问答。

**工具组合**：LLM 用 DeepSeek 或 Qwen3（中文好、成本低），Embedding 用 BGE 系列，向量库用 Chroma（零配置），框架用 LlamaIndex（易改造）或 RAGFlow（文档解析强）。

**五步流程**：

1. 文档放入 `data/` 目录；
2. 按段落切分，建议 256～512 token、重叠 50 token；
3. 生成向量并写入 Chroma；
4. 提问 → 向量化 → 检索 top-5 → 拼 prompt → 生成；
5. 用 10 个测试问题验证：回答是否基于文档、是否遗漏关键信息。

```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader, Settings
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.chroma import ChromaVectorStore
import chromadb

Settings.embed_model = HuggingFaceEmbedding("BAAI/bge-small-zh-v1.5")

documents = SimpleDirectoryReader("data/").load_data()
db = chromadb.PersistentClient(path="./chroma_db")
store = ChromaVectorStore(chroma_collection=db.get_or_create_collection("docs"))
index = VectorStoreIndex.from_documents(documents, vector_store=store)

engine = index.as_query_engine(similarity_top_k=5)
print(engine.query("文档中关于 XXX 的关键结论是什么？"))
```

三个常见问题：块太大导致噪声多、嵌入模型与中文不匹配、top-k 太小导致证据不足。进阶方向是换 RAGFlow 提升 PDF 表格解析、加 reranker 重排、尝试 Agentic RAG 让 Agent 自主判断检索次数。

## 2. 五分钟写一个 MCP Server

**目标**：用 FastMCP 暴露一个自定义工具，让 Claude Code 或 OpenClaw 调用。

```python
from fastmcp import FastMCP

mcp = FastMCP("weather-server")

@mcp.tool()
def get_weather(city: str) -> str:
    """获取指定城市的天气信息"""
    data = {"北京": "晴，25°C", "上海": "多云，22°C", "深圳": "阵雨，28°C"}
    return data.get(city, f"未找到{city}的天气数据")

if __name__ == "__main__":
    mcp.run()
```

启动 `fastmcp run weather_server.py`，然后在项目根目录的 `.mcp.json` 中登记：

```json
{
  "mcpServers": {
    "weather": {
      "command": "python",
      "args": ["weather_server.py"]
    }
  }
}
```

重启客户端后输入「查一下北京天气」，Agent 会自己调用这个工具。进阶方向：接真实天气 API、增加资源与提示、用 Streamable HTTP 部署成远程 Server（按 2026 年无状态规范实现）。

## 3. 一小时做出一个 MVP

**目标**：从零用 AI 生成一个可运行的 Web 应用。

**方案 A（Bolt.new）**：打开站点用自然语言描述需求 → 浏览器预览 → 对话修改（「把颜色改成蓝色主题」「加一个筛选已完成的功能」）→ 一键 Deploy → 导出代码到本地继续迭代。

**方案 B（Claude Code + Cursor）**：

```text
1. 初始化：创建一个 Next.js 项目，包含首页和 API 路由
2. Vibe 阶段：加登录页面（Tailwind）、给 API 加 JWT 认证
3. 切换 Spec：先写 PRD.md 列出模块与输入输出，再按规格实现
4. 上线前加 Harness：补单元测试、做一次 CodeReview 查安全问题
```

三条原则：**先跑通再优化**（Vibe 阶段别纠结代码质量）、**及时切换范式**（原型验证后立刻用规格与测试约束）、**小步提交**（每完成一个功能就 commit，避免 AI 生成大量不可控代码）。

## 4. 三个项目的对照

| 项目 | 核心链路 | 关键概念 | 预计耗时 |
|---|---|---|---|
| RAG 问答 | 模型 + 嵌入 + 向量库 + 框架 | 切分、召回、上下文拼接 | 30～60 分钟 |
| MCP Server | 协议 + 工具调用 + Agent | 工具描述、项目级配置 | 5～15 分钟 |
| Vibe MVP | 范式 + CLI / IDE | 范式切换、验收标准 | 1～2 小时 |

## 5. 三个项目共同的收尾动作

跑通之后，值得补三件事，否则只能算「演示」而不是「工程」：

- **留一份评测集**：RAG 留 10 条问题，MCP 留 3 个调用场景，MVP 留关键路径的冒烟测试；
- **记录环境与命令**：工具链版本变化快，半年后复现靠的是这份记录；
- **写清边界**：哪些能自动跑、哪些必须人工确认，这个边界决定了后续能不能交给 loop。
