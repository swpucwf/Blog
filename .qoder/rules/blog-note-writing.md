# 博客笔记编写规范

适用于 d:\Blog 博客（docsify 站点，内容位于 docs/source/）新增、迁移或改写任何文章时，必须遵守以下规则。

## 1. 笔记口吻（非教程）

- 正文一律为「笔记」风格，禁止教程讲课式表达：
  - 章节自指：「这一章 / 本章 / 本节课 / 本节 / 本篇教程 / 你将学到 / 你将收获」→ 改用「本文 / 内容概览 / 下面」等中性表述。
  - 第二人称指令式：「你可以先… / 如果你想… / 帮助你… / 推荐你的…」→ 改为去主语表述「可以先… / 若要… / 便于… / 推荐的…」。
- 属内容而非口吻的第二人称必须原样保留：代码块内的 prompt 模板、引用的用户话术与示例问句（如访谈问题对照表、Mom Test 问句）。
- 通用解释性叙述中的「我们（笔者）」可留。
- 批量改写时先用正则定位候选、逐条 Read 取原文精确匹配（注意全角引号），改后复扫计数验证归零。

## 2. 分篇与顺序

- 整理自外部教程的内容不做整篇搬运，也不写成单篇大汇总：按来源主题提炼，一个主题重写成独立一篇。
- 篇目编号顺序必须与来源教程原章节顺序一致（以源站侧边栏 / 学习路径为准），不得按主观重排。
- 文章内章节标题一律用阿拉伯数字编号（`## 1.`），禁止中文数字（`## 一、`）。
- 每篇以引用块「笔记缘起」开头，说明读的材料；篇末「写在最后」用相对链接承接下一个主题。
- 调整篇目顺序时，用 git mv 保留历史，并同步更新全部篇间互链及「前两篇」类指代。

## 3. 开源教程来源注明

- 专栏或子系列 README 只用一行引用块注明出处，格式固定：
  `> 内容整理自开源教程 [名称](链接)，作为参考笔记。`
- 不写「关于本专栏」式多段说明，不罗列借鉴的章节标题，不写「已适配本站排版」「非原文搬运」等过程性细节。
- 正文文章内的来源信息，同样仅在篇首「笔记缘起」一句带过。

## 4. 配图与提交

- 图片统一走图床 `https://raw.githubusercontent.com/swpucwf/MyBolgImage/main/img/<文件名>`；删本地图前校验 `\]\(images/` 与本地 assets 引用计数为 0。
- 每批内容改动校验（无本地图片、无断链、口吻合规）后提交；推送需用户单独下达指令（经本机代理 127.0.0.1:17890）。
